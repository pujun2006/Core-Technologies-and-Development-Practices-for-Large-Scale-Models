Multi-Level Explainability Analysis of Transformer-Based Text Classification Models.py代码把前面讨论的三条可解释性路线串联进了一个完整流程：**在 IMDb 数据集上微调 `bert-base-uncased` 二分类模型后，对同一条示例文本同时执行 SHAP 归因、LIME 局部扰动解释，以及逐层 Attention 权重提取**。

---

### 一、 逐段代码详细解析

#### 1. 数据集加载与模型/分词器初始化（第 1–33 行）

* **数据集加载**：优先从 `stanfordnlp/imdb` 加载 IMDb 影评情感数据集，失败时回退到 `"imdb"`；随后加载 `bert-base-uncased` 分词器与 `AutoModelForSequenceClassification(..., num_labels=2)`（在 BERT 编码器上方接二分类头）。
* **数据预处理与 `max_length=128**`：对影评文本做统一填充与截断（`padding="max_length"`, `truncation=True`, `max_length=128`）。影评原文往往较长，截断到 128 个 token 可显著加快训练与后续解释速度，但会丢弃后半段信息。

#### 2. 使用 `Trainer` 微调模型（第 36–63 行）

* **`TrainingArguments`**：配置单轮训练（`num_train_epochs=1`）、批大小（`8`）、学习率预热（`warmup_steps=500`）、权重衰减（`weight_decay=0.01`）、每 100 步打印日志（`logging_steps=100`）与学习率（`2e-5`）。
* **`trainer.train()`**：启动微调，使模型参数从通用语义表示适配到 IMDb 影评情感极性判别。

#### 3. 方法一：SHAP 文本归因（第 66–87 行）

* **封装 `pipeline` 适配 `shap.Explainer**`：通过 `pipeline("text-classification", model=model, tokenizer=tokenizer, return_all_scores=True, ...)` 封装端到端文本分类接口。`return_all_scores=True` 让输出包含所有类别的得分，便于后续按标签索引归因。
* **`shap_explainer(sample_text)` 与索引取值**：传入文本列表后，`shap_values[0, :, "POSITIVE"]` 提取第 0 条样本中各个 token 对 `"POSITIVE"` 类别的 SHAP 归因值（在 Notebook 中可进一步用 `shap.plots.text(shap_values[0])` 可视化）。

#### 4. 方法二：LIME 局部特征解释（第 90–122 行）

* **显式切换 `model.eval()` 与设备对齐**：将模型移至 `device` 并设为评估模式，确保扰动推理结果稳定。
* **`predict_proba` 概率函数**：接收扰动后的文本列表，经分词、前向推理和 `F.softmax(..., dim=-1)` 转换为 `[N, 2]` 的类别概率 NumPy 数组，供 `LimeTextExplainer` 拟合局部线性代理模型。
* **`explain_instance` 与 `as_list()**`：围绕 `sample_text[0]` 做扰动采样并提取 Top 10 词级权重，正权重支持目标类别，负权重起反向作用。

#### 5. 方法三：Layer-wise Attention 权重提取（第 125–153 行）

* **显式传入 `output_attentions=True**`：编码 `sample_text` 得到 `input_ids` 与 `attention_mask`，在 `torch.no_grad()` 下前向传播获取 `outputs.attentions`。
* **逐层打印形状**：遍历 12 个编码器层，打印每层注意力张量形状（通常为 `[batch_size, num_heads, seq_len, seq_len]`），避免直接打印完整数值造成终端刷屏。

### 三、 工程细节与潜在踩坑点

1. **全量 IMDb + 1 个 Epoch 的训练耗时与效果**：
IMDb 训练集有 25,000 条样本，`per_device_train_batch_size=8` 意味着 1 个 epoch 需要约 3,125 步，且 `warmup_steps=500` 占了较大比例；若只想快速跑通解释流程，调试阶段可先截取小样本子集（如 `.select(range(200))`）验证。
2. **新版 `transformers` 中的 `pipeline(..., return_all_scores=True)` 与 `TrainingArguments` 参数兼容**：
部分较新版本的 `transformers` 中 `return_all_scores=True` 已逐步被 `top_k=None` 替代或发出弃用提示；此外 `Trainer` 训练完成后 `model` 权重已更新，但若涉及多卡/分布式或后续独立加载 checkpoint，需确认使用的是微调后的 `model` 实例。
3. **三种方法互补解读**：
同一句话上，**SHAP** 给出基于联盟边际贡献的 token 级加性归因，**LIME** 给出词级局部线性近似权重，**Attention** 展示各层各头的位置关注分布。三者角度不同，结论不完全等同，交叉对照能更全面地理解模型行为。
