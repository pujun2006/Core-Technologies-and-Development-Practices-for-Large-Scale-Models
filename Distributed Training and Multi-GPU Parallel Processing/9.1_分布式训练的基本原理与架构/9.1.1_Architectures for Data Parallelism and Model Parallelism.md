Architectures for Data Parallelism and Model Parallelism.py代码在一个单进程脚本中，分别演示了 PyTorch 中数据并行（`nn.DataParallel`）**与**跨设备层切分模型并行（手动指定 `.to(dev0)` / `.to(dev1)`）的基本用法，并做了单卡/无卡环境的动态设备降级处理，避免因设备不足直接报错。

下面按模块逐一拆解其原理、实现细节与工程注意事项。

---

### 一、 设备检测与 Part 1：数据并行（`nn.DataParallel`）

```python
gpu_count = torch.cuda.device_count()
...
device = torch.device("cuda:0" if torch.cuda.is_available() else "cpu")
dp_model = SimpleModel()

if gpu_count > 1:
    dp_model = nn.DataParallel(dp_model)

dp_model.to(device)

```

* **多卡自动切分与聚合**：当 `gpu_count > 1` 时，`nn.DataParallel` 会在单进程内把 `batch_size = 64` 的 `input_data_dp` 按 batch 维度拆分成多份分发到各张 GPU，各自拷贝模型前向计算，最后把输出收集到主设备（`cuda:0`）计算 Loss；反向传播时各卡计算梯度并汇总回主卡更新参数。
* **单卡/CPU 兼容**：若只有 1 张 GPU 或没有 GPU，跳过 `DataParallel` 包装，直接在 `device` 上完成一次完整的 `zero_grad -> forward -> loss -> backward -> step`。
* **工程局限提示**：`nn.DataParallel` 采用单进程多线程 + 主卡汇总的模式，存在 **GIL 限制、主卡负载/显存偏重以及不支持状态分片（如 ZeRO/FSDP）** 等局限；在现代多卡或多机训练中，更推荐使用 `DistributedDataParallel`（DDP）或 `FSDP`。

### 二、 Part 2：跨设备模型并行（`LargeModel`）

```python
class LargeModel(nn.Module):
    def __init__(self, dev0, dev1):
        super(LargeModel, self).__init__()
        self.dev0 = dev0
        self.dev1 = dev1

        self.fc1 = nn.Linear(1024, 512).to(self.dev0)
        self.fc2 = nn.Linear(512, 256).to(self.dev1)
        self.fc3 = nn.Linear(256, 128).to(self.dev0)
        self.fc4 = nn.Linear(128, 10).to(self.dev1)

```

* **层间切分与自动跨设备梯度回传**：`fc1`、`fc3` 放在 `dev0`，`fc2`、`fc4` 放在 `dev1`。在前向传播 `forward` 中，每当张量跨设备流动时显式调用 `.to(...)`；PyTorch 的 Autograd 引擎会自动跟踪跨设备张量转换，在 `loss_mp.backward()` 时把梯度反向传回对应设备上的权重。
* **标签与 Loss 所在设备对齐**：`labels_mp` 被放在 `dev1` 上，与 `outputs_mp`（来自 `fc4`，位于 `dev1`）保持在同一设备，这样 `criterion_mp(outputs_mp, labels_mp)` 可以直接计算损失，无需额外跨卡搬运标签。
* **设备降级逻辑**：当 `gpu_count < 2` 时，`dev0` 与 `dev1` 均退化为 `device`（单张 GPU 或 CPU），保证脚本在任何机器上都能顺利跑通。

### 三、 工程细节与常见坑点

1. **频繁跨设备搬运（`.to(...)`）的代价**：在 `LargeModel.forward` 中，`dev0 -> dev1 -> dev0 -> dev1` 连续切换了三次设备。真实业务中跨设备搬运会占用 PCIe/NVLink 带宽并带来传输延迟，因此切分模型时通常会**把相邻的层尽量聚合成连续的 Stage**，减少来回折返拷贝。
2. **整 Batch 串行推进的空闲等待（Bubble）**：当前演示是一次性把整个 batch（`64` 条样本）送入 `LargeModel`，同一时刻只有一个设备在活跃计算，另一个设备处于等待状态；实际流水线并行中通常会切分为更小的 **Micro-Batch** 并配合流水调度来提高设备利用率。
3. **合成数据与末尾小管道符**：代码中使用的 `torch.randn` / `torch.randint` 仅为连通性演示，真实训练需接入数据集与验证评估；另外提示词末尾多了一个 `|` 符号，属于输入笔误，不影响代码逻辑。
