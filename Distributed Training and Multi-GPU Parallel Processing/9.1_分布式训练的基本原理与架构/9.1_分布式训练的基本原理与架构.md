大模型分布式训练的核心目标，是在成百上千张加速器（GPU / NPU）组成的集群上，突破**单卡算力上限**与**单卡显存容量墙**，同时在可控的**通信开销**下保持高吞吐与训练稳定性。

随着模型参数量、上下文窗口与训练 Token 规模的增长，单一并行方式往往难以兼顾显存节省、通信效率与计算利用率，因此现代大模型训练通常采用**多维并行组合（如 DP + TP + PP + SP/CP + EP）**与**分层互联架构**。

---

### 一、 基本原理：算力扩展、显存瓶颈与通信代价

1. **算力与吞吐扩展（Scale-Out）**
* 单卡的计算吞吐（FLOPs）与显存容量有限。分布式训练通过将训练数据、模型参数、优化器状态或计算图拆分到多台设备并行执行，缩短端到端训练周期。


2. **显存墙与状态冗余**
* 在标准数据并行中，若每张卡都完整保存模型参数、梯度以及优化器状态（如 AdamW 的一阶/二阶动量与高精度主权重），显存占用会迅速超出单卡上限；此外，长上下文和较大 Batch 会使中间激活值进一步放大显存压力。


3. **计算与通信的权衡（Computation vs. Communication）**
* 并行切分越细，设备间需要同步或交换的数据往往越频繁。分布式训练性能的关键之一，是把切分放在**通信带宽充足的层级**（例如机内高速互联），并通过算子融合、梯度累积与异步通信重叠（Overlap）隐藏通信延迟。



---

### 二、 核心并行策略

#### 1. 数据并行（Data Parallelism, DP）与状态分片（ZeRO / FSDP）

* **基础 DP**：将全局 Batch 切分为多个子 Batch 分发到不同设备，各设备持有完整模型副本独立计算前向与反向梯度，随后通过梯度同步（如 `AllReduce`）聚合梯度并更新参数。
* **ZeRO / FSDP（显存优化型数据并行）**：传统 DP 存在严重的状态冗余。ZeRO（Zero Redundancy Optimizer，通常按 Stage 1/2/3 划分）与 FSDP 将**优化器状态、梯度、模型参数**按分片（Shard）分散存储在各数据并行rank 上，仅在计算需要时通过 `AllGather` 拉取对应分片、计算或反传后释放，大幅降低单卡静态显存占用。

#### 2. 张量并行（Tensor Parallelism, TP）

* **原理**：将单个层内的权重矩阵与计算按行或按列切分到多张卡上共同完成一次矩阵乘法（例如 Transformer 中 MLP 的上下投影层、Self-Attention 的 Q/K/V 与输出投影），局部结果通过 `AllReduce` 或 `ReduceScatter` / `AllGather` 合并。
* **特点**：切分粒度细、通信频率高（每层前向/反向都可能发生集合通信），因此**强烈依赖卡间高带宽互联（如 NVLink）**，通常限制在单机（如 8 卡）内部使用。

#### 3. 流水线并行（Pipeline Parallelism, PP）

* **原理**：按网络层或 Block 维度将模型垂直切分为多个 Stage，分配到不同设备上串行衔接；前向时将激活传给下一 Stage，反向时将梯度回传给上一 Stage。
* **气泡（Pipeline Bubble）与微批次（Micro-Batch）**：若整个 Batch 整块推进，设备会出现大量等待空闲（即 Bubble）。现代流水线调度会将一个 Batch 拆成多个更小的 Micro-Batch，采用 **1F1B（One Forward One Backward）** 或交错式调度（Interleaved Schedule）让前反向交织执行，从而压缩空闲气泡、提升设备利用率。

#### 4. 序列/上下文并行（SP / CP）与专家并行（EP）

* **上下文/序列并行（Context / Sequence Parallelism）**：当上下文长度极长时，单卡存放序列维度的激活或注意力计算会成为瓶颈。通过按序列维度切分输入/激活或结合环形注意力（Ring Attention）等机制，分摊长序列显存与计算压力。
* **专家并行（Expert Parallelism, EP）**：针对 MoE（Mixture of Experts）架构，将不同的专家子网络（FFN 专家）分布到不同设备上，Token 经 Router 路由后通过 `AllToAll` 通信分发到对应专家计算，再聚合回原位置。

### 三、 系统架构与通信分层

现代大模型训练集群通常呈现“计算节点 + 高速卡间互联 + 高吞吐跨节点网络 + 集体通信库”的分层架构：

| 架构层级 | 典型组成 | 核心作用与特点 |
| --- | --- | --- |
| **节点内互联（Intra-Node）** | 单机多卡（如 8 卡 GPU/NPU）+ NVLink / NVSwitch / 高速总线 | 带宽极高、延迟极低，适合承载通信密集的 **TP** 与局部高频同步 |
| **节点间互联（Inter-Node）** | InfiniBand（IB）或高速 RoCE 网络 + 胖树/无阻塞拓扑 | 连接多台机器，适合承载 **DP / ZeRO / FSDP / PP / EP** 的跨机通信，需关注网络拥塞与跨机带宽 |
| **通信原语与集合通信库** | `AllReduce`、`ReduceScatter`、`AllGather`、`AllToAll`、`Send/Recv`（常见如 NCCL / RCCL / HCCL 等后端） | 封装底层拓扑感知的集合通信算法（如 Ring / Tree），实现高效数据归约、广播与重排 |
| **训练编排与运行时** | 分布式框架（PyTorch Distributed / FSDP / DeepSpeed / Megatron 等）+ 任务调度与容错机制 | 管理进程组（Process Group）、并行映射、计算-通信重叠、Checkpoint 保存/恢复与故障节点替换 |

---

### 四、 典型组合与工程落地要点

1. **按带宽层级匹配并行维度**：一般优先在单机内铺满高带宽的 **TP**，跨机组合 **PP** 与 **DP / ZeRO / FSDP**（长上下文加 **CP/SP**，MoE 加 **EP**），避免在低带宽跨机链路上做高频细粒度同步。
2. **计算与通信重叠（Overlap）**：通过独立 CUDA Stream / 通信流与分块调度，让当前层的梯度同步或下一微批次的数据通信与当前算子计算并行发生，减少通信等待时间。
3. **容错与检查点（Checkpointing / Resharding）**：大规模集群训练周期长、硬件故障概率随规模上升，需要定期保存分布式 Checkpoint、支持自动重试/隔离异常节点，并尽量缩短恢复时间以降低有效算力损失。
