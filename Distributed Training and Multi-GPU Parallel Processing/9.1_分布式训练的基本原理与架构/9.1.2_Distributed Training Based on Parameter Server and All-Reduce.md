Distributed Training Based on Parameter Server and All-Reduce.py代码展示了 PyTorch 中**分布式数据并行（`DistributedDataParallel`, DDP）**的标准多进程训练写法，覆盖了进程组初始化、GPU / CPU 自适应包装、前反向与自动梯度同步、资源清理以及 `mp.spawn` 进程拉起。相比单进程多线程的 `nn.DataParallel`，DDP 采用**多进程架构**，能够绕开 Python GIL 限制并更好地利用多卡/多机通信带宽。

### 一、 进程组初始化与销毁（`setup` / `cleanup`）

```python
def setup(rank, world_size):
    os.environ["MASTER_ADDR"] = "localhost"
    os.environ["MASTER_PORT"] = "12355"
    backend = "nccl" if torch.cuda.is_available() else "gloo"
    dist.init_process_group(backend, rank=rank, world_size=world_size)


def cleanup():
    dist.destroy_process_group()

```

* **`rank` 与 `world_size**`：`world_size` 是参与训练的总进程数；`rank` 是当前进程的全局编号（从 `0` 到 `world_size - 1`）。
* **`MASTER_ADDR` 与 `MASTER_PORT**`：指定主节点（通常为 `rank 0` 所在机器）的地址与空闲端口，供各进程在初始化阶段交换连接信息、组建默认进程组。
* **通信后端选择（`nccl` vs. `gloo`）**：
* GPU 环境通常优先选 `"nccl"`，它在 NVIDIA GPU 间对集合通信（如 `AllReduce`）和 NVLink/IB 拓扑做了深度优化；
* 纯 CPU 环境或某些不支持 NCCL 的场景则使用 `"gloo"`。


* **`cleanup()`**：训练结束时调用 `dist.destroy_process_group()` 释放通信上下文与底层资源，避免进程退出时残留挂起。

### 二、 模型定义与设备/DDP 包装

#### 1. `SimpleModel` 网络结构

```python
class SimpleModel(nn.Module):
    def __init__(self):
        super(SimpleModel, self).__init__()
        self.fc1 = nn.Linear(1024, 512)
        self.fc2 = nn.Linear(512, 256)
        self.fc3 = nn.Linear(256, 10)

```

* 典型的三层全连接网络，将 `1024` 维输入逐步映射到 `512`、`256`，最终输出 `10` 维 Logits。

#### 2. GPU 与 CPU 模式的差异化包装

```python
use_cuda = torch.cuda.is_available()
if use_cuda:
    torch.cuda.set_device(rank)
    device = torch.device(f"cuda:{rank}")
    model = SimpleModel().to(device)
    model = DDP(model, device_ids=[rank])
else:
    device = torch.device("cpu")
    model = SimpleModel().to(device)
    model = DDP(model)

```

* **显式绑定当前进程 GPU（`torch.cuda.set_device(rank)`）**：在多进程 GPU 训练中，每个进程应绑定到自己对应的卡（`cuda:{rank}`），避免默认卡混乱或跨卡显存错位。
* **GPU 模式必须传 `device_ids=[rank]**`；而 **CPU 模式不能传 `device_ids**`（传 CUDA 设备 ID 会导致报错或行为异常）。
* **初始参数广播**：DDP 初始化时会自动将 `rank 0` 的模型参数与 Buffer 广播给其他 rank，保证各进程起跑时的初始权重一致。

### 三、 训练步骤与后台自动 `All-Reduce`

```python
optimizer.zero_grad()
outputs = model(input_data)
loss = criterion(outputs, labels)

# loss.backward() 期间，DDP 钩子会自动触发梯度的分布式 All-Reduce 平均
loss.backward()

optimizer.step()

```

* **无需手动调用 `dist.all_reduce**`：DDP 在反向传播阶段通过自动求导钩子（Autograd Hooks）与梯度分桶（Gradient Bucketing）机制，在各层梯度计算完成后自动发起跨进程的梯度规约与平均（使各 rank 得到相同的平均梯度），随后各进程用相同梯度执行 `optimizer.step()`，从而保持参数同步。
* **打印日志时的多进程输出**：当前每个 rank 都会执行 `print(...)`，因此在多进程运行时会看到多条 `[Rank X]` 的输出；在正式训练脚本中，通常只在 `rank == 0` 上打印日志、保存 Checkpoint 或记录指标。

### 四、 多进程启动入口（`torch.multiprocessing.spawn`）

```python
if __name__ == "__main__":
    world_size = (
        torch.cuda.device_count() if torch.cuda.device_count() >= 2 else 2
    )
    print(f"启动 {world_size} 个进程进行 DDP 训练...")

    torch.multiprocessing.spawn(
        train, args=(world_size,), nprocs=world_size, join=True
    )

```

* **`if __name__ == "__main__":` 保护**：在多进程派生（尤其是 Windows 或 `spawn` 启动方式下）中必不可少，防止子进程重复执行顶层启动代码导致无限递归创建进程。
* **单机少卡/无卡兜底逻辑**：当可用 GPU 少于 2 张时，脚本将 `world_size` 设为 `2` 并走 `gloo` + CPU 模拟多进程，方便在单卡或无 GPU 机器上验证 DDP 逻辑是否通畅；若只有 1 张 GPU 且强行起 2 个进程走 `cuda:{rank}`，则可能出现 `rank=1` 越界或争抢同一张卡的情况，实际生产中单卡通常用单进程（`world_size=1`）或多卡按实际卡数启动。
* **`torch.multiprocessing.spawn` 参数**：`train` 为入口函数，`args=(world_size,)` 是传给 `train` 的额外参数（`spawn` 会自动把 `rank` 作为第一个位置参数传入），`nprocs=world_size` 指定启动进程数，`join=True` 表示主进程等待所有子进程结束。

### 六、 真实业务落地时的常见补充点

1. **数据切分（`DistributedSampler`）**：当前代码里每个 rank 都用 `torch.randn` / `torch.randint` 各自生成了 `(64, 1024)` 的随机数据；在真实训练中，应为数据集配合 `torch.utils.data.distributed.DistributedSampler`（并在每个 epoch 开始前调用 `sampler.set_epoch(epoch)`），让不同 rank 拿到不重叠的数据子集，从而真正扩大有效全局 Batch Size。
2. **端口冲突与启动方式**：固定端口 `"12355"` 在同一台机器并发跑多个测试脚本时容易冲突，可改为动态空闲端口或通过环境变量传入；此外，现代 PyTorch 生产训练中也常使用 `torchrun` 启动多进程脚本，配合 `LOCAL_RANK` / `RANK` / `WORLD_SIZE` 环境变量管理单机与多机扩展。
