Distributed Training Configuration for Multi-Node Multi-GPU Systems.py代码在单机上启动 **4 个独立进程**（`world_size = 4`），演示了基于 `torch.multiprocessing.spawn` 与 `DistributedDataParallel`（DDP）的分布式训练模拟。它的一个实用亮点是**硬件自适应映射**：无论当前机器有 4 张 GPU、1 张 GPU（单卡模拟多进程），还是没有 GPU（纯 CPU 模拟），都能自动匹配设备与通信后端并跑通完整流程。

### 一、 进程组初始化与参数传递

#### 1. `setup` 函数与环境变量注入

```python
def setup(rank, world_size, master_addr, master_port):
    os.environ["MASTER_ADDR"] = master_addr
    os.environ["MASTER_PORT"] = master_port

    has_cuda = torch.cuda.is_available()
    backend = "nccl" if has_cuda else "gloo"

    dist.init_process_group(backend, rank=rank, world_size=world_size)

```

* **本地回环会合（Rendezvous）**：主程序传入 `master_addr = "127.0.0.1"` 与 `master_port = "12355"`，4 个本地子进程通过环回地址建立分布式通信组。
* **后端自动切换**：有可用 CUDA 设备时选 `"nccl"`，无 GPU 时自动回退到 `"gloo"`，保证脚本在不同硬件上都能执行。

#### 2. `train` 函数签名与 `mp.spawn` 参数对齐

```python
def train(fn_rank, world_size, master_addr, master_port):
    rank = fn_rank
...
torch.multiprocessing.spawn(
    train,
    args=(world_size, master_addr, master_port),
    nprocs=world_size,
    join=True,
)

```

* **`mp.spawn` 的首参约定**：`torch.multiprocessing.spawn` 会自动把子进程索引（`0` 到 `nprocs - 1`）作为**第一个位置参数**传给目标函数，随后再按顺序展开 `args` 中的参数。
* 这里把首参命名为 `fn_rank` 并赋给 `rank`，清晰提醒读者参数位置与 `args` 元组必须严格对应，避免漏参或错位。

### 二、 多进程设备映射与 DDP 包装

```python
if torch.cuda.is_available():
    gpu_count = torch.cuda.device_count()
    gpu_id = rank % gpu_count
    torch.cuda.set_device(gpu_id)
    device = torch.device(f"cuda:{gpu_id}")

    model = SimpleModel().to(device)
    model = nn.parallel.DistributedDataParallel(
        model, device_ids=[gpu_id]
    )
else:
    device = torch.device("cpu")
    model = SimpleModel().to(device)
    model = nn.parallel.DistributedDataParallel(model)

```

* **`gpu_id = rank % gpu_count` 的兼容价值**：
* 当可用 GPU 大于等于 4 张时，`rank 0..3` 分别映射到 `cuda:0..3`，实现真正的 4 卡多进程训练。
* 当只有 **1 张 GPU** 时，4 个进程都会映射到 `cuda:0`（`0 % 1 == 0`），用于**单卡模拟多进程通信与 DDP 流程**；但此时 4 个进程会共享同一张显卡的算力与显存，容易出现显存争用或 OOM，**仅适合功能联调，不适合测真实加速比**。


* **GPU 与 CPU 包装差异**：GPU 模式下显式调用 `torch.cuda.set_device(gpu_id)` 并传入 `device_ids=[gpu_id]`；CPU 模式下使用 `cpu` 设备且不传 `device_ids`。

### 三、 训练步骤、梯度同步与资源释放

```python
optimizer.zero_grad()
outputs = model(input_data)
loss = criterion(outputs, labels)
loss.backward()
optimizer.step()

print(
    f"[Rank {rank}/{world_size}] 在设备 {device} 上完成训练，Loss: {loss.item():.4f}"
)

dist.destroy_process_group()

```

* **自动梯度同步**：`SimpleModel` 为三层全连接网络（`1024 -> 512 -> 256 -> 10`）。在 `loss.backward()` 阶段，DDP 会在后台自动完成 4 个进程间的梯度归约与平均，随后各进程各自执行 `optimizer.step()` 更新参数。
* **清理进程组**：每个进程结束前调用 `dist.destroy_process_group()` 释放通信资源，避免残留进程或端口占用。

### 五、 工程实践中的补充提示

1. **单卡模拟多进程的显存与性能边界**：在只有 1 张 GPU 的机器上起 4 个 DDP 进程，每份进程都会各自实例化模型与优化器状态，显存占用会乘以进程数；若单卡显存较小，可调小 `batch_size`（如从 `64` 调小）或用 CPU 模式验证逻辑。
2. **真实训练的进阶替换**：当前脚本采用 `mp.spawn` 与随机合成数据做本地模拟；在正式训练或跨机扩展时，建议改用 `torchrun` 管理进程与环境变量，并搭配 `DistributedSampler` 切分真实数据集，在 `rank == 0` 上集中输出日志与保存权重。
