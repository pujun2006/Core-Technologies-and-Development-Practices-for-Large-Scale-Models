**多头注意力权重的优化与调控**，是指通过调整注意力得分计算、温度/缩放机制、结构偏置（Bias / Mask / 位置编码）、正则化与头级约束，以及推理阶段的动态干预，来改变注意力分布的**锐度（Sharpness）、稀疏性、多样性与长程关注行为**。

在实践中，权重调控既服务于**训练稳定性与模型表现提升**，也用于**可控生成、长上下文检索增强、冗余头压缩与推理加速**。

---

## 一、 得分与温度调控：控制分布锐度与梯度流

在标准缩放点积注意力中：


$$A = \text{softmax}\left(\frac{QK^\top}{\tau \sqrt{d_k}} + M\right)$$


其中 $\tau$（或缩放系数 $\alpha = 1/\tau$）决定了进入 $\text{softmax}$ 前 Logits 的尺度：

* **缩放因子与温度调控**：
* 维度增大时点积方差线性增长，固定 $\sqrt{d_k}$ 防止初始阶段分布过尖锐导致梯度消失。
* **调低温度（等效放大缩放因子）**：使分布更集中于高匹配位置，减少无关上下文噪声干扰，常用于强化检索对齐或降低采样发散度；但过度尖锐会导致 $\text{softmax}$ 梯度趋近于零，训练初期易出现注意力塌缩（只盯住极少数 Token）。
* **调高温度（等效缩小缩放因子）**：使分布更平滑、熵更高，鼓励信息在多个位置间分散流动，常用于平滑训练或避免局部过早锁定。


* **Logit 软裁剪（Logit Soft-Capping）**：部分架构在进入 $\text{softmax}$ 前对注意力分数施加平滑上限（如 $\text{cap} \cdot \tanh(\text{scores} / \text{cap})$），防止极端高分 Logit 引发数值不稳定或过度集中于单一位置。

## 二、 结构化偏置与掩码调控：注入先验与位置/窗口约束

除了硬屏蔽（将无效或未来位置设为 $-\infty$），还可以通过在 `scores` 上叠加**连续偏置矩阵 $B$** 或改变可见域来精细调控权重分布：

### 1. 位置与距离衰减偏置

* **相对位置编码与旋转位置编码（RoPE）**：通过在 $Q、K$ 内积中引入相对位置旋转或偏置，使注意力权重自然反映词元之间的相对距离关系，并支撑长上下文外推。
* **距离惩罚/偏置（如 ALiBi 思想）**：对距离较远的 `Key` 施加随距离递增的负偏置，使模型天然偏向近期上下文，同时在长度外推时无需重新学习复杂位置嵌入。

### 2. 局部窗口与稀疏注意力掩码

* **滑动窗口注意力（Sliding Window Attention）**：限制每个 `Query` 仅能关注邻近 $W$ 个 `Key`，将注意力矩阵从全稠密 $L \times L$ 调控为带状结构，既保留局部句法/语义建模，又降低长序列计算与访存开销。
* **全局 Token + 局部窗口混合**：在文档理解、长文本或结构化任务中，允许少数关键位置（如段落边界、特殊标记、检索锚点）被全局关注，其余位置走局部窗口，兼顾全局信息汇聚与效率。

### 3. 检索/知识引导偏置（如 RAG 与对齐场景）

在具备外部证据或指定上下文片段的任务中，有时会通过偏置掩码或注意力引导机制提高相关证据段落的 `Key` 得分（或降低无关干扰段落得分），促使模型更多依赖可验证上下文而非参数记忆，从而缓解幻觉。

## 三、 多头多样性与稀疏性优化：防止头冗余与塌缩

多头注意力的核心优势在于“多视角并行”，但训练中常出现**多个头学出高度相似的注意力模式**（冗余）或**少数头主导全部权重**的现象。常见优化手段包括：

1. **注意力分布正则化（Entropy / Diversity 约束）**：
* 在训练损失中引入针对注意力权重的正则项（如控制分布熵在合理区间，或惩罚不同头之间注意力矩阵的余弦相似度/KL 散度过高），促使不同头分工互补（例如有的头关注局部邻近词，有的头关注句法主干或跨句指代）。


2. **注意力 Dropout**：
* 在 `softmax` 后的注意力权重上施加随机丢弃（训练阶段），迫使某个 `Query` 不能过度依赖单一 `Key`，提升对噪声和局部扰动的鲁棒性。


3. **头级门控与头剪枝 / 头合并**：
* **头剪枝（Head Pruning）**：评估各头对损失或最终输出的贡献，移除对性能影响极小或高度冗余的头，精简参数与计算。
* **GQA / MQA 分组共享**：通过让多个查询头共享同一组 $K, V$，在架构层面对键值投影进行“分组约束”，以极小精度代价换取显著的 KV Cache 压缩与推理加速。

## 四、 推理阶段的动态调控：KV 驱逐、Sink 与可控干预

在自回归推理阶段，权重不仅用于前向计算，还可作为动态资源管理与行为干预的依据：

* **注意力汇（Attention Sink）与窗口保留**：长文本流式生成或滑动窗口推理时，序列起始位置（如首几个 Token）常承担大量“基准/汇集”注意力权重。若直接丢弃首部 Token 会导致困惑度飙升，因此常将“初始 Sink Token + 最近滑动窗口 Token”作为常驻保留集。
* **基于权重的 KV 驱逐 / 压缩（如 H2O 类思路）**：在显存受限的长上下文推理中，统计历史 `Key` 累积或近期受到的注意力权重，保留高重要度 Token 的 KV Cache、驱逐长期低权重 Token，以控制显存占用。
* **推理时权重干预（Steering / 偏置调节）**：在特定可控生成、去偏或引用对齐实验中，可在推理钩子中对特定头或特定 Token 范围的注意力得分施加偏置调整；但需谨慎，因为强行扭曲权重可能破坏原有语义连贯性或引发分布偏移。

## 五、 调控时的关键权衡与风险

| 调控手段 | 预期收益 | 主要风险 / 副作用 |
| --- | --- | --- |
| **温度过低 / 过度锐化** | 聚焦高相关位置、减少分散 | `softmax` 梯度饱和、训练不稳定、易忽略次要但关键的上下文线索 |
| **强行局部化 / 过度剪枝** | 降低计算与显存开销、提速 | 丢失长距离依赖或跨段推理能力，复杂推理任务精度下降 |
| **过度施加多样性惩罚** | 减少头之间重复 | 强迫无关头强行拟合不同模式，可能损害主任务损失收敛 |
| **推理期强改注意力权重** | 临时引导关注特定片段 | 偏离训练分布，可能导致语法失真、逻辑跳跃或输出退化 |

在工程落地时，**架构级与训练期优化（如合理缩放、位置编码/掩码设计、GQA、FlashAttention 适配）**通常比**推理期强行修改权重**更稳健；推理期权重调控更适合作为显存受限下的自适应策略或局部诊断工具。
