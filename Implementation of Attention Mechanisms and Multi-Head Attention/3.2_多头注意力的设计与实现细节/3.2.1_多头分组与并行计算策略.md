在现代大模型训练与推理中，“多头分组”与“并行计算策略”是解决显存墙、访存带宽瓶颈以及单卡算力/显存上限的核心手段。前者主要通过调整**查询头（Query Heads）与键值头（Key/Value Heads）的映射分组**来压缩 KV Cache 与参数访存；后者则通过**多设备/多算子切分计算与通信重叠**来扩展吞吐与上下文长度。

---

## 一、 多头分组机制：MHA、GQA 与 MQA

设查询头数为 $H_q$，键值头数为 $H_{kv}$，单头维度为 $d_h$。不同注意力头分组方式决定了 $Q$ 与 $K, V$ 之间的绑定关系：

| 机制 | 查询头数 $H_q$ | 键值头数 $H_{kv}$ | 每组查询头数 $G = H_q / H_{kv}$ | KV Cache 大小（相对 MHA） | 特点与权衡 |
| --- | --- | --- | --- | --- | --- |
| **MHA**（多头注意力） | $H$ | $H$ | $1$ | $1\times$ | 表达能力最强，但解码阶段每步需读取全部 $H$ 组 $K, V$，显存与带宽开销最大 |
| **GQA**（分组查询注意力） | $H$ | $G$ 组（如 $8$） | $H / H_{kv}$ | $H_{kv} / H$（如 $1/8$） | 在接近 MHA 精度与 MQA 推理速度/显存节省之间取得折中，当前主流 LLM 标配 |
| **MQA**（多查询注意力） | $H$ | $1$ | $H$ | $1/H$ | KV Cache 最小、解码访存最快，但极端压缩下部分任务精度可能轻微下降 |

### 1. GQA 的分组映射与计算逻辑

在 **GQA（Grouped-Query Attention）** 中，H_q 个查询头被均匀划分为 $H_{kv}$ 个组，每组包含 $g = H_q / H_{kv}$ 个查询头，共享同一组键头与值头：

* 第 $c$ 个键值头<img width="255" height="40" alt="749d83a0-3766-4573-af20-821f60dde8ba" src="https://github.com/user-attachments/assets/bd0c5517-dfa3-41f0-9e65-7e7adaae7120" />
对应第 $c \cdot g$ 至 $(c+1)g - 1$ 个查询头。
* 在张量维度上，若 `K` 与 `V` 形状为 `(B, H_kv, S_kv, d_h)`，逻辑上可将每个键值头沿头维度重复 $g$ 次（或通过广播/步长索引与 `Q` 的 `(B, H_q, S_q, d_h)` 对齐），再执行缩放点积注意力。
* **工程细节**：现代高效内核（如 FlashAttention 或融合解码内核）通常不在显存中显式复制/广播 `K, V` 整张大表，而是在片上读取或按组映射索引计算，避免额外显存分配与内存拷贝。

### 2. 对推理阶段访存与显存的影响

自回归解码（Decode）阶段通常是 **Memory-Bound（访存受限）** 而非 Compute-Bound（算力受限）：每生成一个新 Token，都要从高带宽显存（HBM）读取历史 KV Cache。

* 将 $H_{kv}$ 从 $H_q$ 降至 $G$（例如 $H_q = 32, H_{kv} = 8$），KV Cache 显存占用与单步解码读取的 KV 字节数均降至原来的 $1/4$。
* 当批大小（Batch Size）增大或上下文长度拉长时，更小的 KV Cache 允许更大的并发 Batch 或更长的上下文窗口，从而显著提升整体吞吐。

## 二、 并行计算策略：从算子级到多设备分布式

多头注意力在计算上有两个典型特征：一是**多头之间在注意力分数计算与加权求和阶段相互独立**，天然适合并行；二是**序列长度 $L$ 增长时注意力矩阵呈 $O(L^2)$ 扩展**，单卡显存容易成为瓶颈。围绕这两点，工程上形成了多维并行策略：

### 1. 算子与单卡级并行优化

* **FlashAttention（分块与在线 Softmax）**：将 $Q, K, V$ 按序列维度切分为块（Block），在 GPU 片上高速缓存（SRAM）中逐块计算局部注意力得分与局部最大值/指数和，利用 **Online Softmax** 修正因子动态合并统计量，最终直接输出加权结果，避免将完整的 $L \times L$ 注意力矩阵写回 HBM。
* **PagedAttention（分页 KV Cache）**：针对连续请求与长短不一的序列，将 KV Cache 划分为固定大小的物理块（Block），通过逻辑块表映射到物理块，减少传统连续预分配导致的显存碎片化，提高显存利用率与并发度。

### 2. 张量并行（Tensor Parallelism, TP）：按头切分

在单节点多卡（如 8 卡 NVLink 互联）内，最常见的是对注意力投影与输出层做 **列切分 + 行切分**：

1. **Q、K、V 投影切分（Column Parallel）**：将 $W^Q、W^K、W^V$（或融合后的 `W_qkv`）按**注意力头维度**均分到 $N_{\text{tp}}$ 张卡上。每张卡持有 $H_q / N_{\text{tp}}$ 个查询头以及 $H_{kv} / N_{\text{tp}}$ 个键值头（当 $H_{kv} \ge N_{\text{tp}}$ 且能整除时）。
2. **本地多头注意力计算**：各卡各自完成本卡负责头部的 $Q K^\top$、Mask、Softmax 与 $\cdot V$ 计算，此阶段**无需卡间通信**。
3. **输出投影切分与聚合（Row Parallel + All-Reduce）**：W^O 按输入特征维（即拼接后的多头维）切分到各卡，每张卡计算局部输出后，通过一次 **`All-Reduce`（求和归约）** 将各卡结果相加，得到完整的 `(B, L, d_model)` 输出。

> **与 GQA 的配合边界**：当使用 TP 切分头时，若 $H_{kv} < N_{\text{tp}}$（例如 8 卡 TP 但仅有 $H_{kv} = 2$ 或 $4$ 个 KV 头），无法直接把单个 KV 头再拆半到两张卡上做独立头并行，通常需要在卡间复制/广播 KV 头，或限制 TP 大小不超过 $H_{kv}$。

### 3. 上下文并行（Context Parallelism, CP）与序列并行（Sequence Parallelism, SP）

* **上下文并行（CP，如 Ring Attention）**：当单条序列极长（如 64K、128K 甚至更长）、单卡装不下完整的序列激活或 KV Cache 时，将输入序列沿**序列长度维度**切分到多张卡上。各卡计算本地 $Q$ 块对本地 $K, V$ 块的注意力，同时通过环状通信（Ring）传递并接收其他卡的 $K, V$ 块，结合在线 Softmax 累积全局精确注意力结果，实现长序列下的显存与计算分摊。
* **序列并行（SP，Megatron 语境）**：常与 TP 配合使用。TP 已经切分了注意力与 MLP 的矩阵乘，但残差连接后的 `LayerNorm / RMSNorm` 和 `Dropout` 激活值在各卡上是重复的；SP 将这些逐元素/归一化层沿**序列维度**切分到各卡，通过 `Reduce-Scatter` 和 `All-Gather` 替代部分 `All-Reduce`，进一步降低激活显存占用。

### 4. 数据并行（Data Parallelism, DP）与流水线并行（Pipeline Parallelism, PP）

* **流水线并行（PP）**：将 Transformer 的不同层（Layer）划分到不同设备组，微批次（Micro-batch）依次流经各阶段，减少单卡需要存放的模型权重与 KV Cache 层数，但会引入气泡（Bubble）等待时间，需配合交错调度（Interleaved PP）降低空转。
* **数据并行（DP / FSDP / ZeRO）**：不同设备处理不同的数据批次；在 ZeRO / FSDP 下，优化器状态、梯度甚至模型参数可在数据并行组内分片存储，按需通信聚合，进一步释放显存。

## 三、 策略组合与选型思路

在实际大模型训练与推理引擎中，单一并行往往不够，通常采用 **混合并行（3D/4D Parallelism）**：

| 场景 / 瓶颈 | 推荐组合思路 | 核心收益 |
| --- | --- | --- |
| **高并发推理、长上下文解码** | **GQA + PagedAttention + TP（匹配 $H_{kv}$）** | 大幅压缩 KV Cache，降低访存带宽压力，提高并发批大小 |
| **超长序列训练（如 tens/hundreds of K tokens）** | **CP（Ring Attention） + FlashAttention + TP** | 突破单卡激活与 KV 显存上限，维持高算力利用率 |
| **超大参数模型训练** | **TP（节点内高速互联） + PP（跨节点） + DP/FSDP** | 兼顾通信带宽限制与总显存容量扩展 |

总体而言，**GQA** 从架构层面减少了 KV 头数量以换取更低的显存与访存开销；**TP、CP、PP、DP** 则从系统层面分别切分“头/权重”、“长序列”、“网络层深”和“数据批次”，使多头注意力在算力、显存与通信带宽之间达到最优平衡。
