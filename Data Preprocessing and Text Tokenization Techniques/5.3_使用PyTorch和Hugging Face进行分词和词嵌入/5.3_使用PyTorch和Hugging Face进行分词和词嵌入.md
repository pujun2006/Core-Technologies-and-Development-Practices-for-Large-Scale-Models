使用 **PyTorch** 与 **Hugging Face** 进行分词和词嵌入，本质上是把“人类可读的自然语言文本”转化为“神经网络可计算的稠密张量（Tensor）”的两个连续阶段：**分词器（Tokenizer）负责把字符串切分为离散 Token 并映射为整数 ID（`input_ids`）**，**词嵌入（Embedding）负责把离散 ID 映射为连续的稠密向量（`embeddings`）**。

---

### 一、 整体链路：从文本到向量表示

在典型的 PyTorch + Hugging Face 流水线中，一条或一批文本会经历以下步骤：

1. **原始文本输入**：如 `["自然语言处理很有趣", "PyTorch 与 Hugging Face"]`。
2. **分词与编码（Tokenizer）**：
* 切分为子词/字符单元；
* 添加特殊标记（如 `[CLS]`、`[SEP]`、`[PAD]`）；
* 映射到词表索引生成 `input_ids`，同时生成 `attention_mask`（标识真实 token 与 padding 填充位）。


3. **嵌入层查表（Embedding Lookup）**：
* 词嵌入矩阵形状通常为 $(\text{vocab\_size}, d_{\text{model}})$，其中 $\text{vocab\_size}$ 是词表大小，$d_{\text{model}}$ 是嵌入向量维度（如 BERT-base 为 $768$）。
* 给定形状为 $(\text{batch\_size}, \text{seq\_len})$ 的 `input_ids`，嵌入层按索引查表取出对应向量，输出形状为 $(\text{batch\_size}, \text{seq\_len}, d_{\text{model}})$ 的三维张量。


4. **后续特征融合（以 Transformer 为例）**：
* 词嵌入通常会加上**位置编码/位置嵌入（Position Embeddings）**（以及部分架构中的类型嵌入 `token_type_ids`），再送入后续注意力层与前馈网络。



---

### 二、 Hugging Face 分词器（Tokenizer）的核心用法与细节

在 Hugging Face `transformers` 中，`AutoTokenizer.from_pretrained(...)` 会根据模型配置自动加载对应的分词器。实际使用中有几个高频且关键的细节：

#### 1. 常用输出字段与参数

调用 `tokenizer(texts, padding=True, truncation=True, max_length=..., return_tensors="pt")` 时，常关注以下内容：

* **`input_ids`**：词表 ID 序列，数据类型通常为 `torch.long`（`int64`），因为 `torch.nn.Embedding` 要求索引为整型。
* **`attention_mask`**：`1` 表示有效 token，`0` 表示填充 token（`[PAD]`）。在后续注意力掩码、池化（如 Mean Pooling）时必须使用 `attention_mask` 排除 `[PAD]` 干扰。
* **填充与截断（`padding` / `truncation`）**：批处理时将不同长度序列对齐到同一长度；超长序列按 `max_length` 截断，避免显存溢出或超出模型最大上下文长度。

#### 2. 常见易踩坑点

* **切分预览 vs. 模型输入**：`tokenizer.tokenize(...)` 返回字符串 token 列表，仅用于观察切分结果；送入模型前需要 `input_ids`（可直接用 `tokenizer(..., return_tensors="pt")` 或 `tokenizer.convert_tokens_to_ids(...)`）。
* **Pad Token 缺失问题**：部分因果语言模型（如 GPT 系列、LLaMA/Qwen 等解码器模型）默认没有配置 `pad_token_id`，做批量 `padding=True` 时需要先显式设置（例如 `tokenizer.pad_token = tokenizer.eos_token`）。
* **分词器与模型权重必须匹配**：不同模型的词表顺序和特殊符号 ID 不同，混用会导致 `input_ids` 指向错误的词向量。

### 三、 PyTorch 词嵌入（Embedding）的两种常见方式

#### 1. 独立使用 `torch.nn.Embedding`（静态/可训练词表向量）

当你自己搭建网络、使用外部预训练词向量（如 Word2Vec / GloVe）初始化，或单独研究词向量矩阵时，会直接使用 `nn.Embedding(num_embeddings=vocab_size, embedding_dim=embed_dim)`：

* 它本质上是一个可学习的参数矩阵 `weight`，前向传播时执行高效的索引查找（等价于 one-hot 向量乘以权重矩阵，但避免了显式构造稀疏/高维 one-hot 张量）。
* **词嵌入 vs. 上下文嵌入**：单独的 `nn.Embedding` 输出的是**静态/非上下文词向量**（同一个 token ID 在不同句子中查出来的初始向量相同）；而在 Transformer 编码器/解码器中，经过多层自注意力计算后得到的隐藏状态则是**上下文相关的向量**（同一词在不同语境下的表示会动态变化）。

#### 2. 直接提取预训练模型的嵌入层或隐藏状态

在使用 Hugging Face 预训练模型时，通常有两种方式获取嵌入：

* **仅取词嵌入层（输入层表征）**：访问模型内部的词嵌入模块（例如 BERT 的 `model.get_input_embeddings()` 或 `model.bert.embeddings.word_embeddings`），只做词表查表，不包含后续 Transformer 层的上下文交互。
* **取模型输出隐藏状态（上下文表征）**：前向传播时传入 `output_hidden_states=True`，`outputs.hidden_states[0]` 通常是嵌入层输出，`outputs.hidden_states[-1]` 则是最后一层的上下文向量，常用于句向量池化（Mean Pooling / `[CLS]` 取向量）或下游任务特征。

### 四、 工程实践要点

* **推理阶段务必加 `model.eval()` 与 `torch.no_grad()**`：关闭 Dropout 并禁用梯度计算，减少显存占用并加快推理速度。
* **句向量池化要避开 `[PAD]**`：直接对 `last_hidden_state.mean(dim=1)` 求均值会把大量 `0` 填充位算进去，拉低向量模长与语义准确性；使用 `attention_mask` 加权求平均更稳妥。
* **微调时的嵌入层策略**：数据量较小时，如果直接放开全部参数微调，词嵌入层和底层参数容易过拟合；通常采用较小的学习率或先冻结部分底层/嵌入层，视任务数据规模与领域偏移程度决定。
