Efficient Tokenization Based on Hugging Face Tokenizers.py代码展示了在 PyTorch 中结合 Hugging Face `AutoTokenizer` 构建**自定义 `Dataset` + 动态填充（Dynamic Padding）`DataLoader`**的规范写法。与整份数据集统一填充到固定 `max_length` 相比，它的核心优势是**每个 Batch 只按本批次内的最长序列长度进行填充**，既保留了特殊标记与掩码，又能减少无效 `[PAD]` 计算与显存开销。

---

### 一、 分步详细解析

#### 1. 加载 Tokenizer 与准备示例数据（第 1～2 步）

* `model_name = "bert-base-chinese"` 与 `AutoTokenizer.from_pretrained(model_name)`：加载中文 BERT 分词器。
* `texts` 与 `labels`：3 条中文文本及其对应的二分类标签（长度各不相同，适合观察不同 Batch 下的动态对齐效果）。

#### 2. 自定义 `TextClassificationDataset`（第 3 步）

继承 `torch.utils.data.Dataset`，实现三个核心方法：

* `__init__`：保存原始 `texts`、`labels`、`tokenizer` 以及最大长度上限 `max_length=64`。
* `__len__`：返回样本总数（`len(self.texts)`），供 `DataLoader` 采样与计算 `len(dataloader)`。
* `__getitem__(idx)`：
* 调用 `self.tokenizer(text, truncation=True, max_length=self.max_length, return_tensors="pt")` 对**单条**文本编码；此时不传 `padding="max_length"`，让单条样本保持自身实际长度（不超过 `max_length`）。
* `return_tensors="pt"` 会返回带 batch 维度的张量（如形状 `(1, L)`），因此通过 `{key: val.squeeze(0) for key, val in encoding.items()}` 去掉第 `0` 维，使单条样本的 `input_ids` 和 `attention_mask` 成为一维张量 `(L,)`。
* 将 `label` 转为 `torch.long` 类型的张量存入 `"labels"`，满足 PyTorch 分类损失函数（如 `CrossEntropyLoss`）对整型类别索引的要求。



#### 3. 自定义 `collate_fn` 实现动态 Padding（第 4 步）

* `DataLoader` 在把多条样本打包成一个 Batch 时，会调用 `collate_fn(batch)`。
* 这里分别收集 `batch` 中每条样本的 `input_ids`、`attention_masks` 与 `labels`，随后调用 `tokenizer.pad(..., padding=True, return_tensors="pt")`：
* `padding=True` 会自动取**当前 Batch 内**的最长序列长度作为对齐长度，短序列右侧补 `[PAD]`（对应的 `attention_mask` 补 `0`，有效 token 为 `1`）。
* 例如某个 Batch 两条句子原长分别为 24 和 21，该 Batch 的 `input_ids` 形状就会是 `(2, 24)`，而不是强行补到 `64`。



#### 4. 构建 `DataLoader` 与 Batch 验证（第 5～6 步）

* `DataLoader(dataset, batch_size=2, shuffle=True, collate_fn=collate_fn)`：
* `batch_size=2`、3 条样本且 `shuffle=True` 时，通常会产生 2 个 Batch（一个大小 `2`，一个大小 `1`；若某个 Batch 只有 1 条样本，最长长度就是它自身长度，不会多余 padding）。


* 遍历 `dataloader` 时打印：
* `input_ids` 与 `attention_mask` 的张量形状；
* `labels` 张量；
* `tokenizer.decode(..., skip_special_tokens=False)`：保留 `[CLS]`、`[SEP]`、`[PAD]` 还原文本，便于核对首尾特殊符号与填充位置；
* `tokenizer.convert_ids_to_tokens(...)`：查看 ID 对应的具体 token 字符串。

### 三、 实用细节与改进建议

1. **名称与组件对应**：代码注释中提到了 `DataCollatorWithPadding`，实际写法是手写 `collate_fn` 调用 `tokenizer.pad`。在更标准/简洁的工程实践中，也可以直接传入 `transformers.DataCollatorWithPadding(tokenizer=tokenizer)` 作为 `collate_fn`，效果一致且更少样板代码。
2. **注意 `shuffle=True` 带来的长短差异波动**：随机打乱样本顺序后，不同 Epoch 同一个样本可能分到不同 Batch，从而导致序列长度略有变化；若追求极致的批处理吞吐，在更大规模数据集上有时还会结合按长度分桶（Bucket Batching）进一步减少 padding 浪费。
3. **跨模型兼容性**：像 BERT 这类模型默认配有 `pad_token_id`；如果换成部分默认没有 `pad_token` 的解码器模型，调用 `tokenizer.pad` 前需先显式指定 `tokenizer.pad_token`（如设为 `eos_token`）。
