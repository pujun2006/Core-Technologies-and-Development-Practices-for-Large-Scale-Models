Transfer Learning and Fine-Tuning.py代码是一个完整的 **基于 `bert-base-uncased` 的二分类迁移微调（Partial Fine-tuning）示例**，结合了 Hugging Face `transformers`、`datasets` 与 PyTorch 原生训练循环。它的核心思路是：**保留预训练语言模型的通用语言表征，冻结前 6 层 Encoder 防止小样本过拟合，仅微调后 6 层 Encoder、Pooler 以及新接入的二分类头**。

---

### 一、 分模块详细解析

#### 1. 模型与分词器加载（第 1 步）

* `AutoTokenizer.from_pretrained(model_name)`：加载与 `bert-base-uncased` 匹配的词表和分词器（小写化、WordPiece 切分），保证输入 token ID 与预训练权重对齐。
* `AutoModelForSequenceClassification.from_pretrained(model_name, num_labels=2)`：加载 BERT 主干并在顶部拼接一个用于二分类的线性分类头（输出维度为 `2`）。由于分类头是新初始化的，实际运行时通常会提示部分分类层权重为随机初始化，这正是微调阶段需要学习的部分。

#### 2. 冻结前 6 层 Transformer Encoder（第 2 步）

* `bert-base-uncased` 共包含 **12 层** Transformer Encoder（索引 `0` 到 `11`）。
* `model.bert.encoder.layer[:6]` 选中前 6 层，将 `param.requires_grad = False` 后，PyTorch 在反向传播时不会为这些参数计算和累积梯度，从而减少显存占用并保护底层通用语义特征不被破坏。
* 随后的 `trainable_params` 与 `total_params` 统计用于直观验证冻结是否生效。

#### 3. 数据集构建与预处理（第 3～4 步）

* `Dataset.from_dict(data)`：将内存中的 Python 字典转换为 Hugging Face `datasets` 格式，便于批量映射与索引。
* `preprocess_data`：
* `padding="max_length"` 与 `truncation=True`（`max_length=32`）将文本统一截断或填充到固定长度 `32`，确保一个 batch 内张量形状一致。
* 将 `"label"` 映射为 `"labels"`：这是 Hugging Face 分类模型前向传播时默认识别的标签字段名；传入 `labels` 后，`model(**batch)` 会自动计算交叉熵损失并返回 `outputs.loss`。


* `dataset.set_format(type="torch", columns=["input_ids", "attention_mask", "labels"])`：将指定列直接转换为 PyTorch `Tensor`，避免在 `map` 阶段提前固化张量导致后续序列化或批处理出现类型问题。

#### 4. DataLoader、设备与优化器配置（第 5～6 步）

* `train_dataloader` 设置 `shuffle=True`（每个 epoch 打乱样本顺序，提升泛化）；`eval_dataloader` 设置 `shuffle=False`（评估阶段保持顺序稳定）。`batch_size=2` 适配当前 3 条示例数据。
* `model = model.to(device)`：将模型权重移动到 GPU（若可用）或 CPU。
* `AdamW(filter(lambda p: p.requires_grad, model.parameters()), lr=2e-5)`：
* 使用 `AdamW`（带解耦权重衰减的 Adam），是 Transformer 微调的标准优化器。
* 通过 `filter(...)` 只传入 `requires_grad=True` 的参数，避免为冻结参数维护优化器状态，进一步节省显存；`2e-5` 也是 BERT 微调常用的较小学习率。



#### 5. 自定义训练循环（第 7 步）

* `model.train()`：启用训练模式（如开启 Dropout）。
* 每个 batch 的标准五步走：
1. 将 `batch` 中各张量转移到 `device`；
2. `outputs = model(**batch)` 前向计算并取出 `outputs.loss`；
3. `optimizer.zero_grad()` 清空上一轮梯度（PyTorch 默认梯度累加）；
4. `loss.backward()` 反向传播计算梯度；
5. `optimizer.step()` 根据梯度更新可训练参数。



#### 6. 自定义评估函数（第 8～9 步）

* `model.eval()`：切换到评估模式（关闭 Dropout 等训练专用行为）。
* `with torch.no_grad():`：禁用梯度计算，显著降低推理显存占用并加快前向速度。
* `torch.argmax(logits, dim=-1)`：在类别维度上取最大得分对应的索引作为预测类别，再用 `accuracy_score` 计算准确率。

#### 做得好的地方

* **参数过滤与格式规范**：`set_format(type="torch", ...)` 与 `filter(lambda p: p.requires_grad, ...)` 写法清晰，符合 PyTorch 与 `datasets` 的最佳实践。
* **标签命名对齐**：显式将 `label` 转为 `labels`，使 `model(**batch)` 能够直接输出 `loss` 与 `logits`。

#### 实际项目中的改进建议

1. **划分独立的训练集与验证/测试集**：当前代码把全部 3 条数据同时放进 `train_dataloader` 和 `eval_dataloader`，评估指标属于“训练集回测”，无法反映真实泛化能力。实际使用应先调用 `dataset.train_test_split(...)`。
2. **补充学习率调度器（Scheduler）与梯度裁剪**：在更正式的训练中，常搭配 `get_linear_schedule_with_warmup`（线性预热 + 衰减）和 `torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)`，能进一步稳定训练过程。
3. **小数据集微调的稳定性**：示例数据仅有 3 条，3 个 epoch 后损失可能快速下降甚至过拟合，实际场景建议根据数据规模调整 `epochs`、`batch_size` 和冻结层数。
