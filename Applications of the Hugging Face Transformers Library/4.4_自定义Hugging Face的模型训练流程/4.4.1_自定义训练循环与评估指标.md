在 PyTorch 与 Hugging Face 生态中，当需要对数据集进行分批迭代、监控泛化表现、按指标择优保存模型，或实现非标准训练逻辑时，**自定义训练循环（Custom Training Loop）**配合**评估指标计算**是最灵活也最可控的工程方案。

下面从核心架构、评估指标体系、完整代码示例与工程细节四个维度详细说明：

---

### 一、 自定义训练循环的核心组成部分

相比于把整批数据硬编码进单步前向传播，规范的自定义训练循环通常包含以下模块：

1. **数据集划分与 `DataLoader` 批处理**
* 将数据划分为训练集（Train）与验证/测试集（Validation / Test），避免直接在训练集上评估导致“虚假高分”。
* 使用 `DataLoader` 为训练集开启 `shuffle=True`（打乱顺序提升泛化）和合理的 `batch_size`；验证集则无需打乱（`shuffle=False`）。
* 若序列长度不一，可结合 `DataCollatorWithPadding` 实现**动态 Padding**（按每个 batch 的最长样本补齐），比统一补齐到固定 `max_length` 更省算力和显存。


2. **设备调度（CPU / GPU / 多卡）**
* 显式将模型（`model.to(device)`）与每个批次的输入张量（`{k: v.to(device) for k, v in batch.items()}`）搬运到同一设备，防止出现设备不匹配错误。


3. **训练阶段与评估阶段隔离**
* **训练阶段**：`model.train()` 开启 Dropout 等训练行为 → `optimizer.zero_grad()` 清空梯度 → 前向计算 `loss` → `loss.backward()` 反向传播 →（可选）梯度裁剪/梯度累积 → `optimizer.step()` 更新权重（若使用学习率调度器，则在对应时机调用 `scheduler.step()`）。
* **评估阶段**：每个 epoch（或每隔固定步数）结束后切换到 `model.eval()` 关闭 Dropout，并在 `with torch.no_grad():` 上下文中收集所有验证集预测结果与真实标签，计算指标并记录验证损失。


4. **最佳模型保存（Checkpointing / Best Model Selection）**
* 依据核心验证指标（如 `val_f1`、`val_accuracy` 或最低 `val_loss`）判断是否刷新历史最佳记录；仅在提升时调用 `model.save_pretrained(...)` 与 `tokenizer.save_pretrained(...)`，防止最后一个过拟合 epoch 覆盖掉最优权重。

### 二、 常见评估指标及其适用场景

选择评估指标时，不能只看单一数值，而要结合任务类型与数据分布：

| 任务/场景 | 常用指标 | 核心含义与适用说明 |
| --- | --- | --- |
| **二分类 / 多分类** | **Accuracy（准确率）** | 预测正确样本占总样本的比例；类别分布较均衡时直观有效，但**类别极度不平衡时容易虚高**（例如 95% 负样本全猜负也能有 95% 准确率）。 |
| **二分类 / 多分类** | **Precision / Recall / F1** | Precision（精确率）关注“预测为正的里面有多少真正”；Recall（召回率）关注“实际为正的里面找出了多少”；**F1** 是两者的调和平均。多分类常用 `macro`（各类平等加权，关注小类）或 `weighted`（按样本数加权）。 |
| **多分类概率输出** | **Log Loss / Val Loss** | 衡量预测概率分布与真实标签的交叉熵损失，能反映预测置信度是否合理，常用于早停或模型选择。 |
| **排序 / 风险打分** | **ROC-AUC / PR-AUC** | 评估不同阈值下的排序/区分能力；正样本稀少时 **PR-AUC** 往往比 ROC-AUC 更敏感。 |
| **回归任务** | **MAE / RMSE / $R^2$** | 预测连续数值误差；RMSE 对大误差惩罚更重，MAE 对异常值更稳健。 |

### 三、 工程落地中的关键细节与常见坑

1. **标签列名必须匹配**：模型前向计算损失时，默认读取名为 `"labels"` 的字段；若数据集里叫 `"label"`，需重命名或手动传入 `labels=...`。
2. **评估时务必聚合全量预测再算指标**：不要在每个 batch 内部直接算 F1 后简单求平均（batch 间样本数可能不等，且小 batch 容易出现某类全无预测的情况），正确做法是把整个验证集的 `preds` 和 `labels` 收集齐后再统一计算。
3. **显存受限时的进阶手段**：
* **梯度累积（Gradient Accumulation）**：每 `k` 个微批次才执行一次 `optimizer.step()` 和 `optimizer.zero_grad()`（注意 `loss` 需除以 `k`），在不增大单步显存的前提下等效扩大 batch size。
* **混合精度训练（AMP）**：配合 `torch.amp.autocast` 与 `GradScaler`（GPU 上）可显著加快训练速度并降低显存占用。


4. **何时选自定义循环 vs Trainer**：
* 需要**特殊损失函数、多任务交替训练、自定义采样/蒸馏/强化学习逻辑或深度嵌入现有 PyTorch 工程**时，自定义训练循环最合适；
* 若是**标准微调任务**且希望少写样板代码、自带分布式/日志/早停集成，则 `transformers.Trainer` 会更省力。
