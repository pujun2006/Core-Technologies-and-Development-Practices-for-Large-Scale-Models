Integrated Use of Dataset and Pipeline Tools.py代码串联了 `datasets.Dataset` 与 `transformers.pipeline` 的典型使用流程，并展示了如何在加载模型时注入自定义标签映射（`id2label` / `label2id`）以及安全地执行批量文本分类推理。

下面按代码模块逐段拆解与分析：

---

### 1. 设备检测与标签映射（第 1～2 步）

```python
device = 0 if torch.cuda.is_available() else -1

id2label = {0: "负面 (Negative)", 1: "正面 (Positive)"}
label2id = {"负面 (Negative)": 0, "正面 (Positive)": 1}

```

* **设备选择**：`device = 0` 表示使用第一张可用 GPU；若无 GPU，回退为 `-1`（CPU 执行）。
* **标签双向映射**：`id2label` 和 `label2id` 用于将模型输出的数字类别索引（`0`、`1`）与人类/业务可读的标签名称互转。

---

### 2. 加载 Tokenizer 与分类模型（第 3 步）

```python
model_name = "bert-base-uncased"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForSequenceClassification.from_pretrained(
    model_name, num_labels=2, id2label=id2label, label2id=label2id
)

```

* `AutoModelForSequenceClassification` 会在 `bert-base-uncased` 编码器后接一个二分类头（`num_labels=2`）。
* 传入 `id2label` 与 `label2id` 后，模型配置（`model.config`）会记录这套映射，因此 `pipeline` 输出的 `pred['label']` 会直接显示 `"正面 (Positive)"` 或 `"负面 (Negative)"`，而不是默认的 `LABEL_0` / `LABEL_1`。
* **注意**：此处加载的是未经情感分类微调的基座模型加随机初始化分类头，因此预测置信度与正负向判断仅用于验证流程，不代表真实情感分析效果。

---

### 3. 构建 `Dataset` 与批量预处理（第 4～5 步）

```python
dataset = Dataset.from_dict(raw_data)

def preprocess_data(examples):
    tokenized_inputs = tokenizer(
        examples["text"], padding="max_length", truncation=True, max_length=32
    )
    tokenized_inputs["labels"] = examples["label"]
    return tokenized_inputs

dataset = dataset.map(preprocess_data, batched=True)

```

* `Dataset.from_dict(raw_data)` 将内存字典转换为 Hugging Face `Dataset` 对象。
* `dataset.map(preprocess_data, batched=True)` 以批次为单位调用 `preprocess_data`，完成分词、填充/截断（统一到 `max_length=32`），并将原始 `"label"` 映射为训练/评估常用的 `"labels"` 字段。
* **一个小细节**：在当前脚本中，第 5 步生成的 `dataset`（含 `input_ids`、`attention_mask`、`labels`）**并没有被后续第 7 步的 `pipeline` 直接消费**；它更像是为后续 `Trainer` 或 `DataLoader` 微调/评估准备的数据特征。

---

### 4. 初始化 `pipeline` 与批量推理（第 6～8 步）

```python
nlp_pipeline = pipeline(
    "text-classification", model=model, tokenizer=tokenizer, device=device
)

texts = [str(x) for x in raw_data["text"]]
predictions = nlp_pipeline(texts, batch_size=len(texts))

```

* **`"text-classification"`**：文本分类任务管线，内部会自动完成“原始文本分词 → 前向计算 → Softmax 归一化算 `score` → 按 `id2label` 映射 `label`”。
* **为什么这里用 `texts = [str(x) for x in raw_data["text"]]**`：
* 确保输入是干净的 Python 字符串列表，避免脏数据（如 `None`、数字或非字符串类型）导致底层分词器报错。
* 同时绕开了直接向 `pipeline` 传入已 `map` 过、且包含额外列（如 `labels`）的 `Dataset` 对象可能带来的参数/字段困扰。


* **`batch_size=len(texts)`**：这里把全部 3 条样本作为一个批次一次性送入推理（数据量很小时方便；若数据量很大，建议设成如 `16`、`32`、`64` 等固定批次大小，避免一次性占用过多显存）。

### 7. 工程改进建议

1. **真正复用 `Dataset` 时可用 `KeyDataset**`：
如果数据源是 `dataset`（而非再读 `raw_data["text"]`），且数据量较大，可以用 `from transformers.pipelines.pt_utils import KeyDataset` 传入 `KeyDataset(dataset, "text")`，既能直接读取 `Dataset` 列，又不用把整列一次性转成列表。
2. **微调后再推理才具备业务意义**：
当前分类头未经训练，若要用于实际情感分类，需先用标注数据对 `model` 进行微调（如配合 `Trainer` 使用第 5 步处理好的 `dataset`），再保存或直接交给 `nlp_pipeline` 推理。
3. **动态 Padding 提升推理效率**：
在推理阶段，若文本普遍较短，使用默认动态 Padding（不强制 `padding="max_length"` 到固定长度）通常比统一补齐到 `max_length` 更快、更省显存。
