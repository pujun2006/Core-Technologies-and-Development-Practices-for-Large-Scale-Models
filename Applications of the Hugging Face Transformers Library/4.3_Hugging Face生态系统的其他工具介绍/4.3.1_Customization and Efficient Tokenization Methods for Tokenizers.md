Customization and Efficient Tokenization Methods for Tokenizers.py代码演示了在使用 Hugging Face `transformers` 加载预训练模型（以 `bert-base-uncased` 为例）时，如何**扩展词表（Vocabulary Expansion）**，并将新词对应的 **Embedding 向量矩阵**与模型同步，最后完成前向传播验证。

下面按代码执行流程拆解核心原理与工程要点：

---

### 1. 加载预训练 Tokenizer 与分类模型

```python
model_name = "bert-base-uncased"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForSequenceClassification.from_pretrained(model_name, num_labels=2)

```

* `AutoTokenizer` 负责文本切分（Tokenization）与 Token 到数字 ID 的映射；`bert-base-uncased` 会将输入转为小写并基于 WordPiece 词表切分。
* `AutoModelForSequenceClassification` 在 BERT 编码器之上接了一个二分类头（`num_labels=2`）。由于分类头参数随机初始化，直接推理没有业务意义，此处主要用于验证维度与前向通路是否畅通。

---

### 2. 扩词表前的基准验证（验证 1）

* **原始词表大小**：`len(tokenizer)` 约为 `30522`（包含特殊 Token 和原有子词）。
* **子词切分现象**：在 `bert-base-uncased` 中，`"Huggingface"` 未作为完整词收录，会被拆成 `['hug', '##ging', '##face']`（`##` 表示接在前一子词后）。
* **未登录词 ID 映射**：直接查询 `"huggingface"` 的 ID 会返回 `[UNK]` 的 ID（`100`），说明原本词表中没有该独立条目。

---

### 3. 向词表添加新词（第 2 步 & 验证 2）

```python
custom_vocab = ["huggingface", "tokenization"]
num_added = tokenizer.add_tokens(custom_vocab)

```

* `add_tokens()` 会检查词表中是否已存在这些词，仅添加真正的新词并返回新增数量（此处为 `2`）。
* **扩词后的三个关键变化**：
1. **词表长度增加**：从 `30522` 变为 `30524`。
2. **切分粒度改变**：再对 `test_text` 分词时，`"huggingface"` 会作为一个整体 Token 出现，不再被拆碎。
3. **分配新 ID**：新词按添加顺序追加到原词表末尾（如 `30522`、`30523`），`decode([new_id])` 可以还原出对应词。



> **注意**：`bert-base-uncased` 是大小写不敏感词表，通常输入文本会先做小写化处理；若扩入带大小写的专有名词或代码符号，需留意分词器预处理规则与实际业务语料的一致性。

---

### 4. 同步调整模型 Embedding 矩阵（第 3 步 —— 核心工程点）

```python
model.resize_token_embeddings(len(tokenizer))

```

* **为什么必须做这一步**：模型的词嵌入层（Input Embedding）本质上是一张形状为 `[vocab_size, hidden_size]` 的查找表（`bert-base-uncased` 的 `hidden_size` 为 `768`）。词表扩充后，新 Token ID（如 `30522`）超出了原矩阵的行数上限，**不调整就会在 `embedding(input_ids)` 时触发 `IndexError` 越界报错**。
* **调整机制**：`resize_token_embeddings()` 会保留原有 `0 ~ 30521` 行的权重不变，并为新增行随机初始化向量。
* **后续训练提示**：新增词的向量初始值是随机的，语义尚未对齐；**在实际任务中，通常需要用领域语料继续微调（Fine-tune）模型**，让新词向量学到合理的语义表示（若冻结了 Embedding 层，则新词表征不会更新）。

---

### 5. 编码与前向传播测试（第 4 步）

```python
inputs = tokenizer(
    test_text,
    padding="max_length",
    truncation=True,
    max_length=16,
    return_tensors="pt",
)
outputs = model(**inputs)

```

* `tokenizer(...)` 一次性完成分词、转 ID、补齐/截断到 `max_length=16`，并输出 PyTorch 张量（`input_ids`、`attention_mask` 等）。
* `model(**inputs)` 解包传入张量完成前向计算，最终输出 `outputs.logits`，形状为 `[batch_size, num_labels]`，即 `[1, 2]`，说明词表、嵌入层与模型结构已完全对齐。

### 工程落地小贴士

* **保存与复用**：修改了 `tokenizer` 和 `model` 后，记得分别调用 `tokenizer.save_pretrained(...)` 和 `model.save_pretrained(...)`，否则下次直接从原始 `bert-base-uncased` 加载时不会包含新增词与调整后的嵌入层。
* **什么时候该扩词表**：高频领域专有名词、特定符号/公式/代码片段，或希望减少高频词被拆成过长子词序列时可以考虑；如果只是少量生僻词且数据很少，有时直接依赖子词切分或微调即可，不必盲目扩词增加词表与参数量。
