在 Hugging Face 生态系统中，分词器由 **`transformers`**（高层封装、模型对齐与特殊标记管理）和 **`tokenizers`**（底层核心引擎，由 **Rust** 实现并提供 Python 绑定）共同支撑。

理解它的关键在于掌握**四阶段流水线架构**、**自定义方式（扩词 / 复用训练 / 积木式从零构建）**以及**高效分词与工程优化手段**。

---

### 一、 核心架构：四阶段分词流水线

无论是 BPE、WordPiece 还是 Unigram，底层流水线都围绕四个可组合的阶段运转：

1. **Normalization（规范化）**：对原始文本做清洗或统一处理，如 Unicode 规范化（`NFD`/`NFC`/`NFKC`）、大小写转换（`Lowercase`）、去重音（`StripAccents`）、正则替换等。*注：合并（merge）永远不会跨越预分词边界。*
2. **Pre-tokenization（预分词）**：按空白、标点、字节级规则（`ByteLevel`）或元空格（`Metaspace`，如 `▁`）把文本切分为更小的候选单元（pre-tokens），避免子词合并跨词边界。
3. **Model（分词模型/算法）**：在预分词单元上应用具体算法生成子词与 ID 映射：
* **BPE（Byte-Pair Encoding）**：从字符/字节出发，反复合并高频相邻对直至达到词表上限；字节级 BPE（如 GPT 系列）可覆盖任意字节，天然避免未知字符问题。
* **WordPiece**：类似 BPE，但通常依据互信息/频率比打分合并，常见 `##` 前缀表示后续子词。
* **Unigram**：从较大候选词表出发，基于语言模型概率计算移除某词对语料似然的损失，迭代剪枝至目标大小。


4. **Post-processing（后处理）**：拼接特殊标记（如 `[CLS]`、`[SEP]`、`<s>`、`</s>`）、生成 `attention_mask` 和 `token_type_ids` 等。

---

### 二、 Tokenizer 的三种自定义方式

根据业务场景与成本，自定义通常分为三个层级：

#### 1. 增量扩展词表与特殊 Token（轻量级）

在现有词表上追加领域词或控制符（如工具调用标记、对话角色标记）：

* **普通新词**：使用 `tokenizer.add_tokens(["..."])`（支持传入 `AddedToken` 控制前后空格剥离、整词匹配等行为）；若模型嵌入层维度需同步，需调用 `model.resize_token_embeddings(len(tokenizer))` 并通过微调让新向量获得语义。
* **特殊标记**：使用 `tokenizer.add_special_tokens({"additional_special_tokens": [...]})` 或设置 `cls_token`、`pad_token` 等属性，确保分词时不会被拆散，且解码时可通过 `skip_special_tokens=True` 过滤。

#### 2. 基于已有 Fast Tokenizer 在新语料上重训（中量级）

当目标语言或垂直领域（如代码、医疗、法律）与原训练分布差异较大，但希望沿用某类架构的规范化/预分词规则与特殊标记约定：

```python
from transformers import AutoTokenizer

old_tokenizer = AutoTokenizer.from_pretrained("gpt2")
# corpus_iterator 为 yield 字符串或字符串列表的迭代器
new_tokenizer = old_tokenizer.train_new_from_iterator(corpus_iterator, vocab_size=32000)
new_tokenizer.save_pretrained("./custom_tokenizer")

```

* 优势：直接复用原分词器的流水线配置与特殊标记定义，同时让子词统计分布贴合新语料（例如代码缩进、特定命名习惯）。注意仅适用于具备 Fast 后端的分词器。

#### 3. 使用 `tokenizers` 积木式从零构建（完全定制）

当需要完全自定义的清洗规则、切分逻辑与词表训练参数时，可直接使用 `tokenizers` 库组装模块并训练，再包装进 `transformers`：

```python
from tokenizers import Tokenizer, normalizers, pre_tokenizers, decoders
from tokenizers.models import BPE
from tokenizers.trainers import BpeTrainer
from transformers import PreTrainedTokenizerFast

tok = Tokenizer(BPE(unk_token="<unk>"))
tok.normalizer = normalizers.Sequence([normalizers.NFKC()])
tok.pre_tokenizer = pre_tokenizers.ByteLevel(add_prefix_space=False)
tok.decoder = decoders.ByteLevel()

trainer = BpeTrainer(
    vocab_size=32000,
    special_tokens=["<unk>", "<s>", "</s>", "<pad>"],
)
tok.train(files=["train.txt"], trainer=trainer)

fast_tok = PreTrainedTokenizerFast(
    tokenizer_object=tok,
    unk_token="<unk>",
    bos_token="<s>",
    eos_token="</s>",
    pad_token="<pad>",
)
fast_tok.save_pretrained("./my_bpe_tokenizer")

```

### 三、 高效分词方法与工程实践

在大数据预处理、高并发推理或 Token 级对齐任务中，高效分词的核心在于**减少 Python 解释器开销、充分利用并行与缓存、以及合理组织数据流**：

1. **优先使用 Rust 后端（Fast Tokenizer）**
`AutoTokenizer.from_pretrained(...)` 默认优先加载基于 Rust 的实现。相比纯 Python 分词器，其在批量编码与训练时具备显著吞吐优势，且底层多线程执行可释放 Python GIL 限制。
2. **批量调用而非逐条循环**
始终传入文本列表进行批处理（`tokenizer(texts, padding=..., truncation=..., return_tensors="pt")`），让底层并行处理整批序列，避免 Python 层循环调用的固定开销。
3. **重复词缓存与合并优化**
在自然语言与代码中，高频词和重复片段大量存在；底层流水线会对预分词结果进行缓存复用（如线程级缓存），避免对相同预分词片段重复执行合并/查找计算。词表规模也需权衡：过大的词表会增加 Embedding 矩阵显存与输出投影计算量，过小则会拉长序列长度、降低注意力与吞吐效率。
4. **善用 Span 对齐能力替代二次文本匹配**
Fast 分词器返回的 `BatchEncoding` 支持字符级与词级索引映射（如 `char_to_token()`、`token_to_chars()`、`word_ids()` 等），在命名实体识别（NER）、抽取式问答（QA）或高亮回溯时，可直接定位原文区间，无需手写复杂的字符串对齐逻辑。
5. **离线预分词与多进程数据集流水线**
* 训练大模型或大语料微调时，建议提前将文本分词并持久化为二进制/列式缓存（如配合 `datasets` 的批处理映射），避免训练时 CPU 分词成为 GPU 算力的瓶颈。
* 注意多进程（如 `num_workers > 0`）与线程池的嵌套调度：在多进程 DataLoader 中，有时需结合环境变量（如 `TOKENIZERS_PARALLELISM=false` 或 `true` 按需测试）避免线程争抢导致的性能抖动。


6. **序列化与版本一致性**
自定义完成后，务必通过 `save_pretrained()` 或 `push_to_hub()` 完整保存词表、合并规则及 `tokenizer.json` / `tokenizer_config.json`，保证训练、评估与推理阶段分词行为完全一致。
