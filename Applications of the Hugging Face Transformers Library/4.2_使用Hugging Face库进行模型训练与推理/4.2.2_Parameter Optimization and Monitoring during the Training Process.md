Parameter Optimization and Monitoring during the Training Process.py代码展示了如何使用 Hugging Face 的 `transformers` 和 `datasets` 库，对 **BERT** 模型进行**文本二分类任务**的微调（Fine-tuning）。整体流程非常标准，适合作为入门模板。

下面按模块逐一拆解并补充工程实践中的关键细节：

---

### 一、 依赖库导入

* `numpy`：用于处理模型输出的 `logits` 并计算准确率等指标。
* `torch`：PyTorch 深度学习框架，底层张量与自动求导由它支撑。
* `datasets.Dataset`：Hugging Face 提供的高效数据集格式，能与 `Trainer` 无缝衔接并支持内存映射/批处理。
* `transformers`：
* `AutoTokenizer`：根据模型名称自动加载对应的分词器。
* `AutoModelForSequenceClassification`：在预训练 BERT 编码器顶部自动添加一个**序列分类头**（通常是 `[CLS]` 向量接一个线性层），用于输出各类别的原始得分（`logits`）。
* `Trainer`：封装了训练循环、梯度更新、评估、日志记录和模型保存的高层 API。
* `TrainingArguments`：集中配置所有训练超参数与行为开关。



---

### 二、 分步骤解析

#### 1. 加载模型与 Tokenizer

```python
model_name = "bert-base-uncased"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForSequenceClassification.from_pretrained(
    model_name, num_labels=2
)

```

* `bert-base-uncased` 表示 12 层、768 隐藏维度、12 个注意力头的英文基础版 BERT，且输入文本会统一转小写。
* `num_labels=2` 指定二分类任务，分类头输出维度为 `2`。首次运行会从 Hugging Face Hub 下载权重并缓存到本地。
* **注意**：BERT 预训练权重中不包含分类头参数，因此初始化时通常会看到类似 `Some weights of BertForSequenceClassification were not initialized...` 的提示，这是正常现象，分类头会在微调阶段从头训练。

#### 2. 准备示例数据

```python
texts = [
    "I love Hugging Face!",
    "Transformers library is amazing.",
    "Parameter optimization is crucial.",
]
labels = [1, 1, 0]

```

* 这里提供了 3 条文本和对应的整数标签（`0` 和 `1`）。实际项目中通常会从 CSV、JSON 或 `load_dataset` 加载成千上万条数据。

#### 3. 数据预处理与封装

```python
def preprocess_data(texts, labels):
  inputs = tokenizer(
      texts, padding="max_length", truncation=True, max_length=32
  )
  dataset = Dataset.from_dict({
      "input_ids": inputs["input_ids"],
      "attention_mask": inputs["attention_mask"],
      "labels": labels,
  })
  return dataset

```

* `tokenizer(...)` 完成三件事：分词、映射为词表 ID（`input_ids`），以及生成注意力掩码（`attention_mask`，`1` 表示真实 token，`0` 表示 padding 填充位）。
* `padding="max_length"` 与 `truncation=True` 将所有样本统一截断或填充到 `max_length=32`。
* 字段名命名为 `labels` 是关键约定：`Trainer` 在计算交叉熵损失（Cross-Entropy Loss）时，会自动在样本字典中查找 `labels` 字段。
* 注释提到“避免 Tensor 包装嵌套”很实用：保持 Python `list` 结构交给 `Dataset.from_dict`，后续 `Trainer` 默认的 `data_collator` 会按批次动态转换为正确的张量形状。

#### 4. 配置训练参数（`TrainingArguments`）

* `output_dir="./results"`：存放训练检查点（checkpoints）和输出文件的目录。
* `eval_strategy="epoch"` 与 `save_strategy="epoch"`：每个 epoch 结束后执行一次验证集评估，并保存一次模型权重。两者设为 `"epoch"` 可避免策略不一致导致的报错。
* `learning_rate=2e-5`：Transformer 微调的经典较小学习率，防止破坏预训练语义表示。
* `per_device_train_batch_size=2` / `per_device_eval_batch_size=2`：单张显卡（或 CPU）上的训练与评估批次大小。
* `num_train_epochs=3`：完整遍历训练集的轮数为 3。
* `weight_decay=0.01`：AdamW 优化器的权重衰减系数，起到正则化作用、减轻过拟合。
* `logging_steps=10`：每 10 个训练步输出一次日志（本示例样本少、每 epoch 步数很少，可能看不到多次 step 日志，但每个 epoch 结束仍会打印评估结果）。
* `report_to="none"`：关闭 Weights & Biases、TensorBoard 等第三方实验追踪平台的自动上报。

#### 5. 自定义评估指标（`compute_metrics`）

```python
def compute_metrics(eval_pred):
  logits, labels = eval_pred
  predictions = np.argmax(logits, axis=-1)
  accuracy = np.mean(predictions == labels)
  return {"accuracy": accuracy}

```

* `eval_pred` 是一个元组 `(logits, labels)`：`logits` 形状通常为 `(样本数, 2)`，`labels` 形状为 `(样本数,)`。
* `np.argmax(logits, axis=-1)` 取出得分最高的类别索引作为预测结果，再计算与真实标签相等的比例作为准确率（`accuracy`）。
* 必须返回一个字典，键名会作为评估日志中的指标名称。

#### 6. 初始化 `Trainer` 并启动训练

```python
trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=dataset,
    eval_dataset=dataset,
    compute_metrics=compute_metrics,
)
trainer.train()

```

* `Trainer` 自动检测可用设备（CUDA GPU / MPS / CPU），构建 `DataLoader` 和优化器（默认 `AdamW` + 线性学习率调度），并在训练中周期性调用 `compute_metrics`。

### 四、 实际使用中的注意事项

1. **切勿直接复用同一份数据做 `train_dataset` 和 `eval_dataset**`：代码里为了跑通流程把 `dataset` 同时传给了两者，这会导致评估结果严重虚高（数据泄漏）。正式训练时应拆分为独立的训练集和验证集（例如 `dataset.train_test_split(test_size=0.2)`）。
2. **动态 Padding 提升效率**：如果句子长短差异较大，相比 `padding="max_length"`，通常更推荐只做 `truncation=True`，并搭配 `DataCollatorWithPadding(tokenizer=tokenizer)` 按 batch 补齐到该批次最长序列，能减少无效计算。
3. **保存最终模型与分词器**：`save_strategy="epoch"` 会在 `./results` 下生成 `checkpoint-*` 目录；若想导出干净的最终模型目录，可在 `trainer.train()` 后调用 `trainer.save_model("./final_model")` 和 `tokenizer.save_pretrained("./final_model")`。
