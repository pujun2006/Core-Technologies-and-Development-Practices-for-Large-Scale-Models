Multipath Generation and Evaluation in Beam Search.py代码基于 Hugging Face `transformers` 库，使用中文 GPT-2 模型（`uer/gpt2-chinese-cluecorpussmall`）演示了 **Beam Search（束搜索）** 在文本生成中的标准调用方式。

下面按执行流程拆解代码逻辑、关键参数含义以及工程实践中需要注意的细节。

---

### 一、 分步代码解析

#### 1. 加载模型与分词器

```python
model_name = "uer/gpt2-chinese-cluecorpussmall"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name)

tokenizer.pad_token_id = tokenizer.eos_token_id

```

* **`AutoTokenizer` 与 `AutoModelForCausalLM**`：分别加载分词器和因果语言模型（Causal LM，即自回归逐词预测模型）。`uer/gpt2-chinese-cluecorpussmall` 是基于中文语料训练的 GPT-2 模型，中文分词通常按字/子词切分。
* **设置 `pad_token_id**`：部分 GPT-2 类模型默认未显式定义填充符（`pad_token_id`），在批处理或生成对齐时可能触发提示/警告；将其设为 `eos_token_id` 是一种常见做法（更严谨的做法是在 `model.generation_config.pad_token_id` 或 `inputs["attention_mask"]` 一并传入，避免 `eos` 与 `pad` 混淆）。

#### 2. 准备输入文本与张量编码

```python
input_text = "在未来的人工智能领域，"
inputs = tokenizer(input_text, return_tensors="pt")
input_ids = inputs.input_ids

```

* `tokenizer(..., return_tensors="pt")` 将输入文本转为 PyTorch 张量，返回包含 `input_ids` 和 `attention_mask` 的字典。
* `input_ids` 的形状通常为 `(batch_size=1, seq_len)`，代表模型看到的初始上下文 Token 序列。

#### 3. 设置 Beam Search 候选数量参数

```python
beam_size = 5
num_return_sequences = 3

```

* `beam_size = 5`：每一步保留得分最高的 **5 条**候选路径（束宽 $B=5$）。
* `num_return_sequences = 3`：最终从搜索结果中返回得分最高的 **3 条**完整序列。注意该值**不能大于** `num_beams`（否则 `transformers` 会报错）。

#### 4. 调用 `model.generate()` 执行束搜索

```python
outputs = model.generate(
    input_ids,
    max_length=50,
    num_beams=beam_size,
    num_return_sequences=num_return_sequences,
    early_stopping=True,
    length_penalty=1.0,
)

```

`generate()` 内部会自动完成多步自回归前向传播、对数概率累加、束内剪枝、KV Cache 维护与重排。核心参数说明如下：

* **`max_length=50`**：整个输出序列（**包含**输入的 `input_ids` 长度）的最大 Token 数上限。如果只关心**新生成**的 Token 数量，通常更推荐使用 `max_new_tokens`。
* **`num_beams=5`**：启用 Beam Search（当 `num_beams=1` 且 `do_sample=False` 时退化为贪心搜索）。
* **`num_return_sequences=3`**：输出张量 `outputs` 的形状会变为 `(3, seq_len)`。
* **`early_stopping=True`**：当已有 `num_beams` 条候选序列生成了结束符（`eos_token_id`）时提前停止搜索，而不必硬撑到 `max_length`。
* **`length_penalty=1.0`**：控制序列长度对最终排序得分的影响（在 `transformers` 的 `generate` 实现中，长度惩罚因子通常与序列长度指数相关；一般而言，**较大值**更倾向较长输出，**较小值**如小于 1 或负数倾向较短输出，需结合具体模型版本与任务调参验证）。

#### 5. 解码并打印结果

```python
for i, sequence in enumerate(outputs):
    text = tokenizer.decode(sequence, skip_special_tokens=True)
    print(f"Beam {i+1}: {text}")

```

* `outputs` 中的每条 `sequence` 都是一个一维 Token ID 张量。
* `tokenizer.decode(..., skip_special_tokens=True)` 将 ID 还原为可读中文字符串，并剔除特殊符号（如 `<|endoftext|>`）。打印顺序按模型评估的序列得分从高到低排列。

### 二、 实际使用中的常见改进点

1. **显式传入 `attention_mask` 与设备迁移**
实际运行中建议把整个 `inputs` 字典（含 `attention_mask`）传给 `generate()`，并将 `model` 与张量放到 GPU（`cuda`）上以加速推理：
```python
device = "cuda" if torch.cuda.is_available() else "cpu"
model = model.to(device)
inputs = tokenizer(input_text, return_tensors="pt").to(device)

outputs = model.generate(
    **inputs,
    max_new_tokens=40,       # 明确控制新生成长度，比 max_length 更直观
    num_beams=5,
    num_return_sequences=3,
    early_stopping=True,
    no_repeat_ngram_size=2,  # 防止中文连续重复字词/短语（如“的的人人”）
    pad_token_id=tokenizer.eos_token_id,
)

```


2. **中文生成中的“复读”与“同质化”问题**
Beam Search 在中文文本生成中很容易出现多条候选句式高度相似，或局部字词循环重复的情况。加上 `no_repeat_ngram_size=2` 或 `3`（或适度设置 `repetition_penalty`，如 `1.1 ~ 1.2`）通常能明显改善可读性。
3. **`max_length` 与 `max_new_tokens` 互斥**
两者不要同时传入；若输入长度不固定，优先用 `max_new_tokens` 避免因输入较长导致几乎没有生成空间。
