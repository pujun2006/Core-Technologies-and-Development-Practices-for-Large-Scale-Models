Limitations and Sparsity Control of Top-K Sampling.py代码基于 Hugging Face `transformers` 库，使用中文 GPT-2 模型（`uer/gpt2-chinese-cluecorpussmall`）演示了 **Top-K 采样**的调用方式，并通过循环对比不同 `top_k` 取值（`10`、`50`、`100`）对生成结果多样性的影响。

下面按执行流程拆解代码逻辑、关键参数作用以及实验对比时的工程细节。

---

### 一、 分步代码解析

#### 1. 加载模型与分词器

```python
model_name = "uer/gpt2-chinese-cluecorpussmall"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name)

tokenizer.pad_token_id = tokenizer.eos_token_id

```

* 加载适配中文的因果语言模型（Causal LM）及对应分词器。
* 将 `tokenizer.pad_token_id` 设为 `tokenizer.eos_token_id`，可避免部分情况下因缺少填充符 ID 导致的控制台提示。

#### 2. 准备输入文本与编码

```python
input_text = "在科技发展的未来，"
inputs = tokenizer(input_text, return_tensors="pt")
input_ids = inputs.input_ids

```

* 将中文提示词编码为 PyTorch 张量 `input_ids`，形状为 `(1, seq_len)`。

#### 3. 单次 Top-K 采样测试

```python
top_k_value = 50
output = model.generate(
    input_ids,
    max_length=50,
    top_k=top_k_value,
    do_sample=True,
)

```

* **`do_sample=True`**：**极其关键**。在 `transformers` 中，如果只传 `top_k=50` 而不显式设置 `do_sample=True`，默认情况下模型仍会走贪心搜索（或束搜索），`top_k` 参数不会生效。
* **`top_k=50`**：在每一步预测下一个 Token 时，仅保留概率最高的前 50 个候选 Token，其余词概率置零并重新归一化后按概率随机抽取。
* **`max_length=50`**：整个输出序列（含输入 `input_ids`）的最大 Token 长度。

#### 4. 解码并打印单次采样结果

```python
generated_text = tokenizer.decode(output[0], skip_special_tokens=True)

```

* `output` 形状为 `(1, seq_len)`，`output[0]` 取出第一条生成序列的 Token IDs，再通过 `decode(..., skip_special_tokens=True)` 还原为可读中文并剔除特殊符号。

#### 5. 多组 `top_k` 对比循环

```python
top_k_values = [10, 50, 100]
generated_texts = []

for k in top_k_values:
    output = model.generate(input_ids, max_length=50, top_k=k, do_sample=True)
    text = tokenizer.decode(output[0], skip_special_tokens=True)
    generated_texts.append((k, text))

```

* 依次将 `top_k` 设为 `10`、`50`、`100` 进行采样生成，用于直观观察候选词池扩大后文本词汇与走向的变化：
* **`top_k=10`**：候选集最紧凑，语义连贯性较高，但词汇与句式变化相对克制；
* **`top_k=50`**：多样性与可控性折中，适合常见开放续写；
* **`top_k=100`**：候选集更宽，更容易出现新颖表达，但也更可能抽到概率偏低的词，增加跑题或局部不通顺的概率。

### 二、 实验与实际使用中的改进建议

1. **固定随机种子以保证可复现性**
代码中注释已提示可设置随机种子。做参数对比实验时，建议在每次循环前调用 `torch.manual_seed(...)`（若使用 GPU 还可加上 `torch.cuda.manual_seed_all(...)`），否则单次抽样存在偶然性，可能出现“某次 `top_k=100` 反而很保守、某次 `top_k=10` 却跳出意外词”的现象。
2. **多轮重复采样观测分布规律**
由于采样是随机过程，每个 `K` 值只跑 1 次只能看单样本。若要客观对比多样性，可以对每个 `K` 值生成多条序列（例如设 `num_return_sequences=5` 或循环跑多次），观察不同样本之间的差异程度。
3. **补充 `attention_mask`、`max_new_tokens` 与设备配置**
```python
device = "cuda" if torch.cuda.is_available() else "cpu"
model = model.to(device)
inputs = tokenizer(input_text, return_tensors="pt").to(device)

for k in [10, 50, 100]:
    torch.manual_seed(42)
    output = model.generate(
        **inputs,
        max_new_tokens=40,
        top_k=k,
        do_sample=True,
        temperature=0.8,
        pad_token_id=tokenizer.eos_token_id,
    )

```


使用 `max_new_tokens` 可以更直观地控制新增字数，传入 `**inputs` 能完整保留 `attention_mask`，搭配 `temperature` 则可进一步调节概率分布的陡峭度。
