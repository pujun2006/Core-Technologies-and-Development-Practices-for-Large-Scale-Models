Adaptive Probability Truncation Mechanism in Top-P Sampling.py代码基于 Hugging Face `transformers` 库，使用中文 GPT-2 模型（`uer/gpt2-chinese-cluecorpussmall`）演示了 **Top-P（Nucleus / 核）采样**的单次生成与多阈值对比（`0.7`、`0.9`、`0.95`），并在推理阶段显式加入了 `torch.no_grad()`。

下面按执行流程拆解代码逻辑、关键参数作用以及实际运行时的改进建议。

---

### 一、 分步代码解析

#### 1. 加载模型与分词器

```python
model_name = "uer/gpt2-chinese-cluecorpussmall"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name)

tokenizer.pad_token_id = tokenizer.eos_token_id

```

* 加载中文 GPT-2 因果语言模型（Causal LM）及分词器。
* 将 `tokenizer.pad_token_id` 设为 `tokenizer.eos_token_id`，以避免在缺少独立填充符号时产生冗余提示。

#### 2. 准备输入文本与张量编码

```python
input_text = "未来的科技发展将会带来"
inputs = tokenizer(input_text, return_tensors="pt")
input_ids = inputs.input_ids

```

* 将中文提示词编码为 PyTorch 张量 `input_ids`，形状为 `(1, seq_len)`。

#### 3. 使用 `torch.no_grad()` 执行单次 Top-P 采样

```python
top_p_value = 0.9

with torch.no_grad():
    output = model.generate(
        input_ids,
        max_length=50,
        top_p=top_p_value,
        do_sample=True,
    )

```

* **`with torch.no_grad():`**：禁用自动求导计算图构建，不保存中间激活值以供反向传播，从而显著降低显存/内存占用并减少推理开销（注：`model.generate()` 内部通常也带有 `torch.inference_mode()` 或 `no_grad` 保护，但显式包裹是规范的推理习惯）。
* **`do_sample=True`**：开启随机采样模式；只有开启该参数，`top_p` 才会生效。
* **`top_p=0.9`**：每一步按概率降序累加候选词，仅保留累计概率达到或超过 `0.9` 的最小核心词集，在集合内重新归一化后抽样。
* **`max_length=50`**：生成结束后整个序列（包含输入 `input_ids`）的最大 Token 总长度。

#### 4. 解码并打印单次结果

```python
generated_text = tokenizer.decode(output[0], skip_special_tokens=True)

```

* 取出第一条生成序列（`output[0]`），解码为中文字符串并跳过特殊 Token（如结束符）。

#### 5. 对比不同 `top_p` 阈值的生成效果

```python
top_p_values = [0.7, 0.9, 0.95]
generated_texts = []

with torch.no_grad():
    for p in top_p_values:
        output = model.generate(
            input_ids,
            max_length=50,
            top_p=p,
            do_sample=True,
        )
        text = tokenizer.decode(output[0], skip_special_tokens=True)
        generated_texts.append((p, text))

```

* 依次测试 `0.7`、`0.9`、`0.95` 三档累计概率阈值，观察候选词池动态伸缩带来的差异：
* **`top_p=0.7`**：截断较紧，核心词集更小，输出更稳健、贴合高概率主线，但词汇发散度相对保守；
* **`top_p=0.9`**：兼顾连贯性与丰富度，是通用对话与续写中较为均衡的经验值；
* **`top_p=0.95`**：放宽长尾截断，在分布分散时能纳入更多候选词，多样性更高，但偶发低概率词的几率也会随之增加。

### 三、 实际使用中的改进建议

1. **加上随机种子与多样本对比**
与 Top-K 类似，随机采样具有偶然性。做阈值对比时，若想观察单一参数设定下的稳定倾向，可在循环内固定随机种子（如 `torch.manual_seed(42)`）；若想对比多样性，可设置 `num_return_sequences=3`（或多次运行），直观比较同一 `p` 值下不同样本的差异程度。
2. **补充 `attention_mask`、`max_new_tokens` 与设备移动**
```python
device = "cuda" if torch.cuda.is_available() else "cpu"
model = model.to(device).eval()
inputs = tokenizer(input_text, return_tensors="pt").to(device)

with torch.no_grad():
    output = model.generate(
        **inputs,
        max_new_tokens=40,
        do_sample=True,
        top_p=0.9,
        temperature=0.8,
        pad_token_id=tokenizer.eos_token_id,
    )

```


* 调用 `model.eval()` 可确保 Dropout 等推理期行为处于评估状态；
* 传入 `**inputs` 能同时传递 `attention_mask`；
* 使用 `max_new_tokens` 控制新增长度，可避免因输入文本长短不一导致实际生成字数波动。
