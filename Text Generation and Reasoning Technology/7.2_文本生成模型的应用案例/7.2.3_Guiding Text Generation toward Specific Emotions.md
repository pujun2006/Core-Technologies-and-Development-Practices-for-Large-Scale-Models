Guiding Text Generation toward Specific Emotions.py代码基于 Hugging Face `transformers` 与中文 GPT-2 模型（`uer/gpt2-chinese-cluecorpussmall`），演示了一种**无需微调、通过自然语言提示词前缀引导情绪**的文本生成方法，并对正面/积极与负面/悲伤两种情绪进行了对比测试。

下面按模块拆解代码逻辑、解码参数组合，以及在**基座续写模型**上做情绪引导时的注意事项。

---

### 一、 分步代码解析

#### 1. 模型与分词器初始化

```python
model_name = "uer/gpt2-chinese-cluecorpussmall"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name)

if tokenizer.eos_token is None:
    tokenizer.eos_token = "<|endoftext|>"
tokenizer.pad_token_id = tokenizer.eos_token_id

```

* 加载中文因果语言模型（Causal LM）及分词器，并通过防御性检查补全 `eos_token` 与 `pad_token_id`，避免缺少填充符号或结束符时出现异常或警告。

#### 2. 情绪提示词组装与编码

```python
if emotion_desc:
    full_prompt = f"【请用{emotion_desc}的情绪接写】\n{prompt}"
else:
    full_prompt = prompt

input_ids = tokenizer.encode(full_prompt, return_tensors="pt")

```

* 当传入 `emotion_desc` 时，将其拼入带有 `【...】` 边界和换行的前缀提示中，再接上核心开头 `prompt`（如 `"今天的天气真好，"`）；
* 注释提到“不使用无效的伪 Tag”，意在避免发明模型训练时从未见过的特殊标记（如 `<emo_pos>`），而是用自然中文词句让模型从语义语境中获取倾向。
* 随后通过 `tokenizer.encode(..., return_tensors="pt")` 转换为形状 `(1, seq_len)` 的输入张量。

#### 3. 混合采样参数调用 `model.generate()`

```python
with torch.no_grad():
    output = model.generate(
        input_ids,
        max_new_tokens=max_new_tokens,
        do_sample=True,
        top_p=top_p,
        top_k=50,
        temperature=temperature,
        no_repeat_ngram_size=2,
        pad_token_id=tokenizer.eos_token_id,
    )

```

这段配置把前面介绍的几种解码控制手段组合在了一起：

* **`with torch.no_grad():`**：推理期禁用梯度计算，降低显存/内存占用。
* **`max_new_tokens=50`**：限定最多新生成 `50` 个 Token。
* **`do_sample=True`**：开启随机采样。
* **`top_p=0.9` + `top_k=50**`：同时启用 Top-P 与 Top-K 截断。在 `transformers` 中两者同时传入时，通常会按库内预设顺序先后过滤候选词（先 `top_k` 粗筛再 `top_p` 累积截断，或反之，具体视版本实现），既能保证自适应核心集，又能给极端分散分布加一道上限。
* **`temperature=temperature`**：测试中设为 `0.8`，比默认 `1.0` 略微温和，既能保留情绪表达的丰富度，又能减少过高的随机噪音。
* **`no_repeat_ngram_size=2`**：抑制连续重复的 `2-gram` 片段，缓解短文本复读。

#### 4. 精准截取新生成内容与拼接展示

```python
response_ids = output[:, input_ids.shape[-1] :]
generated_text = tokenizer.decode(response_ids[0], skip_special_tokens=True)
return generated_text

```

* `output` 包含完整的 `full_prompt` 与新生成的 Token；通过切片 `[:, input_ids.shape[-1]:]` 只提取新生成的部分并解码为 `generated_text`。
* 在打印时使用 `base_prompt + pos_text` 和 `base_prompt + neg_text`，把情绪指令前缀剥离，只展示“原始开头 + 对应情绪续写”的最终效果，便于直观对比。

### 三、 实际运行中的局限性与优化建议

1. **基座模型对“指令句式”的响应有限**
`uer/gpt2-chinese-cluecorpussmall` 是以**文本接龙/续写**为主训练的预训练基座模型，而非经过指令微调（SFT）或对话对齐的模型。像 `【请用……的情绪接写】` 这类指令型前缀，模型有时能顺着情绪词带出一些倾向，但有时也可能把 `【...】` 当成普通书名号/括号文本续写，甚至受 `base_prompt` 本身（`"今天的天气真好，"` 本身偏积极）的惯性影响，导致“悲伤/消极”续写出现转折或不够纯粹。
2. **改用“少样本语境续写（Few-Shot）”往往更稳**
对于 GPT-2 这类基座模型，若想让情绪引导更稳定，通常比单句指令更有效的方式是**提供 $1 \sim 2$ 个同情绪风格的续写样例**，让模型直接模仿样例的词汇色彩与语气节奏，例如：
```python
few_shot_prompt = (
    "示例1：\n"
    "开头：今天的天气真好，\n"
    "续写：阳光洒满街道，微风轻拂树叶，整个人都充满活力，恨不得立刻出门跑一圈！\n\n"
    "示例2：\n"
    "开头：今天的天气真好，\n"
    f"续写：{base_prompt}"
)

```


3. **补充 `attention_mask` 与 `model.eval()**`
在推理前调用 `model.eval()`，并将 `tokenizer(full_prompt, return_tensors="pt")` 返回的 `input_ids` 与 `attention_mask` 一并传入 `generate()`，会让推理配置更加完整规范。
