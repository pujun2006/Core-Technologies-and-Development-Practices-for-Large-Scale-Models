Long-Text Generation Using Pre-trained Language Models.py代码基于 Hugging Face `transformers` 库与中文 GPT-2 模型（`uer/gpt2-chinese-cluecorpussmall`），对比演示了生成较长文本的两种常见做法：**一次性采样生成**与**多轮迭代扩展生成**。

下面按执行结构拆解代码逻辑、参数组合特点，以及分段循环中的细节与潜在改进点。

---

### 一、 初始化与输入准备

```python
model_name = "uer/gpt2-chinese-cluecorpussmall"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name)

tokenizer.pad_token_id = tokenizer.eos_token_id

input_text = "在未来的城市里，科技的发展让生活发生了巨大的变化。"
input_ids = tokenizer(input_text, return_tensors="pt").input_ids

```

* 加载中文因果语言模型及对应分词器，并将 `pad_token_id` 设为 `eos_token_id`。
* `input_ids` 是形状为 `(1, seq_len)` 的 PyTorch 张量，作为后续两种生成方式的共同起点。

---

### 二、 方式 1：一次性生成长文本（采样 + 防重复组合）

```python
with torch.no_grad():
    output_one_shot = model.generate(
        input_ids,
        max_length=200,
        do_sample=True,
        top_p=0.9,
        temperature=0.8,
        no_repeat_ngram_size=2,
    )

generated_text_one_shot = tokenizer.decode(
    output_one_shot[0], skip_special_tokens=True
)

```

* **`with torch.no_grad():`**：推理阶段关闭梯度记录，降低显存/内存占用。
* **`max_length=200`**：整个输出序列（含输入 `input_ids`）的最大 Token 总长度上限为 `200`。
* **`do_sample=True` + `top_p=0.9` + `temperature=0.8**`：
* `temperature=0.8` 略微收紧概率分布，避免高温导致的发散跑题；
* `top_p=0.9` 动态保留核心概率词集，兼顾流畅度与词汇多样性；
* 相比纯贪心或 Beam Search，采样组合在长文本中更不易陷入单调套话。


* **`no_repeat_ngram_size=2`**：禁止生成序列中出现重复的 `2-gram`（连续 2 个 Token 的组合）。
* **补充说明**：在字级别或子词切分的中文模型中，设 `no_repeat_ngram_size=2` 能较强地抑制双字短语重复，但有时也可能误伤常见词组（如“科技”“发展”“系统”等若在上下文其他位置出现过）或标点搭配；实际使用时可根据输出效果在 `2`、`3`、`4` 之间对比调整。

### 三、 方式 2：分段迭代扩展生成（Token 级追踪）

```python
current_ids = input_ids
step_generate_tokens = 30

with torch.no_grad():
    for _ in range(3):
        input_len = current_ids.shape[1]

        output_step = model.generate(
            current_ids,
            max_length=input_len + step_generate_tokens,
            do_sample=True,
            top_p=0.9,
            temperature=0.8,
            no_repeat_ngram_size=2,
            pad_token_id=tokenizer.pad_token_id,
        )

        current_ids = output_step

final_text = tokenizer.decode(current_ids[0], skip_special_tokens=True)

```

1. **为什么在 Token 张量层迭代而不是字符串拼接？**
直接在 Token ID 张量（`current_ids`）上追加生成结果，可以避免反复“Token 转字符串再重新分词”带来的边界切分差异或特殊符号丢失，序列追踪更准确。
2. **每轮扩展长度的计算**
每轮先读取当前序列长度 `input_len = current_ids.shape[1]`，再将目标总长度设为 `input_len + step_generate_tokens`（即每次最多新增 `30` 个 Token），循环 `3` 次，理论最大新增约 `90` 个 Token。
3. **代码实现中的一个小细节**
注释中提到“只在 Token 层面切片，只保留本次新生成的 Token ID，再更新 `current_ids`”，但实际赋值写的是 `current_ids = output_step`。
* 因为 `model.generate()` 默认返回的是**完整序列**（即 `current_ids` 拼接上新生成的 Token），所以 `current_ids = output_step` 实际上已经把前文与新生成的 Token 一起累积下来了，最终 `final_text` 是完整的连贯长文。
* 如果确实想在循环内部单独拿到**本轮新增的 Token 切片**（例如做单步长度统计、逐段处理或插入分隔符/提示词），可以通过 `new_tokens = output_step[:, input_len:]` 切片取出，再用 `torch.cat([current_ids, new_tokens], dim=-1)` 拼接。

### 五、 实用优化建议

1. **优先使用 `max_new_tokens` 替代 `max_length**`
无论是单次生成还是分段扩展，使用 `max_new_tokens=30` 都能直接表达“新增 30 个 Token”，无需手动计算 `input_len + step_generate_tokens`，可读性更好且不易算错。
2. **分段扩展与“提示词引导”结合**
目前方式 2 在循环中每次直接把 `current_ids` 原封不动喂回 `model.generate()`，作用上接近“分步设置上限的一次性续写”；若希望分段生成发挥更大价值，可在每段之间根据需要动态调整参数，或结合大纲/段落提示词引导下一阶段内容。
3. **注意模型最大长度限制与 `attention_mask**`
`uer/gpt2-chinese-cluecorpussmall` 的最大位置编码长度通常为 `1024`，当多轮累积的 `current_ids.shape[1]` 接近上限时需注意截断或控制总步数；同时建议将设备转移（`.to(device)`）与 `attention_mask` 一并传入 `generate()`。
