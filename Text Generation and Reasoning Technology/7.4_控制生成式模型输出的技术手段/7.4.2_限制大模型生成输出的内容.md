限制大模型（LLM）生成输出的内容，核心目标是**框定信息来源、锁定表达/结构边界、屏蔽高风险与越界内容**。与泛化的“输出控制”不同，“限制内容”更强调“什么能说、什么不能说、只能基于什么说、必须长什么样”**。在工程上，通常需要将**指令提示、知识锚定、解码掩码、外部护栏组合使用，形成纵深防御。

### 一、 从“知识与信息源”限制：防瞎编与防越界引用

当业务要求模型“只按规矩办事、不自由发挥”时，重点在于限制其可用的事实与上下文边界：

* **强上下文锚定（Context Grounding + 拒答兜底）**：在 RAG 或文档问答中，明确规定“仅允许依据 `[Context]` 作答；若上下文中未提及，必须输出 `未在提供资料中找到相关信息`，严禁调用外部常识或猜测”。配合**低温度（如 `0.0` ~ `0.2`）**，能显著压制参数记忆幻觉。
* **白名单与溯源约束**：要求模型在给出结论时必须附带段落编号、文档 ID 或引用片段，并在应用层校验引用是否真实存在于检索结果中，剔除无据断言。
* **工具调用隔离（Tool / API Gate）**：涉及实时数据、权限查询、数据库读写或精确计算时，通过 Tool Calling 强制模型走结构化参数调用，而不是靠文本“口头编造”结果。

### 二、 从“语义范围与话题边界”限制：防跑题、防违规、防越狱

针对主题范围、合规红线与敏感信息泄露的限制，需要同时兼顾**输入侧防护**与**输出侧拦截**：

* **System Prompt 边界声明**：清晰定义角色职责、允许讨论的话题领域、禁答话题清单与标准拒答话术；同时采用分隔符（如 XML 标签或三引号）隔离不可信的用户输入，降低提示词注入（Prompt Injection）绕过限制的概率。
* **输入预检与输出审查（Input / Output Guardrails）**：
* 部署独立的安全分类器、审核模型或规则引擎，对用户输入和模型输出进行违规类别检测、敏感词匹配与 PII（手机号、身份证、密钥、隐私数据）识别。
* 一旦命中风险，直接在网关层拦截并返回预设安全回复，不让违规内容抵达用户端。


* **对齐与拒答微调（SFT / DPO / 红队样本）**：针对垂域合规要求或特定拒答风格，补充负样本与边界样本进行对齐训练，使模型在面对诱导性提问时更稳定地执行拒答或安全转述。

### 三、 从“词表与解码路径”限制：防格式跑偏、禁词与死循环

当需要从底层限制模型**允许选哪些词、必须遵循什么语法或长度上限**时，解码层最直接有效：

* **结构化约束解码（JSON Schema / 正则 / 文法掩码）**：利用有限状态机或语法解析器在每一步生成前屏蔽非法 Token，强制输出符合 JSON Schema、枚举值、正则模式或 SQL/代码语法的内容。这不仅限制了“形式”，也通过枚举字段（如 `intent: ["refund", "complaint", "other"]`）把开放生成收窄为有限选项。
* **词表级禁用与偏置（Bad Words / Logit Bias）**：
* **禁用词列表（`bad_words_ids` / 禁止 Token 掩码）**：直接将特定违禁词、敏感词或特定格式标记的概率置零，阻止其生成。
* **Logit Bias**：对特定 Token 施加正向或负向偏置，引导模型倾向或规避某些词汇/符号。


* **长度与终止控制（`max_new_tokens` / `stop` 序列）**：
* 通过 `max_new_tokens` 硬性卡住最大输出长度，防止长篇废话或无限续写；
* 配置停止词（Stop Sequences，如特定分隔符、换行组合或闭合标签），一旦生成到指定边界立即截断。


* **重复惩罚与采样截断**：通过重复惩罚抑制复读机现象；通过 `temperature`、`top_p`、`top_k` 控制候选词发散程度，避免在高温下抽出生僻或离谱词汇。

---

### 四、 从“结果校验与闭环修正”限制：后置兜底与重写

提示词和采样参数本质上都是“概率引导”，在强约束业务中不能完全依赖单次生成，需要后处理闭环：

* **Schema / 规则校验器 + 自动重试**：模型输出后立即做 JSON 解析、字段类型/范围校验或业务规则检查；若不合规，可将错误信息回传给模型做定向修复（限定重试次数，如最多 2 次），仍失败则走确定性降级模板。
* **后置改写 / 脱敏流水线**：对已生成文本执行正则脱敏、敏感词替换或轻量重写模型精炼，在不重新跑完整复杂推理的前提下完成最后一道内容清理。

### 五、 常见限制目标与方案对照

| 限制目标 | 推荐组合手段 | 关键注意事项 |
| --- | --- | --- |
| **只说检索到的事实，不瞎编** | 强上下文 Prompt + 拒答指令 + 低 Temperature + 引用校验 | 检索召回质量是前提；召回为空时应直接走拒答分支 |
| **只输出指定字段/枚举/JSON** | JSON Schema / 枚举约束 + 结构化校验重试 | 约束过死可能影响复杂推理步骤，必要时先思考字段再输出 |
| **禁说违禁词/不泄露隐私** | 输入/输出 Guardrails + 敏感词/PII 检测 + 禁用词掩码 | 单靠词表屏蔽易被谐音、拆字或同义替换绕过，需语义审核兜底 |
| **控制篇幅与停止位置** | `max_new_tokens` + Stop 序列 + 重复惩罚 | 注意别把合法的结束符或必要结尾内容提前截断 |
| **防止话题越界与提示词注入** | System 边界隔离 + 意图/安全分类器 + 对齐拒答 | 高权限工具调用务必在后端做二次鉴权与参数校验，不能仅靠 Prompt |
