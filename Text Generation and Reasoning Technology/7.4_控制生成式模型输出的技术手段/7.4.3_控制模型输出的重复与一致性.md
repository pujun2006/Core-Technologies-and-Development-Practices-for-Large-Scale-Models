在生成式模型工程中，“控制重复”**与**“控制一致性”是一对既相关又常处于张力状态的议题：

* **减少重复（Anti-Repetition）**解决的是**单次输出内部**的复读机、句式循环、词汇枯竭与同义车轱辘话；
* **提升一致性（Consistency）**则涵盖三个层面：**跨次运行的可复现/结果一致**、**多步推理/长文本内部的逻辑与事实自洽**，以及**跨轮对话/多请求之间的风格、口径与规则统一**。

### 一、 控制单次输出内的“重复”

单次生成中的重复通常表现为：高频词或短语反复出现、连续子串/句式死循环，或者换个说法重复同一层意思。

#### 1. 解码与采样层去重

* **重复惩罚（`repetition_penalty`）**：对已出现 Token 的 Logit 施加以惩罚（通常系数大于 1 时压低已见词概率），适合缓解跨段落的词频复读。需注意过高会导致用词生僻、句式僵硬。
* **N-gram 防重（`no_repeat_ngram_size`）**：禁止长度为 $N$ 的连续 Token 序列再次出现。中文任务中通常建议从 `3` 或 `4` 起步，过小容易误伤常见短语或固定搭配。
* **Presence / Frequency Penalty（存在惩罚与频次惩罚）**：在许多推理接口中，存在惩罚对“只要出现过就扣分”一视同仁，频次惩罚则随出现次数线性/累计加重惩罚，适合调节词汇发散度。
* **温度与核采样协同（`temperature` + `top_p`）**：在极低温度下模型容易陷入贪心循环；适度提高温度或结合 `top_p` 截断长尾噪声，有助于跳出局部死循环，但需防止过度发散导致跑题。

#### 2. 语义级去重与循环熔断

* **语义重复抑制**：字面不重复但意思反复念叨（如把同一结论改写三遍），单靠 Token 级惩罚难以根治，通常需要在 System Prompt 中明确“不要重复已陈述的要点/结论，合并同类项”，或在后处理阶段做句子级相似度去重。
* **循环检测与提前终止**：在流式或分步生成中，若检测到连续多步输出高度相似或陷入固定状态机循环，可直接触发停止条件或退回上一有效状态。

### 二、 控制跨次生成的“一致性”（可复现性与口径稳定）

当同一输入被多次调用，或同类业务请求并发到达时，需要决定“每次是尽量一样，还是合理多样但结论统一”。

#### 1. 追求“确定性与可复现”

* **低温度或贪心解码**：将 `temperature` 设为 `0.0`（或关闭采样 `do_sample=False`），使模型在每一步优先选择高概率路径。
* **固定随机种子与推理环境对齐**：开启采样时固定 `seed`；在生产推理中还需注意批处理大小、连续批处理调度与部分非确定性算子可能带来的微小浮点差异。

#### 2. 追求“多路径探索但最终结论一致”：Self-Consistency（自洽投票）

* 在数学推理、逻辑判断、代码生成或复杂决策中，单次贪心路径容易在某一步走偏。
* 常见做法是**适度放开采样**（如中等温度 + `top_p`）生成 $N$ 条独立的推理路径，提取每条路径的最终答案或关键判定，再通过**多数投票（Majority Voting）或打分器聚合**选出最一致的结果。这既利用了采样的多样性，又把最终输出收束到高共识答案上。

#### 3. 跨请求/跨轮次的“风格、规则与知识一致”

* **统一 System Prompt 与结构化 Schema**：把角色设定、术语表、输出格式与拒答规则固化在统一模板中，避免不同业务入口各自拼写提示词导致口径分裂。
* **RAG 知识库与状态记忆锚定**：动态事实依赖统一检索源与版本号，多轮对话中显式维护“已确认约束/状态摘要”，防止模型随着上下文变长而“忘掉”前文约定。

### 三、 控制长文本与多步任务中的“内部自洽”

长输出或复杂任务最容易出现“前面说 A、后面说 B、总结又变成 C”的内部矛盾。

* **先规划/列纲要，再展开正文**：让模型先输出结构化要点、状态变量或推理步骤，再按要点逐段填充，能显著减少前后跳跃与自相矛盾。
* **关键状态显式追踪（State Tracking）**：在多步执行、长文档改写或角色/设定延续中，每一步显式更新并回传核心状态（如当前条件、已做修改、剩余任务），而不是完全依赖隐式注意力记忆。
* **自检与回填校验（Self-Check / Critic）**：生成后增加轻量校验步骤，专门检查“前后数字/结论是否冲突”“是否违反前置约束”“是否遗漏必填项”，发现矛盾则局部重写。

### 四、 常见冲突与工程权衡

| 维度 | 常见冲突 | 工程处理建议 |
| --- | --- | --- |
| **去重 vs 结构化格式** | 开启强 `repetition_penalty` 或 `no_repeat_ngram_size` 会破坏 JSON 括号、引号、代码缩进或固定模板字段 | 生成 JSON、代码、表格、SQL 时关闭或大幅减弱防重参数，改用结构化约束解码与校验器 |
| **去重 vs 语义连贯** | 惩罚过重会导致模型被迫找生僻词、绕远路，反而破坏流畅度 | 适度设置参数（如 `repetition_penalty` 在 `1.05` ~ `1.25` 区间起步），结合人工/自动样本集观察 |
| **一致性 vs 多样性** | 强求每次完全一致会让创意与表达变僵硬；过度追求多样会让事实与结论漂移 | 按任务分流：抽取/计算/分类走高一致性；文案/发散走可控采样，必要时用多采样 + 择优/投票 |
| **长上下文自洽** | 上下文过长或信息堆砌会导致注意力分散，前后设定不一致 | 精简无关上下文，把硬性约束放在清晰边界内，必要时采用分段摘要 + 状态回传 |
