Controlling Repetition and Consistency in Model Outputs.py代码聚焦于自回归生成中的**重复控制（Repetition Control）**，通过 Hugging Face `transformers` 的 `repetition_penalty`（重复惩罚）与 `no_repeat_ngram_size`（禁止 N-gram 重复）两项解码策略，防止中文 GPT-2 在连续生成中出现“复读机”、同义词组反复出现或句式僵化循环。

下面按核心参数机制、代码结构与运行实验设计进行详细说明：

---

### 一、 核心参数机制解析

#### 1. `repetition_penalty`（重复惩罚系数）

```python
repetition_penalty=repetition_penalty

```

* **作用机制**：在每一步解码时，检查当前序列中**已经出现过**的 Token（甚至部分实现会结合上下文历史），对这些 Token 对应的 Logit 施加惩罚缩放：
* 当 `repetition_penalty > 1.0` 时，已出现 Token 的得分会被削弱（正 Logit 除以惩罚系数，负 Logit 乘以惩罚系数，具体实现依 `transformers` 的 `RepetitionPenaltyLogitsProcessor` 而定），从而降低它们再次被选中的概率。
* 当 `repetition_penalty == 1.0` 时，表示不施加重复惩罚。


* **效果特征**：属于**软性概率抑制**。系数越高，模型越倾向于换用新词、新表达；但若设置过高（例如 `1.5` 以上），可能迫使模型放弃合理的常用词或关联词，导致用词生僻、句式别扭。

#### 2. `no_repeat_ngram_size`（N-gram 防重窗口）

```python
no_repeat_ngram_size=no_repeat_ngram_size

```

* **作用机制**：在 `transformers` 的 `NoRepeatNGramLogitsProcessor` 控制下，强制保证生成序列中**任意长度为 $N$ 的连续 Token 片段（N-gram）不会重复出现**。具体来说，当前已生成序列末尾的 $(N-1)$ 个 Token 构成前缀时，若拼接某个候选 Token 会形成历史上已出现过的 $N$-gram，该候选 Token 的概率会被直接屏蔽（Logit 置为负无穷）。
* **为什么注释建议至少设为 `3`？**
* 对于中文分词或字符级/子词级 Token 而言，设为 `1` 会禁止单个字/Token 重复，极易破坏正常中文表达；设为 `2` 在中文里也经常误伤常见双字词或高频搭配（如“可以”“进行”“智能”等在不同语境下的合理复用）。
* 设为 `3` 或 `4` 能在抑制短语/句段复读与保留正常词汇复用之间取得更合理的平衡。

* **默认参数组合**：`repetition_penalty=1.2`、`no_repeat_ngram_size=3`、`temperature=0.7`、`max_new_tokens=80`、`do_sample=True`。这是一组偏稳健的经验起点：既保留了一定的采样多样性，又用双重手段压制循环复读。

* 同样使用了 `with torch.no_grad():` 关闭梯度以节省显存并提升推理速度。

```python
ngrams = [3, 4]

for penalty in penalties:
    for ngram_size in ngrams:

```

* `penalty=1.3, ngram=4`：对重复短语和重复用词的压制更强，文本词汇发散度更高；但在 `max_new_tokens=80` 的较短篇幅内，有时会让结尾转折略显跳跃。

### 四、 工程使用中的注意事项

* **两者的互补与冲突**：
* `no_repeat_ngram_size` 是**硬性局部去重**（只管连续 $N$ 个 Token 不重复），但无法阻止语义相近的改写重复，也无法阻止跨度更长、中间夹杂其他词的循环。
* `repetition_penalty` 是**全局软性降权**，能抑制跨段落的词频复读，但过度调大容易损伤连贯性。实际调优时建议两者适度搭配，而非把单一参数推到极端。


* **特殊格式与结构化输出慎用强防重**：
* 如果生成的是 **JSON、代码、表格、列表或固定模板**，强行开启 `no_repeat_ngram_size` 或过高的 `repetition_penalty` 可能会破坏重复出现的括号、引号、缩进或固定关键字，导致语法报错。这类场景通常应关闭或大幅调低重复控制。


* **随机性控制**：由于 `do_sample=True`，多次运行同一组参数仍会有采样波动；做精细参数对比时，建议固定随机种子或对同一组参数做多次采样观察平均表现。
