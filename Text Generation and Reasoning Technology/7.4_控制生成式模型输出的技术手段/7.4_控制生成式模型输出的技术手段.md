控制生成式模型（尤其是大语言模型，LLM）的输出，本质上是在**概率分布与生成路径**上施加干预，使其在**格式合规、事实准确、风格一致、安全可靠**之间取得平衡。按介入的生命周期阶段，可将主流技术手段划分为**训练与对齐阶段**、**上下文与检索阶段**、**解码与采样阶段**以及**后处理与护栏阶段**。

### 一、 训练与对齐阶段：重塑参数先验与偏好

这类方法通过修改模型权重或优化目标，从底层改变模型“倾向于生成什么”。

* **监督微调（SFT）**：使用高质量的 `(指令, 目标输出)` 数据对训练模型，使其学会遵循特定任务指令、格式规范或领域表达习惯。在工程实践中，常结合 LoRA / QLoRA 等参数高效微调方法降低算力成本。
* **偏好对齐（Preference Alignment）**：
* **RLHF（基于人类反馈的强化学习）**：先训练奖励模型（RM）对输出打分，再用 PPO 等强化学习算法优化策略模型，兼顾有用性、诚实性与安全性。
* **DPO / ORPO / KTO**：绕过显式奖励模型或简化强化学习流程，直接利用偏好对 `(优选回答, 劣选回答)` 或二元反馈优化策略概率，训练更稳定、开销更低。


* **负向与安全对齐 / 反对齐防御**：通过拒答样本、红队对抗样本与对齐微调，抑制有害、违规或越狱诱导输出，同时防范第三方微调带来的安全回退。

---

### 二、 上下文与检索阶段：动态注入边界与知识

在不更新模型权重的前提下，通过输入侧的上下文编排引导模型关注正确信息与边界。

* **系统提示词（System Prompt）与约束工程**：明确角色定位、任务边界、输出格式、长度限制与禁用词/禁止行为。关键经验是**约束具体化、避免相互冲突**，并在复杂任务中采用“目标—边界—验收标准”分层描述。
* **少样本提示（Few-shot / In-Context Learning）**：在上下文中提供高质量输入-输出示例，利用上下文学习效应锚定输出风格、推理步骤或解析格式。
* **检索增强生成（RAG）与上下文锚定**：在推理前从外部知识库或向量索引中召回相关片段拼入上下文，并要求模型“仅依据给定上下文作答/引用来源”，从而降低参数记忆幻觉、提升事实可控性。
* **工具调用（Function Calling / Tool Use）与结构化 Schema 声明**：通过定义外部工具接口与参数 Schema，将计算、查询、执行等确定性操作交由外部系统完成，减少模型瞎猜。

### 三、 解码与采样阶段：精确干预 Token 选择

自回归模型在每一步都会输出词表上的 Logits 概率分布；解码阶段直接决定“挑哪个 Token”。

* **基础采样与搜索策略**：
* **贪心搜索（Greedy Search）与束搜索（Beam Search）**：追求高概率或全局高分路径，适合确定性较高的任务，但易出现重复或死板。
* **Temperature（温度）缩放**：调节 Logits 分布的平滑度；低温使分布更尖锐、输出更保守确定，高温增加随机性与创造性。
* **Top-k 与 Top-p（核采样）**：截断低概率长尾 Token，仅在候选集合中采样，在多样性与连贯性之间折中。
* **重复惩罚（Repetition / Presence / Frequency Penalty）**：对已出现 Token 或高频 Token 施加惩罚，缓解循环复读。


* **约束解码（Constrained Decoding / 结构化输出）**：
* 核心原理是在每一步生成前，根据正则表达式、有限状态机（FSM / FSA）或上下文无关文法（CFG）计算“合法 Token 掩码（Mask）”，将不合规 Token 的概率置零后再采样或选最大。
* 广泛用于强制生成合法的 **JSON、XML、SQL、代码或特定枚举值**，可将语法/结构合规率提升至接近 100%，但过度僵化的格式约束有时会影响语义自然度或推理质量。


* **引导式 / 对比式解码（Guidance / Contrastive Decoding）**：利用对比模型、引导模型或特定打分器在解码时动态调整 Logits 或替换关键位置预测，实现无需重训的风格或安全对齐。

### 四、 后处理与护栏阶段：输出校验与闭环修正

在模型生成完整响应或流式片段后，通过外部规则与模型进行拦截、校验与修复。

* **安全与合规护栏（Guardrails）**：使用独立的分类器、关键词/正则规则或专用审核模型对输出进行敏感词、隐私泄露、偏见与安全风险检测，触发时执行拦截、脱敏或标准拒答。
* **格式校验与自动修复**：对 JSON/代码/表格进行解析校验；若解析失败或字段缺失，触发自动重试、局部修正或降级兜底逻辑。
* **后编辑 / 精炼模型（Post-hoc Refinement / Aligner）**：引入独立修正模块或反思（Self-Reflection / Critique）步骤，对初稿进行事实核查、语气润色或残差纠偏。

### 五、 核心手段对比与选型建议

| 控制维度 | 代表技术 | 优势 | 主要局限 | 适用场景 |
| --- | --- | --- | --- | --- |
| **参数对齐** | SFT, RLHF, DPO, ORPO | 行为内化程度高，不占推理上下文 | 训练成本高，迭代周期长，可能削弱泛化 | 通用助手、垂域风格与安全底座 |
| **上下文引导** | System Prompt, Few-shot, RAG | 灵活即时，无需改权重，可动态更新知识 | 受上下文窗口与注意力衰减限制，存在被绕过风险 | 知识问答、业务规则约束、多轮任务编排 |
| **解码约束** | Grammar/FSM 掩码、采样参数 | 格式/语法保证极强，推理时直接生效 | 需访问 Logits/词表（部分闭源 API 受限），可能影响流畅度 | JSON/API 抽取、SQL/代码生成、严格格式输出 |
| **外部护栏** | 审核模型、规则校验、后置重写 | 独立于主模型，可叠加多层兜底防线 | 增加额外延迟与系统复杂度，可能误杀合理输出 | 高合规/高安全要求业务、生产级系统兜底 |

在生产系统中，通常采用**分层组合策略**：底座靠 **SFT + 偏好对齐** 奠定规范与安全底线，业务层用 **Prompt + RAG + 工具调用** 提供上下文与事实依据，结构化出口配合 **约束解码** 保证格式，最后用 **护栏与校验器** 做最终把关。
