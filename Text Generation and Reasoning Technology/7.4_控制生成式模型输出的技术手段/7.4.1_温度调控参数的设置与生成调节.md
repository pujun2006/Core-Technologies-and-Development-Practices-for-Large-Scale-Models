**温度参数（Temperature，T）**是自回归生成式模型解码阶段最核心的连续调节超参数之一。它通过缩放模型输出的原始未归一化得分（**Logits**）再经过 Softmax 映射为词表概率分布，从而直接控制输出结果的**确定性、多样性、流畅度与幻觉风险**。

### 一、 数学原理与分布变化机制

设模型在当前解码步对词表中第 $i$ 个候选 Token 输出的 Logit 为 $z_i$，温度系数为 $T > 0$，则该 Token 的采样概率为：

$$P_i(T) = \frac{\exp(z_i / T)}{\sum_{j} \exp(z_j / T)}$$

温度对概率分布的塑形作用具有明确的数学规律：

* **相对排序不变性**：由于 $\exp(\cdot)$ 是严格单调递增函数，除以 $T$ 不会改变候选 Token 的大小顺序，但会改变**分差放大/缩小程度**。
* **$T \to 0^+$（低温 / 趋近贪心）**：z_i / T 的差值被急剧放大，概率质量高度集中在最高 Logit 的 Token 上（退化为 **Greedy Search**），输出高度一致、可复现，但容易陷入套话或循环。
* **$T = 1.0$（标准温度）**：直接按模型原始 Logits 分布进行 Softmax 归一化，保留训练/对齐阶段形成的自然概率结构。
* **$T > 1.0$（高温 / 分布扁平化）**：z_i / T 的差值被压缩，低概率长尾 Token 的相对概率上升，分布更平坦；创意和词汇变化更丰富，但语法错误、跑题或事实胡编（幻觉）的概率也随之升高。

### 二、 常见温度区间设置与场景映射

不同任务对“准确性”与“发散性”的要求差异很大，实际工程中通常按任务类型设定温度区间（常见取值范围为 `0.0` 到 `1.5` 之间，极少无脑拉到 `2.0` 以上）：

| 温度区间 | 分布特征 | 典型应用场景 | 调节重点与风险提示 |
| --- | --- | --- | --- |
| **`0.0` ~ `0.2**` | 极高确定性，几乎只选最高分路径 | 代码生成、SQL 编写、JSON/结构化抽取、数学/逻辑推导、分类与标签 | 适合追求可复现与严格规则的任务；但部分推理/编程模型在极低温度下也可能出现局部死循环，需配合停止词或重复惩罚。 |
| **`0.3` ~ `0.7**` | 稳健平衡，兼顾准确性与自然表达 | RAG 问答、摘要总结、企业客服、技术文档改写、多轮业务对话 | **生产默认甜点区**。既能较好锚定上下文与事实，又不至于让句式显得过于生硬死板。 |
| **`0.8` ~ `1.2**` | 探索性增强，长尾词与新表达增多 | 头脑风暴、营销文案、故事创作、角色扮演、多样化候选生成 | 适合需要发散思维或生成多个不同风格草稿的场景；需警惕事实性幻觉上升，不建议直接用于高可信问答。 |
| **`> 1.2`（如 `1.3` ~ `1.8`）** | 分布高度平滑，噪声与随机性显著 | 实验性创意探索、抽象诗歌/艺术联想、风格极限测试 | 极易出现语义断裂、词不达意或乱码式拼凑，线上业务通常需谨慎限制或搭配严格采样截断。 |

> **工程提示**：不同模型家族对同一温度值的敏感度并不完全相同。经过 RLHF / DPO 强对齐后分布本身较尖锐的模型，即使在 `0.7` 附近也可能比较稳健；而部分推理模型或特定底座模型，官方推荐参数可能与通用对话模型不同，上线前应以实际评测集为准。

### 三、 与其他解码参数的协同调节

在真实推理配置中，温度很少孤立使用，通常与 **Top-p**、**Top-k** 以及**重复惩罚**协同生效：

1. **Temperature 与 Top-p（核采样）的配合**：
* 常见做法是**只调其中一个**，或设定合理的默认值（例如 `temperature = 0.7, top_p = 0.9` 或 `0.95`）。
* **Top-p** 先按累积概率截断掉最不可能的长尾 Token，再在剩余候选集内按温度缩放后的概率采样。当温度较高时，保留 Top-p（如 `0.9`）可以挡住极端荒谬的离谱词汇，避免“彻底放飞”。


2. **Temperature 与 Repetition / Frequency Penalty**：
* 低温（如 `0.0` ~ `0.2`）下模型容易重复同一短语或句式，适度增加重复惩罚有助于打破循环；
* 高温下若惩罚过重，则可能逼迫模型放弃自然高频词而强行选用生僻词，导致表达别扭。


3. **Temperature 与结构化输出 / 工具调用**：
* 当使用 JSON Schema、函数调用（Tool Calling）或语法约束解码时，建议将温度设在较低水平（如 `0.0` ~ `0.3`），以降低参数填错、枚举选错或推理跳步的概率。

### 四、 生产环境中的生成调节实践

* **按路由分流而非一刀切**：将同一应用内的请求按意图拆分为“事实/执行类”与“创作/发散类”，分别绑定不同的温度配置，而不是全站使用单一固定值。
* **多样本采样 + 择优（Best-of-N / 投票）**：在需要高准确率或高质量创意时，可用中高温度采样生成 $N$ 条候选，再通过打分器、规则校验、执行验证（如跑通代码/校验 JSON）或多数投票选出最佳结果。
* **可复现性考量**：即便设置 `temperature = 0`，在分布式推理、不同 Batch 大小、动态批处理（Continuous Batching）或浮点非结合性算子下，不同批次之间仍可能出现微小数值差异；若需要严格确定性，还需关注推理引擎的确定性设置与固定 Seed。
* **用指标驱动调优**：不要凭感觉盲调温度。针对具体业务建立评估集，对比不同温度下的**格式合规率、事实准确率/幻觉率、任务完成率与多样性指标**，找到帕累托最优值。
