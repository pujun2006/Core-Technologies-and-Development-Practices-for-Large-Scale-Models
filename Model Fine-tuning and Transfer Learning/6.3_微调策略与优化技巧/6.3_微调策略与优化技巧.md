大模型（LLM）微调的本质，是在**基座模型的通用语言/推理先验**之上，通过有针对性的训练阶段与参数更新策略，重塑其**指令遵循、领域语义、输出结构与偏好对齐**能力。由于大模型参数规模庞大、训练开销高，实际落地往往依赖“分阶段策略 + 参数高效微调 + 系统与数据优化技巧”的组合拳。

---

## 一、 大模型微调的核心阶段策略

现代 LLM 后训练（Post-Training）通常按顺序或按需组合以下几个阶段：

### 1. 领域持续预训练（CPT, Continual Pre-Training）

* **适用场景**：目标领域术语密集、专业语境独特（如医疗、法律、金融、代码或特定垂直业务），基座模型预训练覆盖不足。
* **做法**：使用大量领域无监督/弱监督文本继续做下一个词预测（Next-Token Prediction），适当混入通用语料防止通用能力退化，学习率通常低于常规微调。

### 2. 监督微调（SFT, Supervised Fine-Tuning）

* **适用场景**：让模型学会响应指令、遵循特定输出格式（如 JSON/表格/思维链）或掌握特定任务范式。
* **做法**：使用高质量的 `(Instruction / Prompt, Response)` 样本对进行训练。**关键工程细节**：在计算交叉熵损失时，通常只对 `Response` 部分计算 Loss，而将 `Prompt / System` 部分的 `labels` 设为 `-100`（忽略损失），避免模型去死记硬背指令模板。

### 3. 偏好对齐（Preference Alignment：DPO / RLHF / GRPO 等）

在 SFT 之后，进一步让模型输出更符合人类偏好、事实可靠性、风格要求或推理质量：

* **RLHF（如 PPO）**：先基于偏好对 `(chosen, rejected)` 训练奖励模型（Reward Model, RM），再通过强化学习优化策略模型（Policy Model），效果上限高但链路长、显存与调参成本大。
* **DPO（Direct Preference Optimization）**：跳过显式训练独立的奖励模型与在线 RL 采样，直接利用偏好对在隐式奖励目标下优化策略模型，训练更稳定、实现更简洁，已成为通用对齐的主流方案之一。
* **可验证奖励 / 推理强化学习（如 GRPO 类思路）**：在数学、代码、逻辑推理等可自动判分或可验证的任务中，通过组内相对奖励优化推理路径与最终答案。

## 二、 参数更新策略：全量微调 vs. PEFT

| 策略类型 | 核心机制 | 显存与算力开销 | 适用场景 |
| --- | --- | --- | --- |
| **全量微调（FFT）** | 更新全部模型参数 | 极高（需存权重、梯度、优化器状态、激活值与 KV 缓存） | 数据充足、领域/任务跨度大、单任务追求极致上限 |
| **LoRA** | 冻结原权重 $W_0$，在旁路训练低秩矩阵 $A, B$ | 低至中；推理可将权重合并回主干，零额外延迟 | 最主流的大模型微调方案，便于多任务/多业务切换 |
| **QLoRA** | 基座以 4-bit（如 NF4）量化加载 + 双量化 + 分页优化器，训练 LoRA 权重 | 低（单卡可微调更大规模模型） | 显存受限下的大模型 SFT / DPO 适配 |
| **DoRA / rsLoRA 等变体** | 拆分权重幅度与方向，或按秩调整缩放因子 | 低至中 | 希望进一步逼近全量微调表现或提升高秩稳定性 |

### LoRA 关键超参数直觉

* **目标模块（`target_modules`）**：早期常只加在 `q_proj, v_proj`，现代实践更推荐覆盖所有线性层（如 `q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj, down_proj`），通常能获得更稳健的适配效果。
* **秩 $r$ 与缩放 $\alpha$**：常见 $r \in [8, 64]$（简单格式/风格任务可用较小 $r$，复杂领域/知识注入可适当调大 $r$）；缩放比例常由 $\alpha / r$ 控制。

## 三、 数据与训练优化技巧

在大模型微调中，**数据质量与训练稳定性**往往比单纯调参更决定最终效果：

### 1. 数据层面的高杠杆优化

* **宁缺毋滥，质量优先**：去重（精确去重与语义/MinHash 去重）、清洗乱码/模板污染/低质废话、剔除矛盾或错误标注。几千条高质量、覆盖多样边界场景的 SFT 数据，常胜过数万条同质化或噪声数据。
* **任务配比与难度分布**：多任务混合微调时，合理控制各任务样本比例，避免高频简单任务淹没低频核心任务；适当包含拒绝回答/边界样本，减少幻觉与越界输出。
* **样本打包（Packing）**：对长度差异较大的短序列进行拼接打包（注意在注意力掩码/位置编码上做好样本边界隔离），可显著提升 GPU 利用率与吞吐。

### 2. 训练稳定性与防遗忘技巧

* **学习率与调度器**：大模型微调学习率通常较小（全量微调常见 $5\times 10^{-6} \sim 2\times 10^{-5}$，LoRA 常见 $5\times 10^{-5} \sim 2\times 10^{-4}$，随模型增大而适当调小），配合 Warmup（如占总步数 $3\% \sim 10\%$）与 Cosine 学习率衰减。
* **缓解灾难性遗忘**：
* 控制训练 Epoch（SFT 一般 $1 \sim 3$ 个 epoch，过多易过拟合并损伤泛化）；
* 在领域/任务数据中按比例混入通用指令或通用语料；
* 结合权重衰减（Weight Decay）与梯度裁剪（如 `max_norm=1.0`）。



### 3. 显存与吞吐系统优化

* **混合精度训练**：使用 `bf16`（推荐，动态范围大、不易溢出）或 `fp16` 替代 `fp32` 计算与存储。
* **梯度累积（Gradient Accumulation）**：在单步 Batch Size 受限的显存下，通过累积多个 micro-batch 的梯度再执行一次参数更新，模拟更大有效 Batch Size，使梯度估计更平稳。
* **梯度检查点（Gradient Checkpointing / Activation Checkpointing）**：牺牲少量重算时间换取大量激活值显存节省，是长上下文或大模型微调的常备手段。
* **分布式与长上下文优化**：多卡场景可结合 ZeRO（如 DeepSpeed ZeRO-2 / ZeRO-3）或 FSDP 切分优化器状态/梯度/参数，并采用 FlashAttention 等高效注意力算子降低显存与访存瓶颈。

## 四、 落地闭环建议

1. **先做基线再决定是否微调**：先验证 Prompt + Few-shot 或 **RAG** 能否满足需求；当需要固化输出结构、领域表达习惯或提升特定任务推理/判别准确率时，再引入微调。
2. **建立“任务指标 + 通用回归”双评测集**：除业务核心指标外，跟踪通用能力、格式遵循率与幻觉/拒答表现，防止“训好了单点任务、训坏了整体能力”。
3. **上线后持续迭代**：收集线上真实 Bad Case 与人工反馈，经清洗脱敏后回流至 SFT / 偏好数据集，形成可持续迭代的微调闭环。
