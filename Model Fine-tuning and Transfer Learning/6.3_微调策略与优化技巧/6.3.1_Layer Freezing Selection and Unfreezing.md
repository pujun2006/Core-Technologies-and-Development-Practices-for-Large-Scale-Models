Layer Freezing Selection and Unfreezing.py代码实现了一个**带渐进式解冻（Gradual Unfreezing）的中文文本分类训练流水线**：前半段使用内置示例数据构建动态 Padding 的 `DataLoader`；后半段以 `bert-base-chinese`（3 分类）为基础，初始冻结词嵌入层与前 6 层 Transformer Encoder（`layer[0..5]`），随后在后续 Epoch 中**从高层往浅层逐层解冻**并动态重建优化器与学习率调度器。

---

## 一、 第一部分：数据准备与动态 Padding `DataLoader`

### 1. 内置示范数据与 `CustomTextDataset`

```python
sample_data = {
    "text": [
        "自然语言处理是一门研究计算机如何理解和生成人类语言的学科。",
        "在实际应用中，文本数据通常具有不确定的长度。",
        "通过使用填充和截断技术，确保每个批次内的序列长度一致，提升模型的处理效率。",
        "深度学习在文本分类任务中取得了显著的成果。",
        "使用 PyTorch 构建端到端的 NLP 管道非常高效。",
    ],
    "label": [1, 1, 0, 1, 0],
}
df = pd.DataFrame(sample_data)

```

* **开箱即用**：直接用内存中的 `DataFrame` 替代外部 CSV 文件，5 条样本在 `batch_size=2, shuffle=True` 下每个 Epoch 会产生 `3` 个 batch（前两个 batch 各 2 条，最后一个尾批 1 条，即 `len(dataloader) == 3`）。
* **仅做截断不强行 Padding**：`CustomTextDataset.__getitem__` 调用 `self.tokenizer(text, truncation=True, max_length=self.max_length, return_tensors=None)` 返回纯 Python 列表，避免对短句做不必要的定长填充。

### 2. `DataCollatorWithPadding` 动态对齐

```python
data_collator = DataCollatorWithPadding(tokenizer=tokenizer, padding=True)

dataloader = DataLoader(
    dataset,
    batch_size=2,
    shuffle=True,
    collate_fn=data_collator,
)

```

* 在组 batch 时，自动按**当前 batch 内最长序列**补齐 `[PAD]` 并生成 `attention_mask`，减少无效计算与显存开销；随后通过一段 `break` 循环打印首个 batch 的 `input_ids`、`attention_mask` 与 `labels` 形状，快速验证数据管道是否正常。

## 二、 第二部分：渐进式解冻与动态重建优化器

### 1. 初始冻结策略（冻结 `embeddings` 与 `layer[:6]`）

```python
for param in model.bert.embeddings.parameters():
    param.requires_grad = False
for param in model.bert.encoder.layer[:6].parameters():
    param.requires_grad = False

```

* 训练开始前，词嵌入层（`embeddings`）与第 `0` 到第 `5` 层 Encoder 被冻结；第 `6` 到第 `11` 层 Encoder、`pooler` 以及 `classifier` 处于可训练状态。

### 2. 解冻索引计算与逐层放开（`unfreeze_index = 6 - epoch`）

在 `num_epochs = 3` 的循环中：

* **Epoch 1（`epoch = 0`）**：不执行解冻，训练初始可训练参数（`layer[6..11]` + `pooler` + `classifier`）。
* **Epoch 2（`epoch = 1`）**：`unfreeze_index = 6 - 1 = 5`，解冻 `model.bert.encoder.layer[5]`。
* **Epoch 3（`epoch = 2`）**：`unfreeze_index = 6 - 2 = 4`，解冻 `model.bert.encoder.layer[4]`。

这种**从索引 `5` 向 `4` 递减**的顺序，体现的是**从高层语义向浅层表征逐步解冻**的思路：先让高层与分类头适应任务，再逐步往下放开更靠近底层的 Encoder Block。

### 3. 核心修复：解冻后重建 `optimizer` 与 `scheduler`

```python
def create_optimizer_and_scheduler(model, lr, total_steps):
    trainable_params = filter(lambda p: p.requires_grad, model.parameters())
    optimizer = AdamW(trainable_params, lr=lr)
    scheduler = get_linear_schedule_with_warmup(
        optimizer, num_warmup_steps=int(total_steps * 0.1), num_training_steps=total_steps
    )
    return optimizer, scheduler

```

* **为什么必须重新生成？**
因为此前 `optimizer` 在初始化时已经把 `trainable_params` 迭代器耗尽并绑定了旧的参数列表，新把 `layer[unfreeze_index]` 的 `requires_grad` 设为 `True` 后，原优化器并不会自动纳入这些新参数；同时 `total_steps` 改用 `remaining_steps = (num_epochs - epoch) * len(dataloader)`，让后续阶段的学习率调度与剩余步数对齐。
* **Warmup 比例写法**：使用 `int(total_steps * 0.1)` 按总步数比例设定预热步数，比写死 `100` 更适配不同数据集大小。

### 4. 单步训练与梯度裁剪

```python
optimizer.zero_grad()
outputs = model(
    input_ids=input_ids, attention_mask=attention_mask, labels=labels
)
loss = outputs.loss

loss.backward()
torch.nn.utils.clip_grad_norm_(
    filter(lambda p: p.requires_grad, model.parameters()), max_norm=1.0
)

optimizer.step()
scheduler.step()

```

* 每次前向传入 `input_ids`、`attention_mask` 和 `labels` 自动计算交叉熵损失；反向传播后用 `clip_grad_norm_` 将可训练参数梯度范数裁剪至 `1.0` 以内，再更新权重与学习率。

## 四、 工程实践中的潜在细节与改进建议

1. **按比例设 Warmup 时注意下限（如至少 `1` 步）**
在当前 5 条样本、`batch_size=2` 的演示数据下，`len(dataloader) == 3`，`total_steps = 9`，`int(9 * 0.1)` 会得到 `0`（虽然 `get_linear_schedule_with_warmup` 支持 `num_warmup_steps=0`，但在正式小样本实验中若想保证预热，可写 `max(1, int(total_steps * 0.1))`）。
2. **新解冻层可考虑更保守的学习率**
当前 `create_optimizer_and_scheduler` 对新解冻层同样使用 `initial_lr`（`2e-5`）。在更深的解冻或更复杂的任务中，有时会给新解冻的层设置更小的学习率（或参数分组设置分层学习率），以减少对已收敛高层与分类头的扰动。
3. **正式训练时补充验证集与模型保存**
当前代码仅用于演示动态 Padding 与渐进式解冻机制；若用于真实业务数据集，建议切分独立的验证集（`train / val`），在每个 Epoch 结束后计算验证集准确率或 F1，并保存最优权重。
