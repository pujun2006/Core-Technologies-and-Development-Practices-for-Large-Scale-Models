Model Selection and Adaptation.py代码展示了一个典型的部分冻结微调（Partial Freeze Fine-Tuning）实践：加载中文预训练模型 `bert-base-chinese` 构建 3 分类网络，冻结词嵌入层与前 6 层 Transformer Encoder，仅保留后 6 层 Encoder、池化层（Pooler）及分类头参与梯度更新，最后统计并打印各层参数的可训练状态与比例。

---

## 一、 逐段代码详细解析

### 1. 导入依赖与加载预训练分类模型

```python
import torch
from transformers import BertForSequenceClassification

model_name = "bert-base-chinese"

# 1. 直接加载用于 3 分类任务的预训练模型
model = BertForSequenceClassification.from_pretrained(model_name, num_labels=3)
print(f"已成功加载分类模型: {model_name}\n")

```

* **`BertForSequenceClassification.from_pretrained(...)`**：在 `bert-base-chinese` 编码器基础上自动拼接了池化与分类头（`classifier`），并将输出维度设为 `num_labels=3`。
* **常见提示**：若本地未缓存权重，首次运行会从 Hugging Face Hub 下载；在网络受限或离线环境下，通常需提前下载好权重目录或配置镜像/本地路径。同时，首次加载分类模型时，由于分类头权重是随机初始化的，控制台常会出现类似 `Some weights of BertForSequenceClassification were not initialized...` 的提示，这属于正常现象。

### 2. 冻结底层参数（Embeddings + 前 6 层 Encoder）

```python
# 2. 正确冻结底层参数 (Embedding + 前 6 层 Transformer Block)
# 注意：BertForSequenceClassification 内部的 Transformer 主体叫做 model.bert
for param in model.bert.embeddings.parameters():
    param.requires_grad = False

for param in model.bert.encoder.layer[:6].parameters():
    param.requires_grad = False

```

* **模块路径正确性**：`BertForSequenceClassification` 的主干编码器属性名为 `model.bert`，而非顶层直接挂载 `embeddings` 或 `encoder`，注释中对此做了明确提醒。
* **冻结机制**：将 `param.requires_grad` 设为 `False` 后，PyTorch 在反向传播（`loss.backward()`）时不会为这些参数计算梯度；而在构建优化器时，若传入 `filter(lambda p: p.requires_grad, model.parameters())`，这些冻结参数也不会被更新，从而节省显存与计算开销。
* **层级划分逻辑**：`bert-base` 共有 12 层 Transformer Encoder（索引 `0` 到 `11`）。这里冻结 `embeddings` 与 `layer[:6]`（即第 `0~5` 层通用底层特征），保留 `layer[6:]`（第 `6~11` 层高层语义特征）以及 `model.bert.pooler` 和 `model.classifier` 进行微调。

### 3. 遍历参数统计可训练状态与比例

```python
trainable_params = 0
all_params = 0

print("=== 参数冻结状态检查 ===")
for name, param in model.named_parameters():
    all_params += param.numel()
    if param.requires_grad:
        trainable_params += param.numel()
        print(f"✅ 可训练参数 (Trainable): {name}")
    else:
        print(f"❄️ 已冻结参数 (Frozen):    {name}")

print("-" * 60)
print(f"总参数量 (Total Params): {all_params}")
print(
    f"可训练参数量 (Trainable Params): {trainable_params} ({100 * trainable_params / all_params:.2f}%)"
)

```

* **`model.named_parameters()`**：返回 `(参数名, 参数张量)` 迭代器，便于精确核对每一层权重是否按预期冻结或解冻。
* **`param.numel()`**：返回单个张量中的元素总数（标量数量），累加后得到总参数量与可训练参数量。
* **输出信息**：逐层打印 `✅` 或 `❄️` 标记，并在末尾给出可训练参数占总参数的百分比，方便在实验前快速确认微调规模。

## 二、 这种冻结策略的设计意图与适用场景

* **为什么冻住底层、放开高层？**
在 Transformer 与 CNN 等分层网络中，浅层更倾向于捕获基础词法、局部搭配或通用表征，而深层与任务头更贴近具体语义与判别边界。冻结前 6 层可以在数据量有限时减少过拟合风险，同时保留足够的高层容量适配 3 分类任务。
* **适用场景**：
* 中文文本分类、情感分析、意图识别等下游任务，数据规模中等偏小，且与通用中文语料分布较为接近。
* 显存有限，希望在不引入额外 PEFT 库（如 `peft`）的前提下，通过原生 PyTorch 冻结策略降低显存与训练耗时。

## 四、 工程实践中的潜在细节与改进建议

1. **优化器只传入可训练参数**
冻结 `requires_grad = False` 后，创建优化器时建议显式过滤参数：
```python
optimizer = torch.optim.AdamW(
    filter(lambda p: p.requires_grad, model.parameters()),
    lr=2e-5,
)

```


这样既能避免优化器为冻结参数分配不必要的状态，也更符合显式管理可训练参数的习惯。
2. **层级数量可按任务与数据量调整**
* 若下游样本极少且任务较简单，可考虑冻结更多层（如前 `8~10` 层）甚至只训分类头；
* 若领域差异较大或样本充足，可只冻结 `embeddings` 或前 `3~4` 层，甚至全量微调。


3. **补充前向推理与梯度检查**
在正式训练前，可喂入一条 dummy batch 做一次前向与反向传播，确认没有出现 `None` 梯度或维度不匹配问题，同时观察 `torch.cuda.max_memory_allocated()` 评估实际显存占用。
