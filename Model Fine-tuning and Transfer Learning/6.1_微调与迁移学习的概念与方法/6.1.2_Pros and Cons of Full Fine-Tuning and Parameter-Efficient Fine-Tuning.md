Pros and Cons of Full Fine-Tuning and Parameter-Efficient Fine-Tuning.py代码演示了在同一个 PyTorch 训练脚本中先执行一步全参数微调（Full Fine-Tuning），再动态切换为部分参数冻结微调（Partial Freeze Fine-Tuning）的完整前向、反向传播与参数更新闭环。

---

## 一、 整体执行流程概览

1. **模型与模拟数据准备**：使用 `AutoModelForSequenceClassification` 加载 `bert-base-chinese`（3 分类），并构造一条最小可运行张量（`input_ids` 与 `labels`）。
2. **第一阶段（全参数微调）**：确保所有参数的 `requires_grad = True`，将全部参数传入 `torch.optim.AdamW`，执行一次 `zero_grad -> forward -> loss.backward -> step` 更新。
3. **第二阶段（切换为部分冻结微调）**：冻结 `model.bert.embeddings` 与 `model.bert.encoder.layer[:6]`，打印各层参数状态，使用 `filter(lambda p: p.requires_grad, model.parameters())` 重新构建优化器，并执行第二次训练迭代。

---

## 二、 逐段代码详细解析

### 1. 依赖导入、模型加载与模拟输入

```python
import torch
from torch.optim import AdamW  # 推荐使用 PyTorch 原生 AdamW，避免 DeprecationWarning
from transformers import AutoModelForSequenceClassification

model_name = "bert-base-chinese"
model = AutoModelForSequenceClassification.from_pretrained(model_name, num_labels=3)

input_ids = torch.tensor([[101, 1045, 2572, 1037, 2339, 102]])
labels = torch.tensor([1])

```

* **`torch.optim.AdamW`**：直接从 `torch.optim` 导入原生实现，避免旧版本 `transformers.AdamW` 触发弃用警告（`DeprecationWarning`）。
* **`AutoModelForSequenceClassification`**：根据 `model_name` 自动识别模型架构（此处为 BERT），并在编码器顶层附加序列分类头，传入 `labels` 时前向输出会直接计算交叉熵损失 `outputs.loss`。
* **模拟张量**：`input_ids` 形状为 `(1, 6)`（`batch_size=1, seq_len=6`），`101` 和 `102` 分别对应 BERT 词表中的 `[CLS]` 和 `[SEP]`；`labels` 形状为 `(1,)`，取值为 `1`（属于 `0, 1, 2` 三个类别之一）。

### 2. 第一阶段：全参数微调迭代

```python
print("=== 1. 执行全参数微调 ===")
for param in model.parameters():
    param.requires_grad = True

optimizer = AdamW(model.parameters(), lr=2e-5)

model.train()
optimizer.zero_grad()  # 清空梯度
outputs = model(input_ids, labels=labels)
loss = outputs.loss
loss.backward()
optimizer.step()

```

* **显式开启全量梯度**：将所有参数的 `requires_grad` 设为 `True`，确保即使此前做过冻结操作，此时也处于全量可更新状态。
* **标准训练步四连击**：
1. `model.train()`：将模型切换至训练模式（启用 Dropout 等训练期行为）。
2. `optimizer.zero_grad()`：清零上一轮残留的 `.grad`，防止梯度累积污染当前步。
3. `outputs = model(input_ids, labels=labels)`：前向传播并计算分类损失。
4. `loss.backward()` 与 `optimizer.step()`：反向传播计算梯度，并按 `lr=2e-5` 更新全部参数。



### 3. 第二阶段：切换为部分参数冻结微调

```python
print("=== 2. 切换为部分参数冻结微调 ===")
for param in model.bert.embeddings.parameters():
    param.requires_grad = False
for param in model.bert.encoder.layer[:6].parameters():
    param.requires_grad = False

for name, param in model.named_parameters():
    status = "✅ 可训练" if param.requires_grad else "❄️ 已冻结"
    print(f"{name}: {status}")

optimizer = AdamW(
    filter(lambda p: p.requires_grad, model.parameters()), lr=2e-5
)

optimizer.zero_grad()  # 训练前清空上一轮梯度
outputs = model(input_ids, labels=labels)
loss = outputs.loss
loss.backward()
optimizer.step()

```

* **冻结底层权重**：将词嵌入层（`model.bert.embeddings`）和前 6 层 Transformer Encoder（`model.bert.encoder.layer[:6]`）的 `requires_grad` 设为 `False`。后续 `loss.backward()` 不会再为这些张量计算梯度。
* **重建优化器并过滤参数**：由于第一阶段创建的 `optimizer` 已经持有了全量参数组，切换到部分冻结后，必须重新实例化优化器并传入 `filter(lambda p: p.requires_grad, model.parameters())`，这样优化器只管理高层 Encoder（`layer[6:]`）、`pooler` 与 `classifier` 等可训练参数。
* **再次执行训练步**：清空梯度、前向计算损失、反向传播并更新未冻结参数。

## 四、 工程实践中的关键细节与注意事项

1. **真实训练中通常不会在单条样本上“先全量再冻结”切换**
这段代码非常适合做**梯度与参数冻结行为的单元测试/烟雾测试**。在实际训练中，更常见的做法是：
* 全程采用固定策略（全量微调或固定冻结底层）；或
* 采用**渐进式解冻（Gradual Unfreezing）**（例如先冻结主干只训分类头几个 step/epoch，再逐步解冻高层到浅层）。


2. **建议传入 `attention_mask**`
实际文本分类中，当一个 batch 内包含不同长度句子并做了 padding 时，应同时传入 `attention_mask`，避免 `[PAD]` 位置参与自注意力计算影响表示。
3. **显存释放与设备迁移**
若在 GPU 上运行，需将 `model`、`input_ids` 和 `labels` 移动到同一设备（如 `.to("cuda")`）；在较长训练循环中，建议结合 `torch.amp.autocast`（混合精度）与验证集评估，避免仅靠单条数据过拟合。
