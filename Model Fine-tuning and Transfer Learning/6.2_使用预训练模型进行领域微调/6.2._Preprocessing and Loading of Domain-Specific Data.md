Preprocessing and Loading of Domain-Specific Data.py代码构成了一个完整的**中文文本分类领域微调训练管线（Data Pipeline + Partial-Freeze Training Loop）**：前半部分负责数据清洗、分词截断与按批次动态对齐（Dynamic Padding）；后半部分负责模型加载、底层参数冻结、带 Warmup 的线性学习率调度、梯度裁剪与多轮训练监控。

---

## 一、 第一部分：数据加载与动态 Padding 管线

### 1. 数据清洗与兜底构造

```python
def load_data(file_path):
  """加载 CSV 文件，清理缺失值与首尾空格，并重置索引"""
  df = pd.read_csv(file_path)
  df = df.dropna(subset=["text", "label"])  # 明确指定关键列
  df["text"] = df["text"].astype(str).str.strip()  # 确保字符串格式并去空格
  df = df.reset_index(drop=True)  # 重置索引，防止断档
  return df

```

* **针对性清洗**：仅丢弃 `text` 或 `label` 缺失的行，避免因无关列空值误删有效样本；`astype(str).str.strip()` 统一文本类型并去除首尾空白；`reset_index(drop=True)` 保证后续按位置索引安全。
* **防报错兜底**：当 `"领域数据集.csv"` 不存在时捕获 `FileNotFoundError`，生成 3 条简短示例数据，确保脚本可直接跑通验证。

### 2. `CustomTextDataset` 与动态 Padding（`DataCollatorWithPadding`）

```python
class CustomTextDataset(Dataset):

  def __init__(self, texts, labels, tokenizer, max_length=128):
    ...

  def __getitem__(self, idx):
    ...
    inputs = self.tokenizer(
        text,
        truncation=True,
        max_length=self.max_length,
        return_tensors=None,  # 返回纯 Python 列表，方便 DataCollator 快速处理
    )
    inputs["labels"] = int(label)
    return inputs

```

* **为什么不在 `__getitem__` 里做 `padding="max_length"`？**
若对所有样本统一填充到 `max_length=128`，短句会包含大量无意义的 `[PAD]` token，白白增加注意力计算量与显存占用。
* **动态 Padding 原理**：`__getitem__` 只负责分词与长度上限截断（`max_length=128`），返回 Python 列表；`DataLoader` 传入 `DataCollatorWithPadding(tokenizer=tokenizer, padding=True)` 后，会在**每个 batch 内部**按该 batch 最长序列对齐（不超过 `max_length`），并自动生成对应的 `attention_mask` 与 `labels` 张量。

## 二、 第二部分：冻结微调与训练循环

### 1. 设备选择、模型加载与底层冻结

```python
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model = AutoModelForSequenceClassification.from_pretrained(
    model_name, num_labels=3
)

for param in model.bert.embeddings.parameters():
  param.requires_grad = False
for param in model.bert.encoder.layer[:6].parameters():
  param.requires_grad = False

model.to(device)

```

* **部分冻结策略**：冻结词嵌入层与前 6 层 Transformer Encoder，仅训练后 6 层 Encoder、池化层与分类头，在保留通用底层表征的同时减少显存与计算量。
* **参数过滤**：构建 `AdamW(filter(lambda p: p.requires_grad, model.parameters()), lr=initial_lr)` 时只纳入可训练参数，避免优化器为冻结权重维护冗余状态。

### 2. 学习率 Warmup 调度器

```python
num_epochs = 3
total_steps = num_epochs * len(dataloader)
scheduler = get_linear_schedule_with_warmup(
    optimizer, num_warmup_steps=100, num_training_steps=total_steps
)

```

* **作用机制**：`get_linear_schedule_with_warmup` 在前 `num_warmup_steps` 步将学习率从 `0` 线性爬升至 `initial_lr`（`2e-5`），帮助稳定微调初期的梯度更新；之后再线性衰减至 `0`，有助于收敛到更平稳的最优解。

### 3. 单步训练与梯度裁剪

```python
optimizer.zero_grad()
outputs = model(
    input_ids=input_ids, attention_mask=attention_mask, labels=labels
)
loss = outputs.loss
loss.backward()

torch.nn.utils.clip_grad_norm_(
    filter(lambda p: p.requires_grad, model.parameters()), max_norm=1.0
)

optimizer.step()
scheduler.step()

```

* **内建 Loss**：向 `AutoModelForSequenceClassification` 传入 `labels` 后，模型自动计算交叉熵损失并返回 `outputs.loss`。
* **梯度裁剪（`clip_grad_norm_`）**：将所有可训练参数梯度的全局 $L_2$ 范数限制在 `max_norm=1.0` 以内，抑制微调阶段偶尔出现的梯度尖峰或爆炸。
* **更新顺序**：通常在 `optimizer.step()` 之后调用 `scheduler.step()`，最后统计每个 epoch 的平均 `loss` 与当前学习率。

## 四、 实操中的潜在注意点

1. **小数据集下的 `num_warmup_steps=100**`
当数据集很小（例如 `len(dataloader)` 较小，`total_steps` 甚至不足 `100`）时，固定设 `num_warmup_steps=100` 会让整个训练过程都处于预热爬升阶段，无法充分衰减。实际项目中常按总步数比例设置（如 `int(0.06 * total_steps)` 或 `int(0.1 * total_steps)`）。
2. **标签取值范围与类型**
`num_labels=3` 要求 `labels` 的合法取值为 `0, 1, 2`；若原始 CSV 中存在越界标签或负值，交叉熵损失计算会抛出运行时错误，建议加载后做一次标签合法性校验。
3. **补充验证集与模型保存**
当前循环仅输出训练集平均 `loss`；正式训练领域分类模型时，建议划分独立的 `val` 集并在每个 epoch 结束时评估准确率/F1，保存最佳 checkpoint。
