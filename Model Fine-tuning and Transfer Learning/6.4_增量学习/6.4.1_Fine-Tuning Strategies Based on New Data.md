Fine-Tuning Strategies Based on New Data.py代码实现了一个**双数据加载器（Dual-DataLoader）并行采样的增量训练循环**：将历史旧数据与新增量数据拆分为独立的 `DataLoader` 并各自按批次动态 Padding，在每个训练步中同时取一个旧 Batch 和一个新 Batch 分别计算交叉熵损失，再通过超参数 `alpha` 进行加权混合与反向传播更新。

---

## 一、 整体工作流概览

1. **模型与分词器准备**：加载 `bert-base-chinese` 3 分类模型与分词器，构造旧样本（3 条）与新样本（2 条）。
2. **双数据集与动态 Padding 加载器**：分别为旧数据和新数据创建 `CustomTextDataset` 与 `DataLoader`（`batch_size=2`），在 `collate_fn` 中按各自 batch 内最长序列动态填充。
3. **循环迭代与独立 Loss 混合**：在每个 Epoch 中遍历 `old_dataloader`（共 `2` 个 batch），通过 `itertools.cycle(new_dataloader)` 无限循环抽取 `new_dataloader` 的 batch，分别计算 `old_loss` 与 `new_loss`，按 `loss = alpha * new_loss + (1 - alpha) * old_loss` 合并后执行梯度裁剪与 `AdamW` 更新。

---

## 二、 逐段代码详细解析

### 1. 独立封装 `old_dataloader` 与 `new_dataloader`

```python
old_dataset = CustomTextDataset(old_texts, old_labels)
new_dataset = CustomTextDataset(new_texts, new_labels)

old_dataloader = DataLoader(
    old_dataset, batch_size=2, shuffle=True, collate_fn=collate_fn
)
new_dataloader = DataLoader(
    new_dataset, batch_size=2, shuffle=True, collate_fn=collate_fn
)

```

* **为什么要拆成两个 `DataLoader`？**
相比于把新旧样本拼在一起混洗，分开构建 `DataLoader` 可以显式控制**每个训练步中必须同时包含旧分布与新分布的样本**，也方便针对新旧数据设置不同的 batch size、采样方式或分别统计/加权它们的损失。
* **Batch 数量说明**：当前示例中 `old_texts` 有 3 条、`batch_size=2`，因此 `len(old_dataloader) == 2`（一个含 2 条，一个含 1 条）；`new_texts` 有 2 条、`batch_size=2`，因此 `len(new_dataloader) == 1`。

### 2. `itertools.cycle` 解决长短数据集步数不对齐

```python
alpha = 0.5  # 新旧 Loss 的平衡权重

for epoch in range(num_epochs):
  model.train()
  total_loss = 0.0

  steps_per_epoch = len(old_dataloader)
  new_dataloader_iter = itertools.cycle(new_dataloader)

  for old_batch in old_dataloader:
    new_batch = next(new_dataloader_iter)

```

* **核心作用**：当两个数据集大小不同时，若直接 `zip(old_dataloader, new_dataloader)`，迭代次数会受限于较短的一方，导致较长的数据集在一个 Epoch 内无法遍历完。
* **此处逻辑**：代码以 `old_dataloader` 为主循环（`steps_per_epoch = len(old_dataloader)`），并用 `itertools.cycle(new_dataloader)` 让较短的 `new_dataloader` 在遍历完后自动从头循环提供 batch。
* **注意方向假设**：注释提到“如果旧数据较多，以 `old_dataloader` 为主主导循环”；若实际业务中**新数据 batch 数多于旧数据**，则需要反过来以 `new_dataloader` 为主循环并用 `cycle(old_dataloader)`，否则新数据在一个 Epoch 内会被截断。

### 3. 分别计算 Loss 并按 `alpha` 加权混合

```python
    optimizer.zero_grad()

    # ✅ 核心优化 2：分别计算 Loss，保持逻辑独立
    old_loss = F.cross_entropy(
        model(old_ids, attention_mask=old_mask).logits, old_lbls
    )
    new_loss = F.cross_entropy(
        model(new_ids, attention_mask=new_mask).logits, new_lbls
    )

    # 混合 Loss
    loss = alpha * new_loss + (1 - alpha) * old_loss

    loss.backward()
    torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
    optimizer.step()

```

* **独立计算 `old_loss` 与 `new_loss**`：调用 `model(...).logits` 拿到未归一化的分类得分后，使用 `F.cross_entropy` 分别计算两个 batch 的平均交叉熵损失。这样做的好处是：
1. 后续若想给 `old_loss` 加上蒸馏损失（KD loss）或单独记录 `new_loss` / `old_loss` 曲线，结构非常清晰；
2. 两个前向传播的计算图会一并接入 `loss.backward()`，梯度在参数空间中自然叠加。


* **`alpha` 的权重含义**：`alpha = 0.5` 表示新旧损失各占一半权重；增大 `alpha` 更偏向新数据收敛，减小 `alpha` 更侧重保留旧数据表现。
* **梯度裁剪**：`clip_grad_norm_(model.parameters(), max_norm=1.0)` 在 `loss.backward()` 之后、`optimizer.step()` 之前执行，限制全局梯度范数上限，防止双 batch 梯度叠加引起震荡。

## 四、 工程实践中的潜在注意点

1. **主循环主导方的选择**
建议根据实际 batch 数量动态选择主循环（例如谁的 `len(dataloader)` 更大就以谁为主循环，另一方用 `itertools.cycle`），这样既能保证数据量较大的一方完整过完一个 Epoch，又能让数据量较小的一方在步数上得到充分复用。
2. **尾批（Last Batch）样本数不同带来的 Loss 尺度差异**
`F.cross_entropy` 默认按 batch 样本数做均值（`reduction="mean"`）。当某个 batch 只有 1 条样本时，其单步 loss 的方差通常大于满 batch，在数据量较大且尾批占比很小时影响有限；若数据集很小，尾批波动会更明显。
3. **显存占用与训练速度**
每个训练 step 需要执行**两次** BERT 前向传播（`old_batch` 与 `new_batch`），因此单步计算量和激活值显存开销约为单 batch 训练的两倍。在较大数据集或 GPU 显存紧张时，可结合混合精度（`torch.amp.autocast`）或调整 `batch_size` 控制显存。
