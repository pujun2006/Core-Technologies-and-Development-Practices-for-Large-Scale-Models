Preserving Original Model Performance with Regularization and Constraint Techniques.py代码实现了一个**结合双数据加载器回放与参数空间锚定正则化（Weight-Space L2 Anchor）的增量微调训练循环**：在每个训练步中同时采样历史旧数据与新增量数据计算交叉熵损失，并加入当前权重相对于微调前初始快照的平方 $L_2$ 偏差惩罚项，以在吸收新样本的同时抑制参数过度漂移与旧知识遗忘。

---

## 一、 整体工作流概览

1. **模型与双路数据管道**：加载 `bert-base-chinese` 3 分类模型与分词器，分别为 `old_texts`（3 条）和 `new_texts`（2 条）构建 `CustomTextDataset` 与动态 Padding 的 `DataLoader`（`batch_size=2`）。
2. **保存初始参数快照**：模型迁移至目标 `device` 后，克隆并分离（`.clone().detach().to(device)`）可训练参数的初始值存入 `initial_params`，作为后续参数偏移约束的参考锚点。
3. **联合损失与约束优化**：在每个 Epoch 中以 `old_dataloader` 为主循环、用 `itertools.cycle(new_dataloader)` 循环补齐新数据 batch；分别计算 `old_loss` 与 `new_loss`，再累加参数相对 `initial_params` 的偏差正则项 `constraint_loss`，经梯度裁剪与 `AdamW` 更新权重。

---

## 二、 逐段代码详细解析

### 1. 模型、双路数据集与 `collate_fn`

```python
model_name = "bert-base-chinese"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForSequenceClassification.from_pretrained(
    model_name, num_labels=3
)
...
old_dataloader = DataLoader(
    old_dataset, batch_size=2, shuffle=True, collate_fn=collate_fn
)
new_dataloader = DataLoader(
    new_dataset, batch_size=2, shuffle=True, collate_fn=collate_fn
)

```

* `CustomTextDataset` 只返回原始文本与标签，`collate_fn` 在拼出 batch 后按各自 batch 内最长序列动态填充（上限 `128`），减少无效 `[PAD]` 计算。
* 将新旧数据拆成两个 `DataLoader`，使每个训练步都能显式兼顾旧分布与新分布样本。

### 2. 保存初始参数快照（`initial_params`）

```python
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model.to(device)

# ✅ 修复 1：保存初始参数快照，并确保 detach() 且与 model 处在同一 device 上
initial_params = {
    name: param.clone().detach().to(device)
    for name, param in model.named_parameters()
    if param.requires_grad
}

optimizer = AdamW(model.parameters(), lr=2e-5, weight_decay=0.01)

```

* **为什么要 `.clone().detach().to(device)`？**
* `.clone()` 复制一份独立张量，防止后续 `optimizer.step()` 原地修改模型权重时把参考锚点也改掉；
* `.detach()` 切断与计算图的连接，避免锚点张量参与梯度追踪或保留不必要的计算历史；
* `.to(device)` 保证与 `param` 处于同一设备，避免跨设备运算报错。


* **双重正则分工**：`AdamW(..., weight_decay=0.01)` 是常规权重衰减（将参数向 `0` 收缩），而后续显式加入的 `constraint_loss` 则是将参数锚定在**微调前的初始权重 `initial_params**` 附近，两者作用参考点不同。

### 3. 双 Batch 迭代与混合损失计算

```python
num_epochs = 3
alpha = 0.5  # 新旧数据 Loss 平衡系数
beta = 0.1  # 参数偏差惩罚系数 (L2 Regularization Strength)

for epoch in range(num_epochs):
  model.train()
  total_loss = 0.0

  # ✅ 修复 2：使用 cycle 防止旧数据丢弃
  steps_per_epoch = len(old_dataloader)
  new_dataloader_iter = itertools.cycle(new_dataloader)

  for old_batch in old_dataloader:
    new_batch = next(new_dataloader_iter)

```

* 以 `old_dataloader` 为主循环遍历全部旧 batch（示例中 `len(old_dataloader) == 2`），用 `itertools.cycle(new_dataloader)` 保证较短的 `new_dataloader` 在每个 step 都能提供新数据 batch。

### 4. 参数偏移 $L_2$ 惩罚项与梯度更新

```python
    optimizer.zero_grad()

    # 1. 新旧数据的交叉熵 Loss
    old_loss = F.cross_entropy(
        model(old_ids, attention_mask=old_mask).logits, old_lbls
    )
    new_loss = F.cross_entropy(
        model(new_ids, attention_mask=new_mask).logits, new_lbls
    )

    # ✅ 修复 3：正确且高效地计算参数偏移 L2 惩罚项
    constraint_loss = torch.tensor(0.0, device=device)
    for name, param in model.named_parameters():
      if name in initial_params:
        # 计算与初始权重的二范数平方和
        constraint_loss += torch.sum((param - initial_params[name]) ** 2)

    # 混合总损失
    loss = alpha * new_loss + (1 - alpha) * old_loss + beta * constraint_loss

    loss.backward()
    torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
    optimizer.step()

```

* **`constraint_loss` 机制**：对 `initial_params` 中记录的每个参数计算 `(param - initial_params[name]) ** 2` 并求和，相当于对参数变化量施加平方 $L_2$ 惩罚（$\sum_i \Vert{}\theta_i - \theta_{0,i}\Vert{}_2^2$）。权重变动越大，惩罚越强，从而约束模型不要偏离微调前的状态太远。
* **总损失与梯度裁剪**：`alpha * new_loss + (1 - alpha) * old_loss + beta * constraint_loss` 将新任务学习、旧数据回放与参数锚定统一到同一个标量目标中；`loss.backward()` 后执行 `clip_grad_norm_(..., max_norm=1.0)` 防止梯度过大，随后 `optimizer.step()` 更新参数。

## 四、 工程实践中的潜在注意点

1. **惩罚系数 `beta` 与参数规模的敏感度**
`constraint_loss` 是对所有记录参数的平方差直接求和，当模型参数总量较大时，即使每个参数只发生微小变动，平方和也可能累积到较大数值。若发现 `constraint_loss` 过大导致模型“学不动新数据”，可适当调小 `beta`（例如从 `0.1` 降为 `1e-3`、`1e-4` 或更小），或改为按参数元素均值计算并结合验证集调参。
2. **多轮增量场景下锚点是“初始基座”还是“上一轮权重”**
当前代码记录的是本次训练开始时的 `initial_params`。如果是**多轮跨阶段增量训练**，既可以锚定在初始预训练/基座权重以守住通用先验，也可以视需求锚定在上一阶段稳定权重以平滑过渡，具体取决于业务更看重哪一层的稳定性。
3. **显存与多卡/分布式扩展**
`initial_params` 在 GPU 上会额外占用一份与可训练参数同规模的显存（若模型较大或使用 ZeRO/FSDP 切分参数，需注意张量所在设备与分片状态）；若数据集较大，建议补充验证集评估与最佳权重保存。
