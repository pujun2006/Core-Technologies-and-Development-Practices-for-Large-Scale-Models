Comprehensive Case Study on Fine-Tuning Strategies and Optimization in Incremental Learning.py代码将前面提到的两项增量微调机制融合进了一条单一数据加载器训练闭环：**通过 `WeightedRandomSampler` 在采样阶段平衡新旧数据分布，同时通过“初始参数快照 + 平方 $L_2$ 偏差惩罚”在参数空间约束模型不要过度偏离微调前的状态**。

---

## 一、 整体方案与核心设计思路

与前一段“双 `DataLoader` 分别算 Loss 再加权合并”的写法相比，这段代码采用了**单 `DataLoader` + 采样加权 + 参数锚定正则**的组合：

1. **合并数据集 + 采样权重控制分布**：把 `old_texts / old_labels` 与 `new_texts / new_labels` 拼成 `combined_dataset`，用 `WeightedRandomSampler` 给旧样本权重 `0.5`、新样本权重 `1.0`，让新样本在抽样时相对更受倾斜，而单步前向只需计算一个 batch 的交叉熵损失（`data_loss`），结构更紧凑。
2. **参数锚定正则防遗忘**：在训练开始前把可训练参数克隆并分离到 `initial_params`，每一步反向传播前额外计算当前参数与 `initial_params` 的平方 $L_2$ 距离 `constraint_loss`，与 `data_loss` 组合成总损失。

---

## 二、 逐段代码详细解析

### 1. 模型加载与新旧数据合并

```python
model_name = "bert-base-chinese"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForSequenceClassification.from_pretrained(
    model_name, num_labels=3
)

old_texts = ["旧数据样本1", "旧数据样本2", "旧数据样本3"]
new_texts = ["新数据样本1", "新数据样本2"]
old_labels = [0, 1, 0]
new_labels = [1, 2]

combined_texts = old_texts + new_texts
combined_labels = old_labels + new_labels

```

* 加载中文 BERT 3 分类模型与分词器，并将 3 条旧样本与 2 条新样本按顺序拼接，使索引 `0..2` 对应旧数据、`3..4` 对应新数据。

### 2. `CustomTextDataset` 与动态 Padding 的 `collate_fn`

```python
class CustomTextDataset(Dataset):

  def __init__(self, texts, labels):
    self.texts = texts
    self.labels = labels

  def __len__(self):
    return len(self.texts)

  def __getitem__(self, idx):
    return {"text": str(self.texts[idx]), "labels": self.labels[idx]}


def collate_fn(batch):
  batch_texts = [item["text"] for item in batch]
  batch_labels = [item["labels"] for item in batch]
  inputs = tokenizer(
      batch_texts,
      padding=True,
      truncation=True,
      max_length=128,
      return_tensors="pt",
  )
  inputs["labels"] = torch.tensor(batch_labels, dtype=torch.long)
  return inputs

```

* `__getitem__` 只负责按索引返回原始文本与标签；`collate_fn` 在组 batch 时统一调用 `tokenizer` 进行 `padding=True` 与 `truncation=True`（上限 `128`），按**当前 batch 内最长序列**动态补齐 `[PAD]`，减少无效计算。

### 3. `WeightedRandomSampler` 与 `DataLoader` 配置

```python
combined_weights = [
    0.5 if i < len(old_texts) else 1.0 for i in range(len(combined_labels))
]
sampler = WeightedRandomSampler(
    combined_weights, num_samples=len(combined_weights), replacement=True
)

dataloader = DataLoader(
    combined_dataset,
    batch_size=2,
    sampler=sampler,
    collate_fn=collate_fn,  # 注意：使用了 sampler 绝不能写 shuffle=True
)

```

* **权重与抽样比例**：旧样本权重 `0.5`、新样本权重 `1.0`，`replacement=True` 表示有放回抽样，单 Epoch 抽取 `num_samples=5` 条样本（`batch_size=2` 下共产生 `3` 个 batch）。
* **互斥规则**：传入 `sampler` 时不能再设置 `shuffle=True`，否则 PyTorch `DataLoader` 会报错。

### 4. 初始参数快照与优化器配置

```python
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model.to(device)

# ✅ 修复 1：将快照移动到对应 device，并使用 detach() 切断计算图
initial_params = {
    name: param.clone().detach().to(device)
    for name, param in model.named_parameters()
    if param.requires_grad
}

optimizer = AdamW(model.parameters(), lr=2e-5, weight_decay=0.01)

```

* `.clone().detach().to(device)` 确保快照独立于后续原地权重更新、不保留计算图历史，并与模型处于同一设备，避免设备不一致报错或图累积。
* `AdamW` 的 `weight_decay=0.01` 负责常规权重衰减，与后续显式的 `initial_params` 锚定形成互补。

### 5. 训练循环：交叉熵损失 + 参数偏移惩罚 + 梯度裁剪

```python
num_epochs = 3
beta = 0.1  # 参数偏差惩罚系数 (L2 Constraint)

for epoch in range(num_epochs):
  model.train()
  total_loss = 0.0

  for batch in dataloader:
    input_ids = batch["input_ids"].to(device)
    attention_mask = batch["attention_mask"].to(device)
    labels = batch["labels"].to(device)

    optimizer.zero_grad()

    # 计算交叉熵 Loss（已通过 WeightedRandomSampler 完成新旧权重平衡）
    outputs = model(input_ids, attention_mask=attention_mask)
    data_loss = F.cross_entropy(outputs.logits, labels)

    # ✅ 修复 2：高效计算二范数平方惩罚，不产生 Device 冲突和显存泄露
    constraint_loss = torch.tensor(0.0, device=device)
    for name, param in model.named_parameters():
      if name in initial_params:
        constraint_loss += torch.sum((param - initial_params[name]) ** 2)

    # ✅ 修复 3：总损失 = 数据交叉熵损失 + 权重锚定惩罚
    total_loss_value = data_loss + beta * constraint_loss

    total_loss_value.backward()
    torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
    optimizer.step()

    total_loss += total_loss_value.item()

  avg_loss = total_loss / len(dataloader)
  print(f"第 {epoch+1} 轮平均损失: {avg_loss:.4f}")

```

* **局部变量命名提醒**：循环外累积每轮总损失的变量名为 `total_loss`，循环内拼接总标量损失的变量名为 `total_loss_value`（避免了同名覆盖）；但每步累加时用的是 `total_loss += total_loss_value.item()`，因此 `avg_loss` 统计的是包含 `data_loss + beta * constraint_loss` 在内的每 batch 平均总损失。
* **梯度裁剪与更新**：`total_loss_value.backward()` 后调用 `clip_grad_norm_(model.parameters(), max_norm=1.0)` 约束梯度范数上限，再通过 `optimizer.step()` 完成参数更新。

## 四、 工程实践中的潜在注意点

1. **命名与日志可读性**
循环内若把 `total_loss_value` 改名为 `step_loss`，并将 `data_loss` 与 `beta * constraint_loss` 分开打印，在调参时能更直观地看出是数据交叉熵没降下去，还是参数锚定惩罚项占主导。
2. **`beta` 的量级与调优**
`constraint_loss` 对所有参数 `(param - initial_params[name]) ** 2` 直接求和，BERT 类模型参数总量较大，若 `beta=0.1` 偏大，容易抑制新样本的梯度更新；实际使用时常需在验证集上对比 `1e-2`、`1e-3`、`1e-4` 等不同量级，同时兼顾新数据指标与旧数据回归指标。
3. **补充验证评估与最佳权重保存**
当前循环仅输出训练集每轮平均损失，正式增量微调时建议拆分独立的验证集（或分别保留新数据验证集与历史回归集），在每个 Epoch 结束后记录指标并保存最优 Checkpoint。
