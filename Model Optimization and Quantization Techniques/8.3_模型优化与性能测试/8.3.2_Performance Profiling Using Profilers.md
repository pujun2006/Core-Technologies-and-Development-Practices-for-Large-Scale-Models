Performance Profiling Using Profilers.py代码使用 `torch.profiler` 对一个无池化层的卷积神经网络（`SimpleCNN`）分别进行了 **CPU 推理性能剖析** 与 **GPU（CUDA）推理性能剖析**，展示了如何记录张量形状、追踪内存/显存、标注自定义区间，并导出 Chrome / Perfetto 时间线追踪文件。

下面按模块逐一拆解其原理与工程细节。

---

### 一、 网络结构与维度计算

```python
class SimpleCNN(nn.Module):
    def __init__(self):
        ...
        self.conv1 = nn.Conv2d(1, 16, kernel_size=3, stride=1, padding=1)
        self.bn1 = nn.BatchNorm2d(16)
        self.conv2 = nn.Conv2d(16, 32, kernel_size=3, stride=1, padding=1)
        self.bn2 = nn.BatchNorm2d(32)

        # 无池化层时空间尺寸保持 28x28，展平维度为 32 * 28 * 28 = 25088
        self.fc1 = nn.Linear(32 * 28 * 28, 128)
        self.fc2 = nn.Linear(128, 10)

```

* **特征图尺寸不变**：两次 `3x3` 卷积均设置了 `stride=1, padding=1`，因此输入 `(16, 1, 28, 28)` 经过卷积与批归一化后，空间分辨率仍为 `28x28`，通道数变为 `32`。
* **全连接层输入维度**：`torch.flatten(x, 1)` 将单样本特征展平为 `32 * 28 * 28 = 25088` 维，与 `fc1` 精确对齐。相比带池化层的版本，这里特征维度更大，`fc1` 的参数量与矩阵计算量也相应更高。

### 二、 CPU 性能剖析

```python
model = SimpleCNN().to("cpu")
model.eval()
input_data = torch.rand(16, 1, 28, 28)

with profiler.profile(
    activities=[profiler.ProfilerActivity.CPU],
    record_shapes=True,
    profile_memory=True,
) as prof_cpu:
    with profiler.record_function("model_inference_cpu"):
        output = model(input_data)

print(
    prof_cpu.key_averages().table(sort_by="cpu_time_total", row_limit=10)
)

```

* **`activities=[profiler.ProfilerActivity.CPU]`**：仅采集 CPU 侧算子执行与调度信息。
* **`record_shapes=True` 与 `profile_memory=True**`：前者记录各算子输入的张量形状，后者统计 CPU 侧内存分配/释放情况。
* **`profiler.record_function("model_inference_cpu")`**：在 Profiler 中打上自定义标签，方便把整段前向推理作为一个逻辑分组观察。
* **`key_averages().table(sort_by="cpu_time_total", row_limit=10)`**：按算子累计 CPU 耗时（含子算子）降序汇总，打印耗时排名前 10 的算子。
* **细节提示**：前向调用时若包上 `with torch.no_grad():`，可避免在推理剖析中产生不必要的梯度相关判断/状态开销。

### 三、 GPU（CUDA）性能剖析与 Trace 导出

```python
if torch.cuda.is_available():
    device = "cuda"
    model.to(device)
    input_data = input_data.to(device)

    with torch.no_grad():
        _ = model(input_data)
    torch.cuda.synchronize()

```

#### 1. 为什么要先 Warmup 再 `torch.cuda.synchronize()`？

* **GPU Warmup**：首次执行 CUDA 算子时，CUDA Context 初始化、cuDNN/算子选择与显存缓存分配会带来额外开销；先跑一次前向能减少冷启动干扰。
* **同步点（`torch.cuda.synchronize()`）**：由于 GPU 内核是异步调度的，CPU 发起算子后可能立即返回。在剖析结束前调用 `torch.cuda.synchronize()`，能确保所有已提交的 GPU Kernel 真正执行完毕，从而准确计入耗时。

#### 2. 双端采集、排序与导出 Trace

```python
    with profiler.profile(
        activities=[
            profiler.ProfilerActivity.CPU,
            profiler.ProfilerActivity.CUDA,
        ],
        record_shapes=True,
        profile_memory=True,
        with_stack=False,
    ) as prof_gpu:
        with profiler.record_function("model_inference_gpu"):
            output = model(input_data)
            torch.cuda.synchronize()

    print(
        prof_gpu.key_averages().table(
            sort_by="cuda_time_total", row_limit=10
        )
    )
    prof_gpu.export_chrome_trace("trace_gpu.json")

```

* **同时开启 `CPU` 与 `CUDA**`：既能看到主机端下发算子的耗时，也能看到设备端实际执行 Kernel 的耗时与显存分配细节。
* **`with_stack=False`**：关闭 Python 调用栈采集，降低剖析开销；若需要精确定位某个底层算子是由哪行 Python 代码触发，可设为 `True`。
* **`sort_by="cuda_time_total"`**：按 GPU 累计耗时排序，快速找出最耗时的卷积、矩阵乘或归一化等 Kernel。
* **`export_chrome_trace("trace_gpu.json")`**：将时间线事件导出为 JSON 文件，可在 Chrome 的 `chrome://tracing` 或 Perfetto（`ui.perfetto.dev`）中打开查看 CPU 与 GPU 的并行时间轴。

### 五、 补充工程细节

* **单次运行 vs. 多步采样**：当前代码在 `profiler.profile` 块内只跑了单次推理；若要观察更稳定的平均表现或周期性开销，可结合 `torch.profiler.schedule` 进行多步 `warmup` 与 `active` 采样。
* **注意输出文件**：在支持 CUDA 的环境中运行后，当前目录会生成 `trace_gpu.json`，分析完成后可根据需要清理或归档。
