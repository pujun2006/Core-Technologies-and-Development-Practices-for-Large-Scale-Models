模型量化在推理阶段的加速效果，本质上是通过将原本高精度的权重、激活值或 KV Cache（如 FP32、FP16 / BF16）映射到低比特表示（如 INT8、INT4、FP8、FP4），**同时降低访存字节数并提升底层计算单元的吞吐率**。

但在实际推理中，量化**并不是在所有阶段都带来线性加速**，其加速收益高度依赖推理阶段（Prefill vs. Decode）、算力瓶颈类型（访存受限 vs. 计算受限）以及硬件指令支持。

---

### 一、 加速的核心机制：访存与算力双轮驱动

#### 1. 降低显存带宽瓶颈（Memory Bandwidth Bound）

自回归大模型在 **Decode（逐 Token 生成）** 阶段，每生成一个 Token 都需要将全部模型权重与历史 KV Cache 从显存（HBM）搬运到片上缓存（SRAM / 寄存器）参与矩阵向量乘（GEMV）。此时算术强度（Arithmetic Intensity，即每字节访存对应的计算量 $\text{FLOPs}/\text{Byte}$）较低，推理性能主要受限于**显存带宽**。

* 将权重从 FP16（2 字节）压缩到 INT4（0.5 字节），理论权重搬运量可降至原来的约 **1/4**；若同时量化 KV Cache（如 FP8 / INT8），长上下文下的 KV 访存与显存占用也会显著下降。
* 在访存受限区域，访存体积缩小会直接缩短数据加载时间，从而降低单步延迟（TPOT）并提升吞吐。

#### 2. 提升低精度算力吞吐（Compute Bound）

在 **Prefill（提示词编码）** 阶段或大 Batch 高并发推理时，输入序列长、计算量大，算术强度较高，推理更容易进入**计算受限**状态。

* 现代 GPU / NPU 的张量计算单元（如 Tensor Core）对低比特数据类型通常提供更高的理论峰值算力（例如部分架构上 INT8 / FP8 相对 FP16/BF16 具有更高的吞吐上限）。
* 当激活值与权重同时量化（如 **W8A8** 或 **FP8**）并在低精度矩阵乘（GEMM）硬件单元上直接执行时，可充分利用低精度计算吞吐，加快 Prefill 首字延迟（TTFT）与高并发吞吐。

### 二、 不同量化路线与推理阶段的加速差异

| 量化形式 | 典型方法 / 格式 | 主要收益来源 | 适用场景与局限 |
| --- | --- | --- | --- |
| **仅权重量化（W4A16 / W8A16）** | GPTQ、AWQ、GGUF | 显著减少权重访存与显存占用；在 SRAM 中反量化后用 FP16/BF16 计算 | **Decode 阶段**与单卡部署收益明显；但矩阵计算仍走高精算力，高 Batch Prefill 算力增益有限 |
| **权重 + 激活量化（W8A8 / FP8）** | SmoothQuant、FP8 GEMM | 兼顾访存缩减与低精度 GEMM 算力提升 | 适合算力受限、长 Prompt 或高并发吞吐场景；需处理激活值离群点（Outliers）以控制精度损失 |
| **KV Cache 量化（FP8 / INT8 KV）** | KVCache 量化 | 降低长上下文 KV 读写带宽与显存占用，允许更大 Batch Size | 对长文本推理、高并发批处理尤为关键 |

### 三、 为什么实际加速往往低于“理论比特比”？

在实际工程部署中，将 FP16 改为 INT4 很少能达到严格的 4 倍端到端加速，常见原因包括：

1. **反量化与打包/解包开销**：W4A16 等方案在计算前需要将 4-bit 权重解包并乘以缩放因子（Scale）和零点（Zero-point）恢复为 FP16/BF16。若算子融合（Kernel Fusion）不充分，反量化与类型转换会消耗额外的访存和指令周期。
2. **非矩阵乘算子的比例**：Transformer 中除了线性层（Linear / GEMM），还有 Attention 调度、LayerNorm / RMSNorm、RoPE、激活函数与采样等非量化或高频算子。根据阿姆达尔定律，这些部分会限制整体加速上限。
3. **Batch Size 与序列长度的影响**：
* 小 Batch、长生成的 **Decode** 更依赖权重与 KV 带宽缩减；
* 大 Batch 或长上下文的 **Prefill** 更看重激活量化带来的计算吞吐提升与 KV 显存节省（从而支撑更大 Batch）。


4. **硬件指令集与 Kernel 优化程度**：不同芯片对 INT4、INT8、FP8 的原生指令支持和算子库成熟度不同；某些硬件上缺乏原生 INT4 Tensor Core 指令时，甚至可能出现反量化开销抵消部分带宽收益的情况。

### 四、 评估量化加速效果的关键指标

在落地测试时，建议结合以下指标对比量化前后的真实收益：

* **TTFT（Time To First Token，首字延迟）**：观察 Prefill 阶段计算与提示词访存优化效果。
* **TPOT / ITL（Time Per Output Token / Inter-Token Latency，逐字生成延迟）**：观察 Decode 阶段带宽缩减与反量化开销的净收益。
* **吞吐量（Tokens/s）与最大并发 Batch**：量化释放显存后，通常能容纳更大的 Batch Size 或更长的上下文窗口，从而在系统级提升总吞吐。
* **精度/任务指标退化（如困惑度 PPL、评测基准与业务准确率）**：在追求更高压缩率（如 INT4）时，需在加速比与精度损失之间做权衡。
