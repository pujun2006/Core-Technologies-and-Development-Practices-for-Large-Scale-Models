Quantization-Aware Training.py代码使用 PyTorch 的 `torch.ao.quantization` 对一个卷积神经网络（`SimpleCNN`）执行完整的量化感知训练（QAT）流程：从网络定义、算子融合（Fusion）、插入伪量化观察器、训练微调与冻结统计量，最后转换为纯 INT8 模型并验证推理。

下面按模块逐一拆解其原理与工程细节。

---

### 一、 网络结构与 `QuantStub` / `DeQuantStub`

```python
class SimpleCNN(nn.Module):
    def __init__(self):
        super(SimpleCNN, self).__init__()
        self.quant = quantization.QuantStub()
        self.dequant = quantization.DeQuantStub()
        self.conv1 = nn.Conv2d(1, 16, kernel_size=3, stride=1, padding=1)
        self.bn1 = nn.BatchNorm2d(16)
        self.relu1 = nn.ReLU()
        ...

```

* **输入输出转换桩**：`QuantStub` 负责将输入张量（`1x28x28` 灰度图，类似 MNIST 尺寸）量化为低比特表示；`DeQuantStub` 在网络末端把输出反量化回浮点型，以便计算 `CrossEntropyLoss` 或直接输出浮点 Logits。
* **保留独立的 `Conv`、`BatchNorm`、`ReLU` 层**：在 QAT 融合前，结构上拆分为独立的子模块，方便后续按层名序列进行算子融合。

### 二、 算子融合函数 `fuse_cnn_model`

```python
def fuse_cnn_model(model):
    modules_to_fuse = [
        ["conv1", "bn1", "relu1"],
        ["conv2", "bn2", "relu2"],
        ["fc1", "relu3"],
    ]
    model.train()
    for m in model.modules():
        m.training = True

    if hasattr(quantization, "fuse_modules_qat"):
        return quantization.fuse_modules_qat(model, modules_to_fuse)
    return quantization.fuse_modules(model, modules_to_fuse)

```

* **为什么要融合 `Conv + BN + ReLU` 和 `Linear + ReLU`？**
1. **推理更高效**：融合后减少中间特征图的读写与激活/量化切换，也便于推理后端直接执行融合算子。
2. **QAT 语义更准**：在训练时若直接用未融合的 `Conv` 权重做伪量化，后续 `BatchNorm` 的缩放与平移（$\gamma, \beta$）会改变有效权重分布，导致伪量化误差与真实推理分布不一致；QAT 融合会把 BN 的统计量与仿射参数吸收进前向模拟逻辑中。


* **为什么强制设为 `train()` 模式？**
* `fuse_modules_qat` 要求模型处于训练模式（`training == True`），以便在 QAT 期间正确跟踪 BatchNorm 的批统计量与移动均值/方差。代码中显式遍历所有子模块设置 `m.training = True`，是为了规避部分自定义子模块状态不一致导致的断言错误（`AssertionError`）。

### 三、 QAT 准备、训练与统计量冻结

#### 1. 配置与 `prepare_qat`

```python
model.qconfig = quantization.get_default_qat_qconfig("fbgemm")
prepared_model = quantization.prepare_qat(model, inplace=False)

```

* **`get_default_qat_qconfig("fbgemm")`**：选择面向 x86 平台的默认 QAT 量化配置（通常权重采用 per-channel 伪量化，激活采用 per-tensor 伪量化）。
* **`prepare_qat`**：在融合后的模型中插入 `FakeQuantize` 与对应的 Observer 模块，前向传播会通过伪量化模拟低比特舍入与截断，反向传播则通过直通估计器（STE）更新高精度权重。

#### 2. 后几轮冻结 Observer 与 BN 统计量

```python
if epoch >= num_epochs - 3:
    prepared_model.apply(quantization.disable_observer)
    prepared_model.apply(nn.intrinsic.qat.freeze_bn_stats)

```

这是 QAT 中非常经典的收尾技巧（代码在最后 3 个 epoch 启用）：

* **`disable_observer`**：停止更新量化参数（Scale / Zero-point）的统计范围，让量化边界在训练末尾趋于稳定，避免后期因极值抖动导致量化参数剧烈跳变。
* **`freeze_bn_stats`**：冻结 BatchNorm 的 running mean 和 running variance 更新，使 BN 统计量在导出前稳定下来，减小训练与推理时的统计偏差。

#### 3. 学习率调度

* 使用 `Adam(lr=1e-3)` 配合 `StepLR(step_size=5, gamma=0.5)`，每 5 个 epoch 学习率减半。
* **实践提示**：在真实任务中，QAT 通常从已训练收敛的浮点模型开始微调，学习率往往比从头训练更小（例如原学习率的 `1/10` 或更低），否则容易破坏已有特征；同时当前示例使用的是随机假数据（`torch.rand` / `torch.randint`），仅用于验证代码流程与算子连通性，**真实业务需替换为真实数据集**。

### 四、 模型转换与推理验证

```python
prepared_model.eval()
quantized_model = quantization.convert(
    prepared_model.to("cpu"), inplace=False
)

with torch.no_grad():
    test_input = torch.rand(1, 1, 28, 28)
    output = quantized_model(test_input)

```

* **先 `eval()` 再 `convert()**`：转换前将模型切到推理模式，然后 `quantization.convert` 会根据收集到的量化参数移除 `FakeQuantize` 和 Observer，将融合后的 QAT 模块替换为真正的低比特量化算子（如 INT8 算子）。
* **推理阶段关闭梯度与测试输入**：`torch.no_grad()` 禁用梯度计算，传入 `(1, 1, 28, 28)` 的单张输入验证前向输出形状与数值是否正常。
