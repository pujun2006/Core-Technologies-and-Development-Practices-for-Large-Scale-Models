剪枝策略可以从**剪枝粒度（结构化程度）**、**重要性评估准则（剪谁）**以及**执行时机与迭代方式（何时剪、怎么剪）**三个正交维度来分类。不同策略在**精度保留率、硬件加速收益、实现复杂度与适用场景**上各有侧重。

---

### 一、 按剪枝粒度划分：从“单个权重”到“整块结构”

#### 1. 非结构化剪枝（Unstructured Pruning）

* **做法**：以单个标量权重（如线性层权重矩阵或卷积核中的某个具体元素）为单位进行掩码置零，产生不规则的稀疏权重矩阵。
* **特点**：
* 粒度最细，自由度最高，在较高稀疏度下往往比同稀疏度的结构化剪枝更容易保留模型精度；
* 但零值分布不规律，在常规 GPU 的密集矩阵乘法（GEMM）上若缺乏专用稀疏算子/硬件支持，未必能带来实际推理加速，甚至可能因访存不连续而变慢。


* **典型场景**：模型压缩与稀疏性机理研究、支持稀疏计算的专用推理引擎/硬件、或作为后续结构化裁剪/蒸馏前的探索基线。

#### 2. 结构化剪枝（Structured Pruning）

* **做法**：按规整的物理或逻辑结构整块移除参数，例如：
* **卷积/特征通道剪枝**：移除整个输出通道或输入通道；
* **Transformer 组件剪枝**：裁剪冗余的注意力头（Attention Head）、FFN/MLP 的中间隐藏维度（Intermediate / Hidden Size）、甚至整层（Layer Pruning / Depth Pruning）。


* **特点**：
* 保留规整的稠密张量形状，直接减少参数量、计算量与显存占用，在通用 GPU/CPU 上无需特殊稀疏指令即可获得真实的延迟降低与吞吐提升；
* 粒度较粗，激进剪枝时更容易引发功能缺失，通常需要更精细的重要性评估与恢复微调。


* **典型场景**：生产环境高并发推理、显存受限的实时服务、端侧/边缘设备部署。

#### 3. 半结构化剪枝（Semi-Structured / N:M Pruning）

* **做法**：在连续的 $M$ 个权重元素中强制保留 $N$ 个非零值、其余置零（例如业界常见的 `2:4` 稀疏，即每 4 个连续权重保留 2 个非零值）。
* **特点**：介于非结构化与结构化之间，既保留了一定的细粒度选择空间，又能匹配特定硬件提供的 `N:M` 稀疏张量核加速能力。
* **典型场景**：搭载支持 `N:M` 稀疏加速指令的 GPU/芯片推理场景。

### 二、 按重要性评估准则划分：如何判断“哪些参数可删”

剪枝的关键在于打分函数（Importance Metric），决定哪些权重或结构对任务损失贡献最小：

1. **幅值准则（Magnitude-based，如 L1 / L2 范数）**：
* 认为绝对值（或向量范数）越小的权重/通道对输出扰动越小。
* **优点**：计算极快、无需反向传播梯度或大量校准数据；**缺点**：忽略了跨层协同效应与任务敏感度，在高剪枝率下较粗糙。


2. **梯度与一阶敏感度准则（Gradient / Taylor 近似）**：
* 结合参数值与损失函数对其梯度（如权重乘以梯度，或一阶泰勒展开近似移除该参数导致的损失增量），衡量在当前任务数据上的实际影响。
* **优点**：比纯幅值更能感知具体任务；**缺点**：依赖反向传播与代表性数据集。


3. **二阶与激活/数据驱动准则**：
* 利用 Hessian 矩阵对角线/近似或校准集上的激活分布、特征重构误差来评估剪枝后的输出偏差。
* **优点**：对大模型或复杂非线性结构更精确；**缺点**：计算开销更高，实现更复杂。


4. **全局剪枝 vs. 逐层剪枝（Global vs. Layer-wise）**：
* **逐层剪枝**：每层按统一比例裁剪，简单可控，但不同层冗余度不同，可能“冤枉”关键层或放过冗余层；
* **全局剪枝**：跨层统一排序并按全局阈值/比例裁剪，能自动让冗余度高的层承担更多剪枝，但需注意不同层数值尺度或敏感度差异。

### 三、 按执行时机与迭代模式划分

* **一次性剪枝（One-shot Pruning） + 微调恢复**：先按目标比例一次性剪掉参数，再进行一轮或几轮微调（Fine-tuning / LoRA / 蒸馏恢复）弥补精度损失。流程简洁，适合中小幅度剪枝。
* **迭代剪枝（Iterative Pruning，如“剪枝 → 微调 → 再剪枝”）**：分多轮逐步提高稀疏度或裁剪比例，每一步都让模型在现有结构上适应与恢复。通常比单次大幅剪枝更能保住精度，但总训练耗时更长。
* **训练中剪枝 / 结构学习**：在训练过程中通过稀疏正则化、门控机制或动态掩码逐步淘汰冗余结构，使模型在训练阶段就向紧凑结构收敛。

### 四、 不同模型与业务场景的选型映射

| 应用场景 | 推荐剪枝策略 | 核心关注点与实操建议 |
| --- | --- | --- |
| **大模型（LLM）线上推理降本增效** | **结构化剪枝**（如剪冗余 FFN 维度、部分层或注意力头）结合恢复微调/蒸馏 | 优先保证通用推理、指令遵循与垂域任务不明显退化；常与量化配合使用 |
| **CNN / 视觉检测与分类部署** | **通道/滤波器结构化剪枝** + 迭代微调 | 通道裁剪能直接缩减特征图通道数与卷积 FLOPs，注意对齐残差连接与通道维度匹配 |
| **端侧 / 边缘 / 嵌入式设备** | **高收益结构化剪枝**（缩减层数/宽度）为主，辅以量化 | 端侧内存带宽与算力严格受限，必须看实际设备上的端到端延迟与内存峰值 |
| **垂域微调模型瘦身** | 针对目标任务数据做**敏感度评估 + 结构化/半结构化剪枝** + 领域微调 | 通用能力可适度让位于垂域指标，务必用垂域评测集做回归验证 |
| **算法实验与稀疏性验证** | **非结构化剪枝**（如 L1 范数掩码） | 适合快速验证不同稀疏度下的精度曲线与权重分布规律，不直接等同于无损加速 |

#### 工程落地三原则

1. **以真实硬件与推理后端为准**：剪枝后是否变快，取决于算子与硬件是否支持该结构，切忌只看理论参数量或 FLOPs 下降比例。
2. **剪枝后必须做恢复与回归评测**：剪枝几乎总会带来一定扰动，恢复微调后需对比原始模型在核心业务指标上的表现，防止出现长尾样本或复杂推理的隐性掉点。
3. **与蒸馏、量化协同规划**：若目标压缩率很高，单独硬剪枝往往精度受损较大，可考虑“适度结构化剪枝 + 知识蒸馏恢复”或“结构化精简 + 量化”的组合路线。
