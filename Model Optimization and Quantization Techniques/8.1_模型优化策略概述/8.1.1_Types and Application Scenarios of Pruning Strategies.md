Types and Application Scenarios of Pruning Strategies.py这段代码是一个完整的 **PyTorch 模型剪枝（Pruning）实战演示脚本**，基于 `torch.nn.utils.prune` 组合展示了**非结构化剪枝**、**结构化剪枝**、**稀疏度统计**以及**先固化官方剪枝再执行自定义 L1 分位数剪枝**的工程写法。

下面按模块逐一拆解其实现原理与关键细节：

---

### 一、 网络结构定义：`SimpleCNN`（第 1 部分）

```python
class SimpleCNN(nn.Module):

    def __init__(self):
        super(SimpleCNN, self).__init__()
        self.conv1 = nn.Conv2d(1, 16, 3, 1)  # 28x28 -> 26x26
        self.conv2 = nn.Conv2d(16, 32, 3, 1)  # 26x26 -> 24x24
        self.fc1 = nn.Linear(32 * 24 * 24, 128)  # 修正输入维度为 18432
        self.fc2 = nn.Linear(128, 10)

```

* **特征图尺寸推算**：输入假设为单通道 `28x28`（如 MNIST 尺寸），两次步长为 `1`、无填充的 `3x3` 卷积后，空间尺寸依次变为 `28 - 3 + 1 = 26` 和 `26 - 3 + 1 = 24`。
* **展平维度对齐**：`conv2` 输出通道数为 `32`、空间大小为 `24x24`，展平后特征维数为 `32 * 24 * 24 = 18432`，与 `fc1` 的输入维度精确匹配。

### 二、 稀疏度统计函数：`print_sparsity`

```python
def print_sparsity(model):
    ...
    for name, module in model.named_modules():
        if hasattr(module, "weight") and module.weight is not None:
            w = module.weight
            num_zeros = torch.sum(w == 0).item()
            num_elements = w.nelement()
            sparsity = 100.0 * num_zeros / num_elements

```

* **工作原理**：遍历模型所有子模块，检查是否存在非空 `weight` 参数，统计值为 `0` 的元素占比（`num_zeros / num_elements`），并累计全模型总稀疏度。
* **与 PyTorch 剪枝 Hook 的兼容**：当模块被 `torch.nn.utils.prune` 剪枝后，PyTorch 会注册前向钩子（Hook）并在每次前向传播时动态计算应用掩码后的有效权重 `module.weight`。直接读取 `module.weight` 可以反映当前生效的零值比例。

### 三、 三种剪枝策略的实现细节

#### 1. 非结构化剪枝：`apply_unstructured_pruning`

```python
def apply_unstructured_pruning(model, amount=0.5):
    prune.random_unstructured(model.fc1, name="weight", amount=amount)
    prune.random_unstructured(model.fc2, name="weight", amount=amount)
    return model

```

* 针对 `fc1` 和 `fc2` 的 `weight` 参数，随机按 `amount=0.5`（50%）的比例将单个权重元素置零。
* 属于**元素级稀疏**，不改变权重张量的形状（仍为 `[128, 18432]` 与 `[10, 128]`）。

#### 2. 结构化剪枝：`apply_structured_pruning`

```python
def apply_structured_pruning(model, amount=0.3):
    prune.ln_structured(model.conv1, name="weight", amount=amount, n=2, dim=0)
    prune.ln_structured(model.conv2, name="weight", amount=amount, n=2, dim=0)
    return model

```

* 使用 `prune.ln_structured` 配合 `n=2`（L2 范数）与 `dim=0`（卷积权重形状为 `[out_channels, in_channels, kH, kW]`，`dim=0` 对应**输出通道/滤波器**）。
* 计算每个输出通道切片的 L2 范数，将范数最小的 `amount=0.3`（30%）个整通道置零。
* **注意**：`torch.nn.utils.prune` 的掩码机制本质上仍是**将对应位置掩码/置零（Masking）**，并不会自动缩小张量物理维度或释放显存；若要真正缩小张量形状以减少计算量，通常还需配合结构导出/通道重排或专用结构裁剪工具。

#### 3. 固化剪枝钩子 + 自定义 L1 分位数剪枝：`apply_custom_magnitude_pruning`

```python
def apply_custom_magnitude_pruning(model, threshold_quantile=0.2):
    for name, module in model.named_modules():
        if isinstance(module, (nn.Conv2d, nn.Linear)):
            if prune.is_pruned(module):
                prune.remove(module, "weight")

            with torch.no_grad():
                importance_scores = torch.abs(module.weight)
                threshold_value = torch.quantile(
                    importance_scores, threshold_quantile
                )
                mask = importance_scores > threshold_value
                module.weight.mul_(mask.float())
    return model

```

这段代码的工程处理非常关键，体现了几个重要细节：

1. **先 `prune.remove` 再手动改权重**：
* 在第 1、2 步中，`fc1`、`fc2`、`conv1`、`conv2` 都已经被 `torch.nn.utils.prune` 挂载了钩子，原始权重被重命名为 `weight_orig`，掩码存为 `weight_mask`。
* 调用 `prune.remove(module, "weight")` 会把掩码应用到 `weight_orig` 上、移除钩子与辅助缓冲区，并将合并后的张量恢复为标准 `module.weight` 参数。若不先移除钩子直接操作 `module.weight`，后续 `forward` 钩子仍可能按旧 `weight_mask` 覆盖结果。


2. **L1 重要性与分位数阈值**：
* `torch.abs(module.weight)` 计算每个权重的 L1 幅值；
* `torch.quantile(importance_scores, threshold_quantile)` 取 `0.2` 分位数作为阈值，保留严格大于阈值的权重（`importance_scores > threshold_value`）。
* *细节留意*：当张量中已经存在大量 `0`（前面剪枝留下的零值）时，分位数计算会受到这些零值的影响；若希望在当前非零权重或全量权重上按特定比例裁剪，需明确统计口径。


3. **`torch.no_grad()` 与原地乘法 `mul_()**`：
* 放在 `torch.no_grad()` 下避免构建计算图；`module.weight.mul_(mask.float())` 原地将低于阈值的权重清零。

### 四、 主运行流程的叠加效果与工程提示

在 `if __name__ == "__main__":` 中，三步按顺序叠加执行：

1. 仅对 `fc1`、`fc2` 做 50% 随机非结构化剪枝（`conv1`、`conv2` 仍为 0% 稀疏）；
2. 在此基础上，再对 `conv1`、`conv2` 按输出通道做 30% L2 结构化剪枝；
3. 固化前面所有剪枝钩子后，对所有 `Conv2d` 和 `Linear` 层再按 L1 幅值的 `0.2` 分位数做一次阈值清零。

**补充工程建议**：

* **剪枝后必须配合训练/微调**：当前脚本直接在未训练的随机初始化 `SimpleCNN` 上演示掩码与稀疏度统计；在真实任务中，剪枝后通常需要继续训练（Fine-tuning）恢复精度，否则高剪枝率下准确率会明显下降。
* **张量规模较大时的 `quantile` 注意事项**：`torch.quantile` 在元素数量极大或特定设备上偶尔会有张量大小限制或内存开销，若后续迁移到大模型参数矩阵，通常改用排序/Top-K 或分块统计更稳妥。
