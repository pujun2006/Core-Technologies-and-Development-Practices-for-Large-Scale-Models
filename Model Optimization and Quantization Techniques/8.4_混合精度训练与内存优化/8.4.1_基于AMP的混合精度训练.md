**基于 AMP（Automatic Mixed Precision，自动混合精度）的混合精度训练**，是指由框架或运行时根据算子类型、数值敏感度与目标硬件精度配置，**自动决定哪些算子以低精度（如 `FP16` 或 `BF16`）执行、哪些算子保持高精度（`FP32`）**，并在必要时配合梯度缩放（GradScaler）保证训练数值稳定性的工程方案。

在 PyTorch 生态中，核心通常由 **`autocast`（自动精度转换上下文）** 与 **`GradScaler`（梯度缩放器，主要用于 `FP16`）** 协同完成。

---

### 一、 AMP 的两大核心组件

#### 1. `autocast`（自动类型转换）

`autocast` 会在上下文作用域内拦截算子调用，按内置白名单/黑名单或精度规则自动转换输入张量的数据类型，而无需手动逐层改写模型代码：

* **低精度算子（如 `FP16` / `BF16`）**：常见于 `Linear` / `MatMul`、`Conv` 等高算力密度计算。它们能充分利用 GPU/NPU 的低精度矩阵乘单元，提升吞吐并降低激活值显存占用。
* **高精度算子（保持或提升到 `FP32`）**：常见于 `Softmax`、`LayerNorm` / `RMSNorm`、损失函数计算、规约操作（`sum` / `mean`）或对动态范围与累加精度敏感的运算，避免低精度下出现溢出、下溢或累加误差放大。

#### 2. `GradScaler`（动态梯度缩放）

当使用 **`FP16`** 时，由于其指数位较少、动态范围有限，反向传播中的小梯度容易发生**下溢（Underflow，变为 0）**，大梯度或放大后的中间值则可能发生溢出（Overflow，产生 `Inf`/`NaN`）。`GradScaler` 的作用是：

1. **前向放大 Loss**：在 `loss.backward()` 之前，将 `loss` 乘以缩放因子 `scale`（记为 $S$），使反向传播的梯度也相应放大 $S$ 倍，避免小梯度被截断为 0。
2. **反缩放与溢出检测**：在 `optimizer.step()` 之前，`scaler.step(optimizer)` 会先将梯度除以 $S$ 还原；同时检查梯度中是否存在 `Inf` 或 `NaN`。
* 若发现 `Inf`/`NaN`：**跳过本步参数更新**，并将 `scale` 按退避因子缩小（如乘以 `backoff_factor`），防止脏梯度污染权重。
* 若连续多步无溢出：逐步尝试增大 `scale`（如乘以 `growth_factor`），在安全边界内尽量保留小梯度精度。


3. **更新缩放器状态**：调用 `scaler.update()` 完成当前步的缩放因子调整。

---

### 二、 `FP16` AMP 与 `BF16` AMP 的关键差异

| 对比维度 | `FP16` + AMP（通常需 `GradScaler`） | `BF16` + AMP |
| --- | --- | --- |
| **动态范围** | 较窄（易出现梯度下溢或上溢） | 与 `FP32` 相同（8 位指数，极少下溢/溢出） |
| **尾数精度** | 较高（10 位尾数） | 较低（7 位尾数） |
| **`GradScaler` 需求** | 强烈依赖（否则容易梯度归零或 `NaN`） | 通常不需要（部分特殊场景或极端超参下仍需关注数值稳定） |
| **硬件支持** | 主流 GPU 广泛支持 | 较新架构 GPU/加速器原生支持（如 Ampere 及更新架构） |

### 三、 标准训练循环中的执行顺序

在使用 `FP16` AMP 的典型训练步中，顺序不能乱，尤其涉及梯度裁剪（Gradient Clipping）或梯度累积时：

1. **清零梯度**：`optimizer.zero_grad()`。
2. **开启 `autocast` 前向与算 Loss**：在 `autocast` 上下文中执行前向传播与 Loss 计算（通常建议把 Loss 计算放在 `autocast` 内或紧邻前向输出处，以便 `GradScaler` 正确缩放）。
3. **缩放并反向传播**：调用 `scaler.scale(loss).backward()`。
4. **若需梯度裁剪（如 `clip_grad_norm_`）**：必须先调用 `scaler.unscale_(optimizer)` 将梯度还原到真实尺度，再执行裁剪；否则裁剪阈值会按 `scale` 倍率失真。
5. **执行优化器与更新 Scaler**：调用 `scaler.step(optimizer)` 与 `scaler.update()`。

---

### 四、 常见坑点与工程实践

1. **不要把整个优化器 `step` 或非必要后处理包进 `autocast**`：`autocast` 主要用于前向传播（以及 Loss 计算）；权重更新与优化器状态维护应保持高精度，避免 `FP16` 尾数不足导致小步长更新丢失。
2. **梯度累积时的缩放与更新时机**：若每 $K$ 个 micro-batch 累积一次梯度再更新参数，通常在每个 micro-batch 中对缩放后的 `loss / K` 调用 `.backward()`，累计 $K$ 步后再执行 `scaler.unscale_`、裁剪、`scaler.step(optimizer)` 和 `scaler.update()`。
3. **评估/推理阶段同样可用 `autocast**`：在验证集评估或模型推理时，配合 `torch.no_grad()` / `torch.inference_mode()` 使用 `autocast`（无需 `GradScaler`），同样能降低显存占用并提升前向吞吐；但需抽样对比与 `FP32` 的精度/指标差异。
4. **出现 `NaN` 时的排查思路**：若启用 `FP16` AMP 后频繁跳过更新或出现 `NaN`，先检查学习率是否偏高、Loss 是否本身过大、自定义算子/损失函数是否存在 `log(0)` 或除零；在支持 `BF16` 的硬件上，切换为 `BF16` 往往能显著减少溢出与调参负担。
