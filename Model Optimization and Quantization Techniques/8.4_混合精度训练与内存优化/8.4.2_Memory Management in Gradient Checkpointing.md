### 一、 网络模块与 Checkpoint 调度逻辑

#### 1. `NNBlock` 模块

```python
class NNBlock(nn.Module):
    def __init__(self, dim):
        super(NNBlock, self).__init__()
        self.fc = nn.Linear(dim, dim)
        self.act = nn.ReLU()

    def forward(self, x):
        return self.act(self.fc(x))

```

* 每个 `NNBlock` 包含一个 `512 -> 512` 的全连接层和一个 `ReLU` 激活层。
* 在常规反向传播中，为了计算 `fc` 权重与输入的梯度，框架通常需要缓存前向过程中产生的中间激活张量；当网络层数增多或 Batch Size 增大时，这部分中间激活会占用大量显存。

#### 2. `DeepNN` 与 `_run_block`

```python
def _run_block(self, block, x):
    if self.use_checkpointing and self.training:
        return checkpoint.checkpoint(block, x, use_reentrant=False)
    return block(x)

```

* **只在训练且开启时启用 Checkpoint**：`self.use_checkpointing and self.training` 确保只有在训练阶段才做激活重计算；推理/评估阶段（`model.eval()`）无需保留反向传播激活，直接走普通前向即可。
* **`use_reentrant=False`**：这是现代 PyTorch 推荐的非重入式实现方式。相比早期的重入式（`use_reentrant=True`），它与 PyTorch 自动求导（Autograd）引擎契合更好，对复杂控制流、部分张量不需要梯度或结合 `torch.amp` / 分布式包装时的兼容性与稳定性更高。
* **时间换显存机制**：前向经过 `block` 时不常驻保存块内全部中间激活，仅保留块输入等必要边界信息；到了反向传播需要求该块梯度时，再重新执行一遍 `block` 的前向计算来恢复激活。

### 二、 训练循环与显存峰值测量

#### 1. `train_model` 标准训练循环

```python
def train_model(model, optimizer, num_epochs=3):
    model.train()
    for epoch in range(num_epochs):
        optimizer.zero_grad()
        output = model(input_data)
        loss = criterion(output, labels)
        loss.backward()
        optimizer.step()
        print(f"Epoch [{epoch+1}/{num_epochs}], Loss: {loss.item():.4f}")

```

* 每次迭代依次完成：**梯度清零 $\rightarrow$ 前向计算 $\rightarrow$ 计算 Loss $\rightarrow$ 反向传播 $\rightarrow$ 优化器更新参数**。
* 这里使用的是 `batch_size = 256`、`dim = 512` 的随机张量，目的是让中间激活占一定比例，便于在 GPU 上观察显存变化。

#### 2. `measure_peak_memory` 峰值统计逻辑

```python
def measure_peak_memory(use_ckpt):
    model = DeepNN(use_checkpointing=use_ckpt).to(device)
    optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)
    model.train()

    if device == "cuda":
        torch.cuda.empty_cache()
        torch.cuda.reset_peak_memory_stats()

    optimizer.zero_grad()
    output = model(input_data)
    loss = criterion(output, labels)
    loss.backward()

    if device == "cuda":
        mem_mb = torch.cuda.max_memory_allocated() / (1024**2)
        return mem_mb
    return 0.0

```

* **`torch.cuda.reset_peak_memory_stats()`**：重置历史显存峰值计数器，保证每次测试统计的是当前测量区间的峰值。
* **`torch.cuda.empty_cache()`**：释放 PyTorch 缓存分配器中当前未被活跃张量占用的空闲缓存块，减少前一次测试残留对统计的干扰（注意它不会释放仍被引用张量占用的显存）。
* **测量点放在 `loss.backward()` 之后**：反向传播阶段往往是激活与梯度张量同时存在的峰值时刻；此时读取 `torch.cuda.max_memory_allocated()`（已分配张量字节数）并换算为 MB，能直观反映 Checkpoint 对显存峰值的压缩效果。

### 三、 主程序执行与工程细节提示

在主程序第 5 部分中，代码先跑了一轮带 Checkpoint 的 3 个 epoch 训练，随后分别调用 `measure_peak_memory(use_ckpt=False)` 与 `measure_peak_memory(use_ckpt=True)` 对比峰值显存并计算节省比例。

实际工程使用中有几个值得注意的细节：

1. **显存节省幅度依赖网络深度与结构**：当前 `DeepNN` 只有 5 个 `512` 维的 `Linear + ReLU` 块，模型参数与 Adam 优化器状态在总显存中也占一定比重；在**层数更深、隐藏维度更大或序列/特征图更长**的模型（如 Transformer 或深层 CNN/视觉主干）中，激活值占比更高，Checkpointing 的显存节省比例通常会更明显。
2. **重计算带来的额外计算时间**：开启 Checkpoint 后，每个被 Checkpoint 的块在反向阶段都会多算一次前向，因此单步训练耗时通常会略高于未开启时（常见额外开销约在 10%～30% 量级，视重计算粒度与算子占比而定）。工程上常把 Checkpoint 放在**计算相对便宜但激活体积很大**的层或块边界上，以控制时间代价。
3. **测试变量清理与 `optimizer.step()**`：在 `measure_peak_memory` 中测完 `loss.backward()` 后就读取峰值是合理的；若后续还要继续循环训练，别忘了执行 `optimizer.step()`，且在对比两次测试时注意清理不再需要的旧模型引用以防显存占用叠加。
