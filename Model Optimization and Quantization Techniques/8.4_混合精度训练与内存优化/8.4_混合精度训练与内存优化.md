**混合精度训练（Mixed Precision Training）**是指在训练过程中**同时使用多种浮点数精度**（常见如 `FP16` / `BF16` 与 `FP32`）：将大量矩阵乘法、卷积等计算与前向激活/权重存储放在低精度（16-bit）上执行以提升算力吞吐并降低显存占用，同时在关键环节（如 Master Weights 维护、Loss 累加、Softmax / LayerNorm / AdamW 矩估计更新等数值敏感操作）保留高精度（`FP32`），以保障训练稳定性与收敛精度。

在此基础上，围绕训练显存瓶颈展开的**内存/显存优化（Memory Optimization）**，核心目标是压缩**模型状态（权重、梯度、优化器状态）**、**中间激活值（Activations）**以及**显存碎片与通信冗余**，从而在有限显存下支持更大的 Batch Size、更长的上下文序列或更大的模型规模。

### 一、 混合精度训练的核心机制

#### 1. `FP16` 与 `BF16` 的格式差异

* **`FP16`（IEEE 半精度，16-bit）**：1 位符号位 + 5 位指数位 + 10 位尾数位。动态范围较窄（约 $6 \times 10^{-5}$ 到 $65504$），小梯度容易发生**下溢（Underflow，变为 0）**，大数值容易发生**溢出（Overflow，变为 `NaN`/`Inf`）**。
* **`BF16`（Brain Floating Point，16-bit）**：1 位符号位 + 8 位指数位 + 7 位尾数位。指数位与 `FP32` 相同，**动态范围极大、不易溢出/下溢**，通常无需 Loss Scaling 即可稳定训练；但尾数精度较低（7 位 vs. 10 位），数值精细度略逊于 `FP16`。

#### 2. 为什么需要 `FP32` Master Weights 与 Loss Scaling？

* **权重更新精度丢失**：当学习率较小时，微小的梯度更新量 $\Delta w$ 加到低精度权重上时，可能因尾数位不足被直接舍入掉（权重停滞不更新）。因此通常在显存中维护一份 `FP32` 的主权重（Master Weights），用高精度梯度更新后再拷贝一份低精度副本参与前向计算。
* **Loss Scaling（损失缩放，主要用于 `FP16`）**：
1. 在反向传播前将标量 Loss 乘以一个放大因子 $S$（如动态调整的 `GradScaler`），使微小梯度整体上移，避免在 `FP16` 下溢为零。
2. 反向传播得到缩放后的梯度后，先除以 $S$ 还原到正常量级（同时检查是否存在 `Inf`/`NaN`；若出现则跳过本步更新并缩小 $S$，连续稳定则逐步尝试增大 $S$）。



#### 3. 算子精度策略（AMP / Autocast）

现代自动混合精度（AMP）不会把所有算子无脑转成 16-bit：

* **倾向低精度（16-bit）**：`Linear` / `MatMul`、`Conv` 等高计算密度算子，可充分利用硬件 Tensor Core 吞吐。
* **倾向高精度（32-bit）**：归约、指数/对数、归一化与损失计算等对数值范围或累加精度敏感的算子（如 `Softmax`、`LayerNorm` / `RMSNorm`、Cross-Entropy、梯度累加与优化器状态更新）。

### 二、 训练显存构成与常见瓶颈

在标准训练中，显存主要由两部分组成：

1. **模型状态（Model States，与参数量 $N$ 成正比，与 Batch Size 无关）**：
* 若维护 `FP32` 参数（4B）+ `FP32` 梯度（4B）+ `AdamW` 一阶/二阶动量（通常各 4B，共 8B），单参数对应固定状态开销可达约 **16 Bytes**（若再叠加 `FP16`/`BF16` 权重/梯度副本，开销会更高）。


2. **激活值（Activations，与 Batch Size、序列长度、隐藏维度及层数密切相关）**：
* 前向传播中为计算反向梯度而缓存的中间张量。在**长上下文**或**大 Batch**场景下，激活值往往会超过模型状态，成为最先触发 OOM（Out Of Memory）的元凶。

### 三、 关键内存与显存优化技术

#### 1. 激活重计算 / 梯度检查点（Activation Checkpointing / Gradient Checkpointing）

* **做法**：前向传播时不保存所有层的中间激活，只保留少数检查点（Checkpoint）层的输出；反向传播到达某段时，**重新执行该段的前向计算**来恢复所需激活。
* **权衡**：**用额外的计算时间换取显著的激活显存下降**（尤其适合深层网络或长序列训练）。

#### 2. 梯度累积（Gradient Accumulation）

* **做法**：将一个较大的逻辑 Batch 拆分为多个较小的 Micro-Batch，连续跑 $K$ 个前向与反向步并将梯度累加（通常按 $K$ 取均值），每累积 $K$ 步才执行一次优化器参数更新（`optimizer.step()`）。
* **权衡**：在不增大单步激活显存的前提下模拟更大 Batch 的梯度统计效果，但总训练步数对应的前向/反向计算次数不变，且小 Micro-Batch 会影响 BatchNorm 等批统计行为。

#### 3. 显存卸载与分片（Offloading & ZeRO / 分片状态）

* **CPU / NVMe Offload**：将暂时不参与当前计算的优化器状态、权重或部分激活卸载到主机内存（RAM）或磁盘，降低 GPU 显存峰值，但会引入 PCIe/主机内存传输带宽与延迟开销。
* **优化器状态 / 梯度 / 参数分片（如 ZeRO 思想）**：在多卡分布式训练中，避免每张卡都完整复制一份相同的优化器状态、梯度和参数，而是按分片拆分存储，按需通信聚合，大幅摊薄单卡显存占用。

#### 4. 注意力与算子级显存优化

* **融合注意力内核（如 FlashAttention 类思想）**：避免在显存中物化完整的 $O(L^2)$ 注意力分数矩阵，通过分块计算（Tiling）与在线 Softmax 统计，显著降低长序列下的激活显存占用并提升吞吐。
* **减少临时张量与显存碎片**：避免在循环中保留计算图引用（如未 `.detach()` 或 `.item()` 累积 Loss 张量）、合理设置 Batch/Padding 长度、复用缓冲区，减少显存分配器碎片。

### 四、 工程选型与排查建议

| 遇到的问题 | 优先排查与优化方向 |
| --- | --- |
| **算力利用率低、单步耗时高** | 确认是否启用 `BF16`/`FP16` 混合精度与低精度矩阵乘路径，检查是否存在频繁 Host-Device 同步或小算子碎片 |
| **`FP16` 训练出现 `NaN` / `Inf` 或梯度消失** | 优先评估 `BF16`（硬件支持时），或在 `FP16` 下检查 `GradScaler` 动态缩放与敏感算子的 `FP32` 保护 |
| **长序列 / 大 Batch 下 OOM** | 优先结合 **激活重计算（Checkpointing）**、**梯度累积** 与 **Attention 显存优化**，再评估状态分片或 Offload |
| **显存随迭代步数缓慢上涨直至 OOM** | 检查训练循环中是否有张量历史计算图被意外保留（如列表追加未 `detach()` 的 Tensor）或缓存未释放 |
