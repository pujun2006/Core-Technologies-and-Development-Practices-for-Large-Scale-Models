A BERT-Based Multi-Turn Dialogue System with Named Entity Recognition and Context Tracking.py代码在上一版 CoNLL-2003 NER 训练脚本的基础上，加入了**类别加权交叉熵损失（Weighted CrossEntropyLoss）**、**上下文追踪器（`MultiTurnContextTracker`）**以及**基于 Wikipedia REST API 的实体摘要查询（`KnowledgeGraph`）**，最终组成一个支持命令行交互的实体识别与知识查询原型。

---

## 一、 核心模块逐段解析

### 1. 模型初始化与本地 CoNLL 数据加载（第 1 节）

* **标签映射与模型初始化**：定义了 CoNLL-2003 的 9 类标签（`O` 及 `PER/ORG/LOC/MISC` 的 `B-/I-`），构建 `id2label` 和 `label2id`，并在调用 `BertForTokenClassification.from_pretrained` 时显式传入它们，使模型配置自带可读标签名。
* **`read_conll_file` 与 `DatasetDict**`：按空行或 `-DOCSTART-` 分句，读取 `conll2003_data/` 下的 `train.txt`、`validation.txt`、`test.txt`，声明 `Sequence(ClassLabel(...))` 特征后组装为 `DatasetDict`。

### 2. 子词标签对齐（第 2 节）

* **`tokenize_and_align_labels`**：对已切词样本设置 `is_split_into_words=True` 与 `truncation=True`，利用 `word_ids()` 将每个词的原标签赋给其**首个子词**，特殊 Token（`None`）与后续子词均设为 `-100`，使交叉熵损失自动跳过非首子词与特殊符号。

### 3. 稳健类别权重计算与自定义 `WeightedLossTrainer`（第 3 节）

针对 NER 中大量位置为 `O`、少数实体类样本偏少的类别不平衡问题，代码用 `sklearn.utils.class_weight.compute_class_weight("balanced", ...)` 动态计算权重：

1. 从训练集 `labels` 中收集所有非 `-100` 标签 ID。
2. 仅对实际出现的 `unique_labels` 计算 `"balanced"` 权重（避免某些标签在子集或小样本中缺失导致报错）。
3. 初始化长度为 `len(label_list)`（9）的全 `1.0` 数组 `class_weights_np`，填入计算得到的权重并转为 `torch.Tensor`。

* **`WeightedLossTrainer`**：继承 `Trainer` 并重写 `compute_loss`（兼容 `num_items_in_batch=None` 参数签名），将 `class_weights` 移动到 `logits.device` 后传入 `nn.CrossEntropyLoss(weight=weight, ignore_index=-100)`，计算展平后的交叉熵损失。

### 4. 训练配置、评估与微调（第 4 节）

* **`TrainingArguments`**：设定输出目录 `./results`、按 epoch 评估（`eval_strategy="epoch"`）、训练/验证 batch size 为 `16`、训练 `3` 个 epoch、权重衰减 `0.01`、学习率 `3e-5`。
* **`compute_metrics`**：取 `argmax` 后过滤 `-100` 位置，还原为标签字符串并调用 `seqeval` 计算整体 `precision`、`recall`、`f1` 与 `accuracy`；随后通过 `DataCollatorForTokenClassification` 动态补齐并启动 `trainer.train()`。

### 5. 上下文追踪、Wikipedia 摘要查询与交互循环（第 5–6 节）

* **`MultiTurnContextTracker`**：在内存中维护 `self.context` 列表，每轮追加 `{"text": text, "entities": entities}`（当前主要用于记录轨迹，尚未在 `interactive_test()` 中读取拼接）。
* **`KnowledgeGraph`**：将实体名中的空格替换为 `_`，请求 `[https://en.wikipedia.org/api/rest_v1/page/summary/](https://en.wikipedia.org/api/rest_v1/page/summary/){formatted_entity}`（附带自定义 `User-Agent` 和 `timeout=5`），若 HTTP 状态码为 `200` 则提取 `extract` 摘要文本，否则返回提示或异常信息。
* **ner_pipeline 与 interactive_test()**：使用 `aggregation_strategy="simple"` 将子词聚合成完整实体，并自动选择 GPU（`device=0`）或 CPU（`device=-1`）；在 `while True` 命令行循环中接收输入（输入 `退出` 或 `exit` 结束），抽取实体后逐个查询 Wikipedia 摘要并打印。

### 三、 关键细节与潜在改进点

1. **类别权重对 Precision / Recall 的影响**：使用 `"balanced"` 权重会放大稀有实体标签（如 `B-MISC`、`I-MISC`）的错分惩罚，通常有助于提升**召回率（Recall）**，但也可能增加误报导致精确率（Precision）下降、训练早期损失波动变大；实际调优时常会做平滑处理（如对权重取幂 `weight ** alpha`，`0 < alpha < 1`）或与默认均匀权重对比验证集实体级 F1。
2. **`context_tracker` 尚未参与多轮消解**：当前 `context_tracker.update_context(...)` 存入了历史文本与实体，但后续查询并未利用历史实体补全指代（例如第二轮问 `"Where is its headquarters?"` 时，`its` 不会被识别为实体，也未自动回填上一轮的 `ORG` 实体）。
3. **实体名清洗与查询鲁棒性**：`ner_pipeline(..., aggregation_strategy="simple")` 在遇到带标点或特殊符号的词时，`item["word"]` 偶尔可能包含多余空格或标点（如 `"Apple 's"`），直接 `.replace(" ", "_")` 请求 Wikipedia API 时偶尔会命中重定向或 404；更稳健的做法是先清理首尾标点，必要时结合 Wikipedia 搜索接口做候选消歧。
