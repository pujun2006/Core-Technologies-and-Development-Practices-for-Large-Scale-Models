在问答系统中，“答案抽取（Answer Extraction）”与“评分机制（Scoring Mechanism）”并非只有单一做法，而是随着模型形态演进形成了两条清晰路线：**编码器抽取式 QA 的 Span 定位与打分**，以及**生成式大模型 / RAG 场景下的证据召回打分、输出概率/自洽性评分与答案质量评估**。

下面把这两套机制分开讲透，方便你把上一轮的代码原理与实际大模型系统联系起来。

---

### 一、 编码器抽取式 QA：Span 抽取与打分机制

在 `RoBERTa / BERT` 等抽取式问答模型中，模型不会凭空生成新词，而是从输入文本里截取一段连续 Token 作为答案。
<img width="720" height="300" alt="57602d40-a7ac-4dbe-bf1e-655a38fcf014" src="https://github.com/user-attachments/assets/08f8cffc-7278-41b7-bb62-1ba7cedbbe48" />


#### 1. 候选区间（Span）生成与合法性约束

模型对序列中每个 Token 分别输出起始得分 `start_logits` 和结束得分 `end_logits`。组合 `(s, e)` 成为合法候选答案通常需要满足：

* **顺序约束**：结束位置不早于起始位置（$e \ge s$）。
* **跨度长度约束**：答案长度不超过设定的最大跨度（如 $e - s + 1 \le L_{\max}$），防止截出整段无关长句。
* **区域合法性约束**：起止位置应落在上下文区间内（避免把问题本身的词当成答案）。

#### 2. 常见评分公式与归一化

* **联合 Logit 求和（最经典）**：在假设起止位置独立的情况下，跨度 `[s, e]` 的联合对数得分常写为：

$$\text{Score}(s, e) = \text{start\_logit}_s + \text{end\_logit}_e$$



相比直接对两个 logit 取均值，求和更贴合对数空间下的联合打分逻辑；若先做 `Softmax` 得到概率分布 $P_{\text{start}}(s)$ 与 $P_{\text{end}}(e)$，联合概率则为 $P_{\text{start}}(s) \cdot P_{\text{end}}(e)$（对数域即为 $\log P_{\text{start}}(s) + \log P_{\text{end}}(e)$）。
* **“无答案”阈值对比（SQuAD 2.0 风格）**：当允许“文中无答案”时，常以 `[CLS]` 位置的起止得分组合 $\text{Score}_{\text{null}} = \text{start\_logit}_0 + \text{end\_logit}_0$ 作为基准线。只有当最佳非空跨度得分超过 $\text{Score}_{\text{null}} + \delta$（$\delta$ 为可调阈值）时才输出答案，否则判为拒答/无答案。

#### 3. 多滑窗（Stride）聚合与后处理

当长文档被切分为多个重叠滑窗时，不同窗口可能给出同一段答案，或者各自给出最高分片段。通常需要对各窗口得分做**全局排序**，并对重复/重叠的文本片段去重或合并得分，最后再做标点修剪与空白清理。

### 二、 生成式大模型与 RAG：从“抽片段”到“抽证据 + 评答案”

在大语言模型（LLM）与检索增强生成（RAG）中，答案通常由模型自回归生成，此时的“抽取”与“评分”发生在三个关键环节：

#### 1. 证据抽取与相关性评分（Retrieval & Reranking）

大模型生成前，系统需要先从知识库中“抽”出相关段落/结构化条目并打分：

* **召回阶段评分**：向量检索常用余弦相似度或内积（MIPS）计算 Query 与 Chunk 向量的匹配分；关键词检索（如 BM25）按词频、逆文档频与文档长度归一化打分；混合检索常将两类分数做归一化或倒数排序融合（RRF）。
* **重排阶段评分（Cross-Encoder / Reranker）**：将 Query 与候选文档拼接送入交叉编码器或重排模型，直接输出精细相关性得分，用于过滤低分噪声、决定送入 LLM 的上下文排序。

#### 2. 生成过程中的置信度与自洽性评分

LLM 生成答案时，常见两类内部/采样级评分机制：

* **Token 对数概率（Logprobs）聚合**：对生成答案所用 Token 的条件对数概率求均值或几何平均（长度归一化，避免长答案因连乘导致概率过小），用于衡量模型对自身输出的“表面置信度”。
* **自洽性投票（Self-Consistency）**：对同一问题以非零温度采样多条推理路径或候选答案，统计语义等价答案的出现频次或加权得分，选出最一致的答案。

#### 3. 结构化信息抽取与答案质量评估

* **结构化抽取与校验**：当要求模型从长文或表格中抽取槽位/JSON 字段时，除了提示词约束，还会结合 Schema 校验、原文溯源比对（核对抽取内容是否能在原文找到依据）来过滤捏造字段。
* **答案评估评分（离线评测 / LLM-as-a-Judge）**：
* **词面/跨度匹配类**：Exact Match（EM，精确匹配）与 Token 级 F1，常用于事实型或抽取式基准。
* **语义与忠实度类**：评估答案是否**切题（Answer Relevance）**、是否**忠实于给定上下文不编造（Faithfulness / Groundedness）**，以及引用是否准确。

### 三、 抽取与评分机制对比总结

| 场景类型 | “抽取”的对象 | 核心评分依据 | 主要风险与应对 |
| --- | --- | --- | --- |
| **编码器抽取式 QA** | 原文中的连续 Token 区间 `[s, e]` | `start_logits` 与 `end_logits` 组合得分（及 `[CLS]` 无答案阈值） | 无法跨句归纳、长文需滑窗、无答案易硬凑 |
| **RAG 生成式 QA** | 检索段落/证据 + LLM 生成的回答文本 | 检索/重排相关性得分、生成 Logprobs / 自洽性、忠实度评估 | 检索漏召回、上下文冗余、模型产生幻觉 |
