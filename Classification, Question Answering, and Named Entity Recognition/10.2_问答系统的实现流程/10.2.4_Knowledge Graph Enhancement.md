Knowledge Graph Enhancement.py代码将前几轮的**中文抽取式问答（RoBERTa）**、**历史上下文累积**与知识图谱检索（Neo4j / 模拟字典降级）串联起来，实现了一个“先从文本抽基础答案，再用知识图谱补充关联实体，并滚动更新历史上下文”的原型系统。

---

### 一、 整体架构与核心亮点

1. **抽取式 QA + 知识图谱后置补充（Post-Extraction KG Lookup）**
与常见的“先检索图谱拼入 Prompt 再生成”不同，这里采用的是“文本抽答案 → 将抽取结果作为实体查图谱 → 拼接关联节点”的串联方式：先靠 RoBERTa 从当前文本中定位核心答案片段，再拿着抽出来的短语/实体去知识图谱里扩展相关概念。
2. **数据库连接优雅降级（Neo4j Fallback）**
尝试连接本地 Neo4j（`bolt://localhost:7687`），若服务未启动或连接失败，自动切换为内置的 `dummy_kg` 字典，保证代码在无图数据库环境下也能完整演示。
3. **参数化 Cypher 与后处理过滤**
在查询 Neo4j 时使用 `$entity_name` 参数绑定，同时在 `extract_answer` 中加入了长度限制、停用词/前缀过滤与联合得分排序，提升了抽取片段的干净程度。

### 二、 分模块详细说明

#### 1. 镜像源配置与模型加载

```python
os.environ["HF_ENDPOINT"] = "https://hf-mirror.com"
model_name = "uer/roberta-base-chinese-extractive-qa"

```

* 配置国内镜像源 `hf-mirror.com`，加载中文抽取式问答模型 `uer/roberta-base-chinese-extractive-qa` 及其分词器。

#### 2. Neo4j 连接与模拟图谱降级

```python
try:
    graph = Graph("bolt://localhost:7687", auth=("neo4j", "password"))
    graph.run("RETURN 1")
    neo4j_available = True
except Exception as e:
    ...
    neo4j_available = False

```

* 通过 `py2neo.Graph` 连接 Neo4j 并执行 `RETURN 1` 验证连通性，用布尔标记 `neo4j_available` 记录状态。
* `dummy_kg` 提供了 `"Transformer"`、`"自然语言处理"`、`"情感分析"` 到各自关联概念的映射，用于离线演示。

#### 3. 知识图谱查询函数 `query_knowledge_graph(entity)`

```python
def query_knowledge_graph(entity):
    if not entity or len(entity) > 15:
        return []
    entity = entity.strip()

```

* **长句过滤**：`len(entity) > 15` 用于筛掉明显是句子或长短语的抽取结果，减少把整句话当成实体名去查图的噪音。
* **Neo4j 查询**：匹配出边 `(e)-[r]->(related)` 且起点名称等于 `$entity_name` 的邻居节点，最多返回 `5` 条（`LIMIT 5`），并使用参数化查询避免 Cypher 注入。
* **降级查询**：未连上 Neo4j 时直接查 `dummy_kg.get(entity, [])`。

#### 4. 抽取式问答核心函数 `extract_answer(...)`

* **编码与前向传播**：将 `question` 与 `context` 编码为最长 `512` Token 的张量（超出截断），在 `torch.no_grad()` 下获取 `start_logits` 和 `end_logits`。
* **Top-K 组合与合法性筛选**：
* 分别取起止得分前 `top_k=5` 的位置，两两组合。
* 检查 `e_i >= s_i` 且跨度长度在 `1` 到 `25` 个 Token 之间。


* **分词还原与停用词清洗**：
* 先将 Token ID 转为 Token 字符串并合并，去掉多余空格与子词前缀 `##`。
* 过滤掉 `stop_words`（如 `"和"`、`"等"`、`"的"`、`"包括"` 等）以及以 `"和"`、`"等"`、`"的"` 开头的碎片。


* **得分与排序**：
* 使用 `score = s_score.item() + e_score.item()`（起止 logit 之和）作为候选得分，降序排列后返回得分最高的文本（若无有效候选则返回空字符串 `""`）。



#### 5. 多轮图谱增强问答流程 `knowledge_enhanced_qa(...)`

* **初始化**：`history` 从 `base_context` 开始。
* **逐轮执行**：
1. 调用 `extract_answer` 在当前 `history` 中抽取 `raw_answer`（若为空则设为 `"未在上下文中找到明确答案"`）。
2. 将 `raw_answer` 传入 `query_knowledge_graph` 检索关联节点 `kg_info`。
3. 若 `kg_info` 非空，则在 `raw_answer` 后追加 `（[知识图谱补充] 相关实体节点：...）` 形成 `final_answer`。
4. 将本轮的 `问：{question} 答：{raw_answer}` 追加到 `history` 中，供下一轮使用。

### 四、 实际运行行为与可改进之处

1. **抽取结果能否命中图谱实体高度依赖粒度**：
例如上下文里写的是 `"通过注意力机制来识别句子中的重要信息"`，如果模型抽出的词是 `"注意力机制"`，恰好能匹配图谱；但如果抽成 `"通过注意力机制"` 或 `"注意力机制来识别"`，精确匹配（`e.name = $entity_name` 或 `dummy_kg.get`）就可能查不到。实际中常配合实体识别/实体链接（NER & Entity Linking）或模糊/别名匹配来提升命中率。
2. **`history` 持续拼接带来的干扰与截断**：
将每轮问答拼接到 `history` 末尾，虽然保留了历史信息，但随着轮次增加，旧问答可能分散注意力，且超过 `512` Token 时会触发截断。更稳妥的做法是结合问题改写或控制历史长度。
3. **增强方式从“简单拼接”到“融合推理”**：
当前代码是把图谱节点直接附在抽取答案后面；在更复杂的系统中，也可以将图谱三元组转化为自然语言背景描述，或结合大模型做归纳整合，使补充信息与原答案衔接更自然。
